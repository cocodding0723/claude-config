Slack 봇 최적화안

쉬운 말 3줄 요약
① 지금 문제 — 30초마다 Slack에 새 답을 묻다가 호출 과다로 거절당한다.
② 그래서 — Slack이 답을 직접 알려주는 방식으로 바꾼다.
③ 그러면 — 버튼으로 답하고, 사용자는 앱 토큰 발급과 결정 3개 답만 한다.

🛠️ 내가 할 일 · 쉬운 풀이

  • 내가 할 일 1: 결정 3개에 답한다
  • 내가 할 일 2: 승인 뒤, Slack 앱 설정 화면에서 Socket Mode와 버튼 사용을 켠다
  • 내가 할 일 3: 같은 화면에서 앱 토큰을 1개 발급해 slack-bot.env 에 직접 넣는다
  • 앱 토큰 값은 이 문서와 대화에 옮기지 않는다

결정1. 답을 받는 방식을 Socket Mode로 바꿀까?

지금 문제: 30초 폴링이 약 240회를 호출해 429가 난다. 그래서 실패한 회차는 즉답도 멈춘다.

안 정하면 멈추는 것: 버튼 누름을 받을 곳이 없으므로 결정2·3이 시작되지 못한다.

선택지고르면비용위험되돌리기
A. Socket Mode ✅ 추천
Slack이 열린 연결로 답을 밀어줌		평소 조회 호출이 0회다.새 파일 2개, 수정 파일 1개. 파일명은 아래 표.연결이 끊기면 답이 빠진다. 하루 1회 미답만 다시 확인한다.쉬움
B. Events API
공개 주소로 받음		답이 즉시 온다.파일 3개 이상.이 Mac은 공개 주소가 없다.보통
C. 5분 폴링
횟수만 줄임		429가 줄고 답이 5분 늦다.수정 파일 1개.버튼이 불가하다.쉬움

추천 이유: 메시지가 늘수록 호출도 늘어 한도를 더 넘는다. A는 평소 조회를 없애 그 증가를 멈춘다. 감수하는 단점: 상시 프로세스 1개를 관리한다.

결정2. 결정 메시지에 버튼을 달까?

지금 문제: 같은 A 답이 이모지 이름 두 가지로 갈려 있다. 반응 43건 중 a 19건, 비서-a 12건이고 해석표에 없는 이모지 1건이 있다.

안 정하면 멈추는 것: 새 이모지가 등장할 때마다 해석표를 손으로 고쳐야 답으로 읽힌다.

선택지고르면비용위험되돌리기
A. 버튼 + 이모지 병행 ✅ 추천
버튼은 메시지 아래 누르는 칸		버튼 값이 고정이므로 해석표를 거치지 않는다. 이모지도 그대로 읽는다.수정 파일 1개: slack_notify.sh. 결정1 A와 합쳐 새 2개·수정 2개.누름을 3초 안에 확인 응답해야 한다.쉬움
B. 이모지만 유지지금과 같아 변화가 없다.수정 파일 0개.해석표 손질이 계속 필요하다.쉬움

추천 이유: 이모지는 이름이 갈려서 해석표를 계속 맞춰야 한다. 버튼은 값이 하나라 그 표가 필요 없어진다. 오답 빈도는 43건 중 1건으로 낮다. 감수하는 단점: 자유 문장 답은 여전히 답글로 한다.

결정3. 답한 결정 메시지를 결과 한 줄로 고칠까?

지금 문제: 답해도 메시지는 그대로다. 그래서 2시간마다 대기 목록이 새 메시지로 올라와 DM이 길어진다.

안 정하면 멈추는 것: 답한 결정과 안 한 결정이 화면에서 구분되지 않는다.

선택지고르면비용위험되돌리기
A. 메시지를 고친다 ✅ 추천
답하면 버튼이 사라지고 선택 결과가 보임		안 한 결정만 버튼이 남는다. 대기 목록은 고정 메시지 1개를 고쳐 쓴다.수정 파일 1개: slack_pending.sh. 세 결정 합계 새 2개·수정 3개.메시지 고치기 호출이 답마다 1회 늘어난다.쉬움
B. 답글로만 확인원문이 그대로라 이력이 온전하다.수정 파일 0개.버튼이 남아 같은 결정에 또 누를 수 있다.쉬움

추천 이유: 버튼이 남으면 이미 답한 결정에 또 눌러 기록이 두 번 쌓인다. 고치면 누른 즉시 버튼이 사라져 그 중복이 막힌다. 감수하는 단점: 원문 질문 위에 결과가 덮여 보인다.
