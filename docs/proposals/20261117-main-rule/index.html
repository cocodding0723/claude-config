결정1. 메인의 직접 작업을 어떻게 막나

배경: 메인은 요청을 카드로 적고 코디네이터를 띄우는 창구인데, 점검에서 메인이 직접 작업한 사례가 나왔다.

안 정하면 멈추는 것: 직접 작업이 계속된다.

선택지결과되돌리기
A. 스킬 문구만 강화문구만 늘므로 같은 문구가 이미 있는 지금과 같다. 막는 힘은 없다.쉬움
B. 훅으로 거부 + 안내 ✅ 추천메인의 Agent·게임 저장소 쓰기·워커 직접 기동은 거부되고 feature_open.sh 안내가 뜬다. 읽기와 카드 조작은 된다.쉬움
C. B + 위반 시도 자동 기록거부마다 기록과 작업판 알림이 남아 시도 횟수가 보인다. 기록 파일이 하나 더 생긴다.보통

추천 이유: 문구는 이미 있었는데 메인이 어겼기 때문에 한 번 더 적어도 같은 일이 생긴다. 그래서 B 는 어기는 호출 자체를 도구 단계에서 거부해 구조로 막는다. 감수하는 단점: 급히 직접 고칠 때 막히므로 임시 허용 파일로 푼다. C 의 기록은 우회가 보이면 그때 더한다.

답하는 법: 결정1 B

용어: 메인 — 사용자와 대화하며 계획 카드를 쓰는 세션. 기능 코디네이터 — 기능 하나를 맡아 워커에게 일을 나누는 세션. 훅 — 도구 실행 직전에 규칙을 검사하는 스크립트.

⚠️ 지금: 빨간 점선 안의 직접 길(하위 에이전트·파일 수정·워커 기동)이 열려 있다. 의도한 길은 코디네이터 하나뿐인데 막는 곳이 없다.

🔄 이후: 모든 도구 호출이 훅을 지나고 코디네이터 길만 통과한다. 나머지는 거부와 안내 문구로 끝난다.

🔄 지금 문제와 근거

  • 점검 보고서 12번은 상태가 부분이다. 안내 문서만 바뀌었고 막는 장치가 없으며 오늘 오전 메인이 직접 작업했다.
  • skills/orca-main/SKILL.md 의 「직접 하지 않는 것」에 조사·구현·워커 배정 금지가 이미 적혀 있다. 문구는 있는데 어겨졌다.
  • 메인 판별은 이미 있다. claude/hooks/lib/main_role.py 의 is_main 이 ORCA_ROLE=main 이거나 세션 기록 폴더가 메인 체크아웃과 같으면 메인으로 본다. 계획 승인 기록 쓰기 제한이 같은 방식으로 이미 동작한다.
  • Orca 의 agent launch 는 환경변수를 넘기지 못한다. 그래서 실제 판별은 두 번째 방법, 곧 세션을 시작한 폴더로 한다.
  • 메인이 직접 일하는 길은 네 가지다. Agent 도구, Write·Edit 로 게임 저장소 파일 수정, Bash 로 수정·빌드, orca worker-start 직접 기동.
  • 의도한 길은 hubs/scripts/feature_open.sh 다. 티켓·이름·기준 브랜치를 받아 통합 브랜치, 허브 작업 공간, 작업판 epic 카드, 코디네이터 세션을 만든다. 다시 실행해도 있는 것은 재사용하고 --dry-run 이 있다.
