📖 용어 풀이

  • 스킬 = Claude 에게 작업 방법을 알려 주는 지침 파일. 폴더 하나가 스킬 하나다.
  • 메모리 = Claude 가 프로젝트별로 기억해 두는 규칙 메모. 프로젝트 폴더마다 따로 있다.
  • 허브(문서 코디네이터) = 문서 작업을 받아 워커에게 나눠 주는 담당 창구. 터미널 세션 하나다.
  • 옛 허브 = 연애혁명 저장소 안에 있는 기존 문서 허브. 새 허브 = claude-config 에 만들 허브.
  • 워크스페이스 = 저장소를 복사해 작업하는 별도 폴더(git 워크트리).
  • sparse 워크트리 = 저장소 일부 폴더만 꺼내 둔 워크스페이스.
  • HANDOFF.md = 허브가 다음 세션에 일을 넘기는 인계 문서.
  • decisions.tsv = 허브가 스스로 내린 판단을 한 줄씩 남기는 기록 파일.
  • 개인-* = 옛 허브 밑에 만든 개인 업무용 하위 워크스페이스.
  • 3차 검수 = 1차 다른 Claude, 2차 교차 모델, 3차 사용자가 보는 마지막 확인.
  • 구조안 = 구조 변경 제안 문서 유형. 해설·기록·보고서도 문서 유형 이름이다.
  • detached HEAD = 브랜치 없이 특정 커밋에 붙은 상태. 여기서 만든 커밋은 이력에 안 남는다.
  • 양식 외 규칙 = 문서 양식이 아닌 규칙. 전달(누구에게 어떻게 보냄)·책임(누가 만들고 올림)·문체(쉬운 말·압축)가 있다.
  • 정리안 결정 = 이 문서의 결정. 저장소 구조안(다른 문서)의 결정과 구분하려고 붙인 이름이다.
  • TOML = 설정을 [섹션]과 키 = 값으로 적는 텍스트 형식.
  • [default] = 설정 파일 맨 위의 기본값 섹션. 프로젝트 섹션이 없는 값을 채운다.
  • 정규식 = 글자 패턴을 적는 규칙. 예: ABC-\d+ 는 ABC- 뒤에 숫자가 붙은 티켓 키를 뜻한다.
  • a|b|c = 검색 패턴에서 a 또는 b 또는 c 라는 뜻이다.
  • origin = git 이 저장소의 기본 원격 주소에 붙이는 이름이다.
  • 파이썬 TOML 모듈 = 파이썬 3.11 부터 들어 있는 TOML 읽기 기능(tomllib)이다.
  • 전역 CLAUDE.md = 모든 프로젝트 세션이 매번 읽는 개인 규칙 파일(~/.claude/CLAUDE.md).
  • 프로젝트별 설정 = 받는 사람·채널·이름 규칙처럼 프로젝트마다 다른 값을 적는 파일 한 개.
  • doc-kit = 이 안에서 새로 만들자는 통합 문서 스킬의 임시 이름.
  • 🟢 추가·유지 · 🟡 변경 · 🔴 삭제 · 🔵 테스트 · ⚠️ 위험 · ⚪ 해당 없음 · 파랑 도식 칸 = 그대로.

정리안 결정1. 문서 스킬 5개를 doc-kit 하나로 합칠까?

지금 문제: 문서 규칙을 담은 지침 파일(스킬) 5개에 같은 문장이 3~4곳씩 복사돼 있다. 그래서 하나를 고치면 나머지가 낡는다.

안 정하면 멈추는 것: 통합 스킬을 쓰지 못한다.

🔁 바뀐 결정 정리안 결정2. 양식 외 규칙 7개를 규칙별로 나눠 둘까, 전부 전역 CLAUDE.md 에 둘까?

doc-kit 이 읽는 방법

  • 1. 설정 파일을 찾는다. 환경 변수 DOC_KIT_CONFIG, 없으면 ~/.config/doc-kit/projects.toml.
  • 2. 파일이 없으면 기본값표 그대로 진행하고 "설정 없음 — 기본값" 한 줄을 보고에 적는다.
  • 3. 프로젝트를 고른다. 아래 순서에서 먼저 되는 것을 쓴다.
순서방법쓰는 때
1허브 프롬프트·역할 파일·작업 지시에 프로젝트명을 적는다(기본 방법)새 허브가 다른 프로젝트 문서를 맡을 때. 시작 스크립트가 프롬프트로만 값을 넘기므로 이 경로가 확실하다
2환경 변수 DOC_KIT_PROJECT(보조)허브 Bash 까지 환경 변수가 전달되는지는 검증하지 않았다. 확인된 뒤에만 쓴다
3git 원격 주소(origin)를 각 섹션 match 와 대조대상 프로젝트 저장소 안에서 만들 때. 허브·하위 워크트리는 폴더 이름이 달라도 원격이 같아 잡힌다
4저장소 폴더 이름을 match 와 대조원격이 없을 때
5[default] 만 사용위가 모두 안 맞을 때. 채널·받는 사람이 없어 파일 경로만 보고한다
  • 4. 일치한 섹션 값을 [default] 위에 덮어쓴다. 본문 규칙은 값 대신 항목 이름만 부른다.
  • 5. check.py 는 같은 파일에서 ticket_pattern 한 값만 읽는다. 없으면 티켓 검사를 건너뛴다.
  • 🟡 새 허브는 claude-config 안이라 origin 이 어느 match 에도 안 맞는다. 그래서 순서 1 로 프로젝트를 지정해야 채널이 읽힌다.
