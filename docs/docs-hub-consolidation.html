📖 용어 풀이

  • 스킬 = Claude 에게 작업 방법을 알려 주는 지침 파일. 폴더 하나가 스킬 하나다.
  • 메모리 = Claude 가 프로젝트별로 기억해 두는 규칙 메모. 프로젝트 폴더마다 따로 있다.
  • 허브(문서 코디네이터) = 문서 작업을 받아 워커에게 나눠 주는 담당 창구. 터미널 세션 하나다.
  • 워크스페이스 = 저장소를 복사해 작업하는 별도 폴더(git 워크트리).
  • sparse 워크트리 = 저장소 일부 폴더만 꺼내 둔 워크스페이스.
  • HANDOFF.md = 허브가 다음 세션에 일을 넘기는 인계 문서.
  • decisions.tsv = 허브가 스스로 내린 판단을 한 줄씩 남기는 기록 파일.
  • 개인-* = 허브 밑에 만든 개인 업무용 하위 워크스페이스.
  • 3차 검수 = 1차 다른 Claude, 2차 교차 모델, 3차 사용자가 보는 마지막 확인.
  • 구조안 = 구조 변경 제안 문서 유형. 해설·기록·보고서도 문서 유형 이름이다.
  • detached HEAD = 브랜치 없이 특정 커밋에 붙은 상태. 여기서 만든 커밋은 이력에 안 남는다.
  • 전달 규칙 = 문서 양식이 아니라 누구에게 어떻게 보내는지 정한 규칙.
  • 전역 CLAUDE.md = 모든 프로젝트 세션이 매번 읽는 개인 규칙 파일(~/.claude/CLAUDE.md).
  • 프로젝트별 설정 = 받는 사람·채널·이름 규칙처럼 프로젝트마다 다른 값을 적는 파일 한 개.
  • doc-kit = 이 안에서 새로 만들자는 통합 문서 스킬의 임시 이름.
  • 🟢 추가·유지 · 🟡 변경 · 🔴 삭제 · 🔵 테스트 · ⚠️ 위험 · 파랑 도식 칸 = 그대로.

결정1. 문서 스킬 5개를 doc-kit 하나로 합칠까?

지금 문제: 문서 작성 규칙을 담은 지침 파일(스킬) 5개에 같은 문장이 3~4곳씩 복사돼 있다. 그래서 하나를 고치면 나머지가 낡는다.

안 정하면 멈추는 것: 통합 스킬을 쓰지 못하고, 메모리 정리도 시작하지 못한다.

🔁 바뀐 결정 결정2. 전달·책임 규칙 7개를 전역 CLAUDE.md 에 둘까, doc-kit 에 둘까?

안 정하면 멈추는 것: 프로젝트 메모리를 비우지 못하고 doc-kit 범위도 확정하지 못한다.

범위: 받는 사람·채널 값은 전역 절에 쓰지 않고 프로젝트별 설정에서 읽는다. 이 문서는 안만 쓴다.

  • 🟡 역할 파일은 ~/.config 아래라 저장소 밖이고 버전 관리가 없다.

  • 🟢 이름: projects.toml 하나. 프로젝트마다 섹션을 나눈다.
  • 🟢 실제 값 위치: ~/.config/doc-kit/projects.toml. git 밖이라 개인 값이 저장소에 안 들어간다.
  • 🟢 자리표시본 위치: claude-config 의 skills/doc-kit/projects.example.toml. 구조안 문서의 skills 폴더와 *.example 방식을 따른다.
  • 🟢 형식: TOML. 파이썬 3.13 에 읽기 모듈이 들어 있다(이 맥의 pyc 파일명으로 확인).

doc-kit 이 읽는 방법

  • 1. 설정 파일을 찾는다. 환경 변수, 없으면 ~/.config/doc-kit/projects.toml.
  • 2. 파일이 없으면 기본값표 그대로 진행하고 "설정 없음 — 기본값" 한 줄을 보고에 적는다.
  • 3. 있으면 현재 저장소 폴더 이름·원격 주소를 각 섹션 match 와 대조한다.
  • 4. 첫 일치 섹션 값을 [default] 위에 덮어쓴다. 일치가 없으면 [default] 만 쓴다.
  • 5. 본문 규칙은 값을 직접 쓰지 않고 항목 이름만 부른다. 예: "받는 사람(recipients)에게는 직접 보내지 않는다".
  • 6. check.py 는 같은 파일에서 ticket_pattern 을 읽어 고유명사 검사에 쓴다. 없으면 티켓 검사를 건너뛴다.
  • 🟡 실제 값 파일을 만드는 일은 승인 뒤 3단계에서 한다. 지금은 설계만 있다.
  • 🟡 구조안 문서의 .gitignore 에 projects.toml 은 이미 저장소 밖이라 따로 추가가 필요 없다.
