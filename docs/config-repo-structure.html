결정1. 설치를 직접 만든 링크 스크립트로 할까?

지금 문제: 스킬 폴더 안에 외부 도구가 관리하는 항목이 섞여 있다. 폴더째 링크하면 그 항목까지 저장소로 들어온다.

안 정하면 멈추는 것: 저장소 폴더 구조와 설치 파일 형식을 못 정해 저장소를 채우지 못한다.

선택지고르면비용되돌리기
A. 링크 스크립트 ✅ 추천
목록에 적은 항목만 링크하는 셸 스크립트		목록 밖 항목은 건드리지 않으므로 외부 도구 폴더가 안전하다.스크립트 1개, 약 100줄(추정)쉬움 — 링크만 지우면 된다
B. chezmoi
파일을 복사해 적용하는 dotfiles 도구		템플릿·암호화가 생기므로 맥마다 다른 값을 쓸 때 편하다.도구 설치와 학습, 저장소 파일 이름 규칙 변경보통 — 복사본이라 원본과 어긋난다

추천 이유: 지금은 맥이 두 대이고 맥마다 다른 값이 거의 없다. 그래서 템플릿이 필요 없고, A 는 외부 폴더를 건드리지 않는 쪽이다. 감수하는 단점: 스크립트를 직접 유지한다.

답: 결정1 A

결정2. 설정 파일은 링크 대신 병합 복사로 설치할까?

지금 문제: Orca 가 설정 파일을 다시 쓴다. 링크로 걸면 Orca 가 실제 파일로 바꿔 저장소와 조용히 끊긴다.

안 정하면 멈추는 것: 설정 파일을 저장소에 어떤 모양으로 넣을지 몰라 첫 커밋을 못 한다.

선택지고르면비용되돌리기
A. 병합 복사 ✅ 추천
저장소 기본값에 Orca 항목을 얹어 새 파일을 만든다		Orca 가 넣은 항목이 보존되므로 덮어써져도 저장소는 영향이 없다.병합 스크립트 약 30줄(추정)쉬움 — 설치 전 백업본으로 복원
B. 링크
설정 파일 자체를 저장소로 링크		수정이 곧바로 저장소에 보이지만 Orca 가 끊으면 알림 없이 갈라진다.스크립트 없음쉬움 — 다만 끊김을 눈치채기 어렵다

추천 이유: 설정 파일에는 Orca 훅 주입 줄이 15곳 있고 이는 맥마다 다르다. 그래서 통째로 저장소에 넣으면 다른 맥에 쓸모없는 훅이 따라간다. A 는 내 설정만 저장소에 둔다. 감수하는 단점: 설정을 바꾸면 저장소 쪽에도 반영해야 한다.

답: 결정2 A

결정3. 허브 폴더의 스크립트·역할 파일도 저장소에 넣을까?

지금 문제: 허브 스크립트 10개와 역할 파일 10개가 토큰·로그와 한 폴더에 있다. 이력이 없어 잘못 고쳐도 되돌릴 수 없다.

안 정하면 멈추는 것: 저장소 폴더 중 허브 칸을 만들지 말지 몰라 구조가 확정되지 않는다.

선택지고르면비용되돌리기
A. 넣는다 ✅ 추천
스크립트·역할·봇 설정 양식만 파일별 링크		이력이 생기므로 잘못 고친 스크립트를 되돌릴 수 있다.허용 목록 약 25줄, 설치 뒤 봇 동작 확인 1회쉬움 — 링크를 원본 파일로 되돌린다
B. 넣지 않는다
허브 폴더는 지금처럼 로컬에만 둔다		토큰 유출 위험은 없지만 이력과 맥 간 공유가 계속 없다.없음쉬움 — 나중에 넣으면 된다

추천 이유: 이 스크립트들은 같은 날 고친 백업본이 6개 남을 만큼 자주 바뀐다. 그래서 이력이 없으면 어느 수정이 문제인지 못 찾는다. A 는 허용 목록으로 토큰·상태 파일을 막는다. 감수하는 단점: 링크된 스크립트의 위치 계산이 깨지지 않는지 확인해야 한다.

답: 결정3 A

결정4. 원격 맥은 직접 pull 해서 맞출까?

지금 문제: 원격 맥 설정은 손으로 맞추고 있어 기준이 없다. 이 맥에서는 접속 시도가 시간 초과로 끝나 상태를 확인하지 못했다.

안 정하면 멈추는 것: 설치 문서의 동기화 절차를 못 써서 원격 맥 반영이 보류된다.

선택지고르면비용되돌리기
A. 직접 pull ✅ 추천
맥에서 pull 후 설치 스크립트 실행		바꾸는 시점을 내가 정하므로 작업 중에 규칙이 바뀌지 않는다.명령 2줄을 맥마다 실행쉬움 — 이전 커밋으로 pull
B. 세션 시작 때 자동 pull
훅이 세션을 열 때마다 pull		잊어도 맞춰지지만 세션 도중 규칙 파일이 바뀔 수 있다.훅 추가와 충돌 처리 규칙보통 — 훅을 빼야 한다

추천 이유: 맥이 두 대라 직접 pull 의 번거로움이 작다. 그래서 충돌이 나면 세션이 막히는 자동 pull 의 위험을 질 이유가 없다. A 로 시작해 불편하면 B 를 붙인다. 감수하는 단점: pull 을 잊으면 맥끼리 달라진다.

🧱 폴더 구조안 / 설치 방식

claude-config/
├─ README.md            설치·동기화 절차
├─ install.sh           링크 생성 + 설정 병합 (--dry-run 지원)
├─ links.tsv            원본 → 대상 → 방식(link|merge) 목록
├─ claude/
│  ├─ CLAUDE.md
│  ├─ keybindings.json
│  ├─ settings.base.json   내 설정만, Orca 항목 제외
│  ├─ hooks/              스크립트 + lib/
│  └─ meat-proxy/
├─ skills/<이름>/        직접 작성한 스킬만
├─ hubs/
│  ├─ scripts/ roles/ launchd/
│  └─ slack-bot.env.example   값 없는 양식
└─ .gitignore           *.env, *.bak*, state, logs 방어용
  • 🟢 install.sh 는 links.tsv 에 적힌 항목만 처리한다.
  • 🟢 이미 있는 실제 파일은 백업 폴더로 옮긴 뒤 링크한다.
  • 🟢 --dry-run 은 바꿀 내용만 출력한다.
  • 🔵 설치 후 점검 모드가 끊어진 링크와 어긋난 설정을 보고한다.
  • 🟡 프로필 홈은 이미 ~/.claude 를 링크하므로 바꾸지 않는다.
  • 🟡 스킬은 폴더 단위가 아니라 스킬마다 링크해 외부 항목과 섞이지 않게 한다.

🔄 여러 맥 동기화

  • 🟢 새 맥: 저장소 clone → install.sh --dry-run → install.sh.
  • 🟢 갱신: git pull → install.sh.
  • 🟢 변경: 작업 브랜치에서 커밋, push 와 병합은 승인 뒤에만.
  • ⚠️ 맥별로 다른 값은 설정 병합 단계에서 따로 얹고 저장소에 넣지 않는다.
  • ⚠️ 원격 맥은 접속 확인이 먼저다. 이 맥에서는 시간 초과였다.

스킬 연결: 폴더째가 아니라 스킬마다

before (지금, 외부 링크가 섞임)
~/.claude/skills/
  comment-lint/        (실제 폴더)
  create-pr/           (실제 폴더)
  synced/              (외부 도구 관리)
  dart-mcp-workflow -> ~/agent-config/skills/...
  factory-workflow  -> ~/.local/share/unity-factory/...

# 폴더째 링크하면 synced 8.7MB 가
# 저장소로 들어온다
after (제안)
# links.tsv
skills/comment-lint  .claude/skills/comment-lint  link
skills/create-pr     .claude/skills/create-pr     link

# install.sh 핵심
while IFS=$'\t' read -r src dst mode; do
  [ "$mode" = link ] || continue
  [ -e "$HOME/$dst" ] && [ ! -L "$HOME/$dst" ] \
    && mv "$HOME/$dst" "$BACKUP/"
  ln -sfn "$REPO/$src" "$HOME/$dst"
done < links.tsv

왜: 목록에 적은 스킬만 링크하므로 외부 도구가 관리하는 폴더가 저장소에 섞이지 않는다.

after (제안)
# links.tsv
claude/settings.base.json  .claude/settings.json  merge

# install.sh merge 단계
# 1) 기존 파일을 백업
# 2) 기존 파일의 Orca 항목을 보존
# 3) 기본값 위에 얹어 새 파일 생성
jq -s '.[0] * .[1]' \
  "$REPO/claude/settings.base.json" \
  "$ORCA_KEEP" > "$HOME/.claude/settings.json"

# 병합 규칙의 세부는 구현 때 확정(미확정)

🔄 진행 순서

  1. 구조 승인 — 검증: 결정 1~4 답 수령
  2. 저장소에 파일 복사 후 첫 커밋 — 검증: 제외 목록 파일이 0개, 토큰 패턴 검색 0건
  3. install.sh --dry-run 실행 — 검증: 바뀔 항목 목록이 links.tsv 와 일치
  4. 이 맥에 설치 — 검증: ls -l 로 링크 확인, 새 세션에서 스킬 목록 37개 유지
  5. 허브 링크 후 봇 동작 확인 — 검증: 알림 스크립트 드라이런 1회, 실패 시 원복
  6. 원격 맥 접속 확인 후 설치 — 검증: 이 맥과 같은 점검 모드 결과
  7. push 와 PR — 검증: 승인 뒤에만
