결정1. 설치를 직접 만든 링크 스크립트로 할까?

지금 문제: 스킬 폴더 안에 외부 도구가 관리하는 항목이 섞여 있다. 폴더째 링크하면 그 항목까지 저장소로 들어온다.

안 정하면 멈추는 것: 저장소 폴더 구조와 설치 파일 형식을 못 정해 저장소를 채우지 못한다.

선택지고르면비용되돌리기
A. 링크 스크립트 ✅ 추천
링크는 파일을 복사하지 않고 원본을 가리키는 바로가기다. 목록에 적은 항목만 링크한다.		목록 밖 항목은 건드리지 않으므로 외부 도구 폴더가 안전하다.스크립트 약 100줄과 훅 공통 파일 1줄 수정(추정, 근거는 참고)쉬움 — 링크를 지우고 백업 폴더에서 원본을 되돌린다
B. chezmoi
홈 폴더 설정 파일을 복사해 적용하는 도구. 파일마다 맥별 값을 넣는 템플릿 기능이 있다.		템플릿을 쓰므로 맥마다 다른 값을 넣기 편하다.도구 설치와 학습, 저장소 파일 이름 규칙 변경보통 — 복사본이라 원본과 어긋날 수 있다

추천 이유:
• 맥별 값이 필요하다는 증거를 이 맥에서 찾지 못했다. 원격 맥은 미확인이다.
• 그래서 템플릿 기능이 필요 없고 A 가 외부 폴더를 건드리지 않는 쪽이다.
감수하는 단점: 스크립트를 직접 유지한다.

답: 결정1 A

결정2. 설정 파일은 링크 대신 병합 복사로 설치할까? (결정1 이 A 일 때)

지금 문제: 설정 파일에 Orca(여러 AI 에이전트를 함께 돌리는 편집기)가 넣은 훅(정해진 시점에 자동 실행되는 스크립트) 항목이 14개 섞여 있다.
그래서 파일째 저장소에 넣으면 이 항목도 같이 커밋된다.

안 정하면 멈추는 것: 설정 파일의 저장 모양을 몰라 첫 커밋을 못 한다.

선택지고르면비용되돌리기
A. 병합 복사 ✅ 추천
기본값과 Orca 항목을 합친 새 파일		내 항목만 저장소에 있어 Orca 항목이 커밋되지 않는다.병합 식 6줄, 복사본에서 동작 확인쉬움 — 백업본으로 복원
B. 링크
설정 파일 자체를 저장소로 링크		Orca 항목이 저장소 파일에 들어가 커밋된다.스크립트 없음쉬움 — 링크를 지우면 된다

추천 이유:
• 그래서 A 는 내 항목만 저장소에 두고 설치 때 합친다.
• 설정 백업본 3종 모두 Orca 15줄이 있다. 재주입 정황이나 원인은 미확인이다.
• Orca 가 링크를 끊는다는 보고는 2차 글 요약뿐이라 미확인이다.
• 맥마다 Orca 항목이 다른지는 원격 맥 미확인이라 근거에서 뺐다.
감수하는 단점: 설정을 바꾸면 저장소 쪽에도 반영해야 한다.

답: 결정2 A

결정3. 허브 폴더의 스크립트·역할 파일도 저장소에 넣을까? (결정1 이 A 일 때)

지금 문제: 허브 스크립트와 역할 파일이 토큰 파일·로그와 한 폴더에 있다.
이력이 없어 잘못 고쳐도 되돌릴 수 없다.

안 정하면 멈추는 것: 저장소 폴더 중 허브 칸을 만들지 말지 몰라 구조가 확정되지 않는다.

선택지고르면비용되돌리기
A. 넣는다 ✅ 추천
스크립트·역할·봇 양식만 파일별 링크		이력이 생기므로 잘못 고친 스크립트를 되돌릴 수 있다.링크 목록 20줄 안팎(추정), 봇 동작 확인 1회쉬움 — 링크를 지우고 백업 폴더에서 되돌린다
B. 넣지 않는다
허브 폴더는 지금처럼 로컬에만 둔다		토큰 유출 위험은 없지만 이력과 맥 간 공유가 계속 없다.없음쉬움 — 나중에 넣으면 된다

추천 이유:
• 허브 폴더에 손으로 만든 백업본이 7개 있다. 11-05 에 6개, 11-06 에 1개다.
• 그래서 백업본이 이력을 대신하고 있다.
• A 는 허용 목록으로 토큰·상태 파일을 막는다.
• 활성 launchd 설정은 다른 폴더의 복사본이라 설치가 따로 복사한다.
감수하는 단점: 링크 뒤 봇 동작 확인이 필요하다. 알림 스크립트 외에는 미확인이다.

답: 결정3 A

결정4. 원격 맥은 직접 pull 해서 맞출까?

지금 문제: 원격 맥 설정을 맞출 기준 저장소가 없다.
이 맥에서 접속하면 시간 초과가 나서 원격 맥 상태는 미확인이다.

안 정하면 멈추는 것: 설치 문서의 동기화 절차를 못 써서 원격 맥 반영이 보류된다.

선택지고르면비용되돌리기
A. 직접 pull ✅ 추천
pull 은 저장소의 최신 내용을 받아오는 명령이다. 받은 뒤 설치 스크립트를 실행한다.		바꾸는 시점을 내가 정하므로 작업 중에 규칙이 바뀌지 않는다.명령 2줄을 맥마다 실행쉬움 — 이전 커밋으로 pull
B. 세션 시작 때 자동 pull
세션을 열 때마다 훅이 pull 을 실행		잊어도 맞춰지지만 세션 도중 규칙 파일이 바뀔 수 있다.훅 추가와 충돌 처리 규칙보통 — 훅을 빼야 한다

추천 이유:
• 작업 지시상 맥은 두 대이고 원격 맥은 미확인이다.
• 그래서 자동 pull 의 충돌 위험을 질 이유가 아직 없다.
• A 로 시작해 불편하면 B 를 붙인다.
감수하는 단점: pull 을 잊으면 맥끼리 달라진다.

실제 사례

  • 🟢 허용 목록 방식 — 설정·규칙·스킬·훅 폴더만 추적하고 세션·기록은 제외한 공개 저장소가 있다.
  • 🟢 stow 패키지 방식 — 설정·훅·규칙·스킬 1개를 한 패키지로 묶고 새 맥에서 stow 한 번으로 설치하는 제안이 있다.
  • 🟢 링크 + 자동 동기화 — 규칙 파일을 링크하고 시작 훅에서 pull, 종료 훅에서 push 하는 도구가 있다.
  • ⚠️ Orca 가 설정 파일 링크를 실제 파일로 바꿔 저장소와 끊었다는 보고가 있다.
  • 이 보고는 검색 요약만 봤고 이 맥에서 재현하지 못해 미확인이다. 결정2 의 근거에서 뺐다.
  • ⚠️ 자동 push 는 이 환경의 승인 규칙과 충돌하므로 채택하지 않는다.

🧱 폴더 구조안 / 설치 방식

claude-config/
├─ README.md            설치·동기화 절차
├─ install.sh           링크 생성 + 설정 병합 + git 설정 (--dry-run 지원)
├─ links.tsv            원본 → 대상 → 방식(link|merge) 목록
├─ claude/
│  ├─ CLAUDE.md
│  ├─ keybindings.json
│  ├─ settings.base.json   내 설정만, Orca 항목 제외
│  ├─ hooks/              스크립트 7 + lib/ (state 는 홈에 남김)
│  └─ meat-proxy/
├─ skills/<이름>/        직접 작성한 스킬만
├─ git/hooks/            git 훅 9개
├─ hubs/
│  ├─ scripts/ roles/ launchd/
│  ├─ roles/*.example     자리표시본 2개
│  └─ slack-bot.env.example   값 없는 양식
├─ docs/out/             문서 허브 전용 브랜치에서만 추적 (main 제외)
└─ .gitignore           *.env, *.bak*, __pycache__, state, logs,
                         HANDOFF.md, decisions.tsv
  • 🟢 install.sh 는 links.tsv 에 적힌 항목만 처리한다.
  • 🟢 백업 폴더는 설치 때 만든다. 경로는 ~/.claude-config-backup/시각.
  • 🟢 이미 있는 실제 파일은 백업 폴더로 옮긴 뒤 링크한다.
  • 🟢 백업 폴더 이름은 시각까지(초 단위) 붙여 같은 날 2회 실행해도 겹치지 않는다.
  • 🟢 install.sh 는 set -e 로 시작하고 백업 폴더가 없으면 만든다(mkdir -p).
  • 🟢 대상이 실제 폴더인지 먼저 검사하고, 옮기기 실패 시 링크를 만들지 않고 중단한다.
  • 🔵 설치 후 점검 모드가 끊어진 링크와 어긋난 설정을 보고한다.
  • 🟡 프로필 홈은 이미 ~/.claude 를 링크하므로 바꾸지 않는다.
  • 🟢 links.tsv: 탭으로 칸을 나눈 목록 파일. 한 줄이 항목 하나다.
  • 🟢 --dry-run: 실제로 바꾸지 않고 바뀔 내용만 보여 주는 실행 옵션.
  • 🟡 스킬은 폴더 단위가 아니라 스킬마다 링크해 외부 항목과 섞이지 않게 한다.
  • 🟡 훅은 폴더째가 아니라 스크립트 7개와 lib 폴더만 링크한다. state 폴더는 제자리에 둔다.
  • ⚠️ 훅 공통 파일은 자기 위치를 realpath 로 구해 state 경로를 정한다. 링크하면 state 가 저장소 클론 안으로 간다.
  • 🔵 임시 폴더 복사본에서 재현했다. 링크 경로로 읽으면 state 경로가 저장소 쪽으로 잡혔다.
  • 🟡 해결: 공통 파일 4행 1줄을 고정 경로로 바꾼다. 기본값은 지금 위치인 hooks/state 다.
  • 🔵 수정본으로 재현하니 state 가 홈 쪽에 남고 기존 로그를 그대로 읽었다. 저장소 쪽엔 state 가 생기지 않았다.
  • 🔵 대안은 훅만 복사 설치(rsync)다. 수정은 필요 없으나 고친 훅이 저장소로 돌아가지 않아 기각했다.
  • 🟢 허브 설치: 스크립트·역할을 파일별 링크한다. 계정 값이 든 역할 2개는 링크하지 않는다.
  • 🟢 launchd: 허브 쪽 설정을 홈의 Library 안 launch 에이전트 폴더로 복사하고 재적재한다. 재적재 명령은 구현 때 확정(미검증).
  • 🟢 git 훅: 9개를 파일별 링크하고 git 설정 4개 키를 git config 로 넣는다.
  • 🟢 문서 허브 이전 시 허브 워크스페이스는 이 저장소의 Orca 워크스페이스가 된다.
  • 🟢 docs/out/ 은 허브 전용 브랜치에서만 추적한다. HANDOFF.md 와 decisions.tsv 는 .gitignore 로 미추적이다.
  • ⚠️ 위 두 줄은 다른 문서의 결정3·5 가 확정돼야 맞다. 지금은 자리만 잡은 것이다.
  • 🛟 되돌리기: 링크를 지우고 백업 폴더의 파일을 원래 자리로 복사한다.
  • 🛟 점검: ls -l 로 실제 파일로 돌아왔는지 확인한다. 설정 파일은 설치 전 백업본으로 복원한다.

스킬 연결: 폴더째가 아니라 스킬마다

before (지금, 외부 링크가 섞임)
~/.claude/skills/
  comment-lint/        (실제 폴더)
  create-pr/           (실제 폴더)
  synced/              (외부 도구 관리)
  dart-mcp-workflow -> ~/agent-config/skills/...
  factory-workflow  -> ~/.local/share/unity-factory/...

# 폴더째 링크하면 synced 8.7MB 가
# 저장소로 들어온다
after (제안)
# links.tsv
skills/comment-lint  .claude/skills/comment-lint  link
skills/create-pr     .claude/skills/create-pr     link

# install.sh 핵심 (임시 폴더에서 동작 확인)
set -euo pipefail
# BACKUP: 덮어쓰기 전 보관 폴더, 초 단위 시각
BACKUP=$HOME/.claude-config-backup/$(date +%Y%m%d-%H%M%S)
while IFS=$'\t' read -r src dst mode; do
  [ "$mode" = link ] || continue
  t=$HOME/$dst
  if [ -L "$t" ]; then rm "$t"
  elif [ -e "$t" ]; then
    mkdir -p "$BACKUP"; mv "$t" "$BACKUP/${dst//\//_}"
  fi
  ln -s "$REPO/$src" "$t"
done < links.tsv

왜: 목록에 적은 스킬만 링크하므로 외부 도구가 관리하는 폴더가 저장소에 섞이지 않는다.

옛 루프 재현: 백업 폴더가 없어 옮기기가 실패하자 ln -sfn 이 기존 폴더 안에 링크를 만들었다.
새 루프: 옮기기 실패 시 중단하고 기존 폴더가 그대로 남았다. 폴더 안 링크도 생기지 않았다.
같은 설치를 연속 2회 실행해도 오류가 없고 백업 폴더는 1개였다.

설정 파일: 링크가 아니라 병합

before (지금)
# ~/.claude/settings.json 과
# 프로필 홈 settings.json 은
# 내용이 같은 실제 파일 두 벌
$ cmp settings.json $PROFILE/settings.json
(출력 없음 = 같음)

# Orca 항목이 섞여 있음
# 훅 항목 14개 + 상태줄 1개
$ grep -c ORCA_AGENT_HOOK settings.json
15   # 줄 수
after (제안)
# links.tsv
claude/settings.base.json  .claude/settings.json  merge

# install.sh merge 단계 (복사본으로 동작 확인)
# CUR: 현재 설정 파일, NEW: 병합 결과 임시 파일
# ORCA_KEEP: 현재 파일에서 Orca 훅·상태줄만 뽑은 임시 파일
jq '{hooks:(.hooks|map_values(map(select(
  tostring|contains("ORCA_AGENT_HOOK"))))
  |with_entries(select(.value|length>0))),
  statusLine}' "$CUR" > "$ORCA_KEEP"
# 기본값 + Orca 항목
jq -s -f merge.jq base.json "$ORCA_KEEP" > "$NEW"

# merge.jq: 훅 배열을 순서 유지하며 이어붙임
def dd: reduce .[] as $i ([];
  if index([$i]) then . else . + [$i] end);
.[0] as $a | .[1] as $b | ($a * $b)
| .hooks = (($a.hooks//{}) as $x | ($b.hooks//{}) as $y
  | reduce ((($x|keys_unsorted)+($y|keys_unsorted))|dd[]) as $k
    ({}; .[$k] = ((($x[$k]//[])+($y[$k]//[]))|dd)))

왜: 단순 병합 식 jq '.[0] * .[1]' 는 배열을 덮어써서 복사본에서 훅 22개 중 6개를 잃었다.

확인: 스크래치 폴더에 설정 파일 사본을 두고 기본값 8개와 Orca 14개로 나눠 합쳤다.
순서 유지 식은 22개를 모두 보존했고 나머지 설정도 같았다.
정렬하는 unique 식은 이벤트 10개의 순서를 바꿨고 순서 유지 식은 1개만 바꿨다.
결과로 다시 설치해도 파일이 바이트까지 같았다. 원본 파일은 건드리지 않았다.
