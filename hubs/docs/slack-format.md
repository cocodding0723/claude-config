# Slack 메시지 고정 양식 (양식 A)

## 쉬운 말 3줄 요약

- 무엇이 바뀌었나: 봇이 보내는 메시지 모양을 하나로 고정했다. 첫 줄은 "종류 이모지 + 주제", 그 아래 무엇·왜·결과를 한 줄씩 쓴다.
- 왜: 메시지마다 모양이 달라 읽기 힘들다는 지적(11-09)이 있었다. 사용자가 "양식 A로 간다"고 확정했다.
- 사용자가 할 일: 없다. 보내는 쪽 스크립트가 `--kind` 를 붙여 부르면 `slack_notify.sh` 가 양식을 검사하고 이모지를 붙인다. 처음 1주는 어겨도 그대로 전송하고 경고만 남긴다.
- 추가(11-10): 결정 카드에 선택지를 붙이면(`--options`) 사용자는 번호 이모지(:one: :two: :three:) 하나로 고른다. ✅ 는 추천대로, ❌ 는 보류다. 아래 「이모지로 고르는 결정 카드」.

## 양식 A 규칙

| 번호 | 규칙 | 검사 | 위반 시 |
|---|---|---|---|
| 1 | 첫 줄 = 종류 이모지 + 주제. 이모지·공백 제외 40자 이내 | 자동 | 위반 `title-len` |
| 2 | 첫 줄 다음은 빈 줄 | 안 함 | - |
| 3 | `• 무엇:` `• 왜:` `• 결과:` 순서, 한 줄에 사실 하나 | 안 함 | - |
| 4 | 결정·할 일이면 `👉 답: …` 줄 필수. 줄 머리의 `👉 답:` 또는 `:point_right: 답:` 만 답 줄로 친다 | 자동 (`--kind decide`·`todo`) | 위반 `no-answer` |
| 5 | 티켓·커밋 번호, 파일명은 맨 아래 `참고:` 줄에만 | 번호만 자동 (`LRM-숫자`, 숫자·영문이 섞인 7자 이상 hex) | 위반 `ticket`·`hex` |
| 6 | 굵게(`*…*`)는 메시지당 1곳 | 자동, 경고만 | 경고 `bold` |
| 7 | 결정 카드는 결정 1건 = 메시지 1개 | 자동 (`--kind decide` 만) | 거부 `multi` (모드와 무관) |

검사에서 빼는 구간: 코드 블록, 인라인 코드, URL, 마지막 `참고:` 로 시작하는 줄부터 끝까지. 첫 줄이 `참고:` 로 시작해도 제외 구간으로 보지 않는다. 답 줄(`👉 답:`) 판정도 이 구간 앞의 본문에서만 한다. 파일명·고유명사·내부 기호(규칙 3, 5 의 파일명 부분)는 기계가 판정하지 못하므로 사람이 지킨다.

## 결정 1건 = 메시지 1개 (규칙 7)

한 메시지에 결정이 여러 개면 이모지 답이 어느 결정에 대한 것인지 모호하다. 그래서 `--kind decide` 본문에 결정이 둘 이상이면 보내지 않는다. 결정 개수를 검사할 수 없을 때(python3 실패)도 보내지 않는다.

- 결정 개수 판별은 보수적으로 둘 중 큰 값이다. 코드 블록·인라인 코드·URL은 세지 않는다. 마지막 `참고:` 줄 이후는 `👉 답:` 줄만 센다(그 뒤의 번호 머리·불릿 안 결정 참조는 세지 않음). 표(`|` 로 시작) 줄도 번호 판정에서 뺀다. 검사 앞에서 NFC 로 정규화하므로 조합형 한글도 같다.
  - `👉 답:` 줄(또는 `:point_right: 답:`) 개수.
  - 번호 매긴 결정 제목의 **서로 다른 번호** 개수(같은 번호 반복은 1개). 줄 머리 접두(인용 `>`, 불릿 `•`·`-`·`*`·`·`, 굵게 `**`/`*`, 머리글 `#`, 대괄호 `[`)를 허용하고 아래 둘 중 하나면 제목이다.
    - 접두 바로 뒤에 `결정` + (`-`·`#`)? + 번호. 번호는 `①`~`⑳` 또는 1~2자리 숫자(+ 선택 `번`)이고, 숫자는 뒤가 `)`·`.`·`:`·공백·굵게 끝·`]`·줄 끝일 때만 인정한다(`결정 1번:`·`### 결정 1`·`[결정 1]` 포함. 줄 머리에 있어야 해서 오탐 위험이 낮다고 보고 넣었다)(`결정 2026-11-01`·`결정 100건` 은 제외).
    - 번호 머리(`①`~`⑳`, `1.`, `1)`, `(1)`, `1번`, 키캡 `1️⃣`) **바로 뒤**의 `결정`(`1. 결정 시각`). 번호 머리 뒤 중간에 낀 `결정`(`1. 기존 결정 유지`)과 줄 중간의 `② 결정 변경` 은 선택지 문구라 세지 않는다.
    - 줄 중간의 `결정 N`(앞이 글자가 아니고, 뒤가 `)`·`.`·`:`·`*` 이거나 번호가 `①`~`⑳`)은 **세지 않고 경고만** 한다(`경고: 줄 중간에 다른 번호의 '결정 N' 이 있음`). 본문 참조(`지난주 결정 3) 과 충돌`)와 한 줄에 이어 쓴 `결정 1) … 결정 2) …` 를 구분할 수 없어서다. 이 경고는 warn·strict 모두 거부하지 않는다. 같은 번호 반복은 경고도 없다.
- 2개 이상이면 `LRM_FORMAT=warn`(기본)이어도 미전송·종료 코드 2다. `거부: 결정이 N개임(전송 안 함) — 1건씩 따로 보내세요. 예: …` 한 줄이 stderr 로 나오며, 다른 경고·위반 줄이 있어도 그 뒤 마지막 줄에 온다.
- 세지 않는 경우(오탐 방지): 결정 1건 안의 선택지 나열(`A 9시 / B 10시`, `① A안 ② B안`, `1. 기존 결정 유지` / `2. 결정 철회`), 번호 머리 뒤에 `결정` 이 바로 오지 않는 번호 목록(`1. 이미 결정된 것`), 날짜·수량(`결정 2026-11-01:`), `--choices` 가 붙이는 안내 줄(검사가 부착보다 먼저 돈다).
- 우회: `--no-check` 와 `LRM_FORMAT=off` 는 그대로 통한다(python3 실패 때도 마찬가지). 다만 `--kind decide` 일 때 집계 로그에 한 줄(`bypass-no-check` 또는 `bypass-off`, 본문 없음)을 남긴다.
- `todo`·`done`·`progress`·`warn`·`doc` 과 `--kind` 없는 호출은 영향이 없다.
- 보낼 때는 결정마다 `slack_notify.sh --kind decide` 를 따로 부른다. 분할을 대신 해 주는 `--split` 옵션은 두지 않았다.

## 이모지로 고르는 결정 카드 (`--options`)

결정 1건을 메시지 1개로 보내고, 사용자는 번호 이모지 반응 하나로 고른다. 선택지·추천·답하는 법 줄은 도구가 만든다. 호출한 쪽은 제목과 배경만 쓴다.

### 카드 모양 (가짜 내용)

```
:비서-선택해주세요: 알림 보내는 시각

• 왜: 지금은 시각이 제각각이라 놓치는 경우가 있음

:one: 오전 9시
:two: 오전 10시
:three: 정하지 않고 지금처럼
:star: 추천: :one: · 되돌리기: 쉬움
👉 답: :one: :two: :three: 중 하나 · :white_check_mark: 추천대로 · :x: 보류

참고: 결정 D-0001 · 3/9
```

| 줄 | 누가 쓰나 | 내용 |
|---|---|---|
| 제목 | 호출한 쪽 | 첫 줄. 양식 A 규칙 1(40자) 그대로 |
| 배경 | 호출한 쪽 | 한두 줄. 선택지·답 줄은 쓰지 않는다 |
| 선택지 | 도구 | `--options` 의 번호마다 `:one:`~`:four:` 한 줄. 2~4개 |
| 추천·되돌리기 | 도구 | `:star: 추천: :N:`, `--reversible` 이 있으면 ` · 되돌리기: 쉬움\|보통\|어려움` |
| 답하는 법 | 도구 | `👉 답:` 줄 1개. 이 카드의 유일한 답 줄이다 |
| 결정 번호·순번 | 도구 | `참고:` 블록 맨 끝. 본문에 `참고:` 가 없으면 `참고: 결정 D-0001 · 3/9` 줄을 새로 만든다 |

- 양식 검사(규칙 1~7)는 **호출한 쪽 본문에만** 돈다. 도구가 붙이는 줄은 검사가 끝난 뒤 붙으므로 선택지 문구에 "결정"이 들어가도 결정 개수(규칙 7)에 세지 않는다. `--choices` 안내 줄과 같은 방식이다.
- 답 줄(규칙 4)은 도구가 채우므로 `no-answer` 위반이 나지 않는다. 본문에 `👉 답:` 줄을 직접 쓰면 답 줄이 둘이 되므로 **거부한다**(종료 코드 2, `--no-check`·`LRM_FORMAT=off` 여도 거부).
- 본문 줄 머리에 `:one:`·`1️⃣` 같은 선택지 줄이 있으면 경고만 하고 보낸다(도구가 만든 선택지와 겹쳐 보임).
- 선택지 줄·추천 줄은 `참고:` 블록 앞에 들어간다. 규칙 5(번호는 `참고:` 줄에만)를 지키려고 결정 번호는 `참고:` 블록에 둔다.

### 이모지 표준표

같은 이모지라도 카드 종류에 따라 뜻이 다르다. 표에 없는 조합은 해석하지 않고 이모지 이름을 그대로 넘긴다.

| 이모지 (반응 이름) | 결정 카드 `--options` | 옛 결정 카드 (`--choices`·종류 없음) | 시안 `review` | 할 일 `todo` |
|---|---|---|---|---|
| :one: :two: :three: :four: (`one`~`four`) | 선택 N. 선택지 수보다 큰 번호는 이름 그대로 | 이름 그대로 | 이름 그대로 | 이름 그대로 |
| ✅ `white_check_mark` | 추천대로(추천 번호를 고른 것으로 봄) | 승인 `approve` | 합격 `pass` | 완료 `done` |
| ❌ `x` | 보류 `hold` | 보류 `hold` | 불합격 `fail` | 보류 `hold` |
| 🛠️ `hammer_and_wrench` | 이름 그대로 | 이름 그대로 | 이름 그대로 | 완료 `done` |
| `:비서-a:`~`:비서-d:` | 이름 그대로 | `a`~`d` | `pick_a`·`pick_b`(c·d 는 이름 그대로) | 이름 그대로 |
| `:비서-추천대로:` 등 | 이름 그대로 | `approve` | 이름 그대로 | 이름 그대로 |
| `:비서-보류:` | 이름 그대로 | `hold` | 이름 그대로 | 이름 그대로 |

- 새 카드는 사용자 결정(11-10)대로 번호 이모지(1️⃣2️⃣3️⃣)를 쓴다. 🅰️🅱️·`:비서-a:` 는 옛 카드·시안 전용으로 남겨 뜻이 섞이지 않게 했다.
- 옛 카드(`--options` 없이 보낸 것)의 해석은 바뀌지 않는다.

### 호출

```sh
slack_notify.sh --tag ui-hub --kind decide \
  --options '1=오전 9시,2=오전 10시,3=정하지 않고 지금처럼' \
  --recommend 1 --reversible 쉬움 --decision-id D-0001 --seq 3/9 \
  $'알림 보내는 시각\n\n• 왜: 지금은 시각이 제각각이라 놓치는 경우가 있음'
```

| 인자 | 필수 | 형식 | 틀리면 |
|---|---|---|---|
| `--options` | ○ | `N=문구` 를 쉼표로 이음. 번호는 1부터 연속 2~4개, 문구 1~80자. 문구 안 쉼표는 뒤에 `숫자=` 가 오지 않으면 그대로 둔다 | 종료 코드 2 |
| `--recommend` | ○ | 선택지 번호 중 하나 | 종료 코드 2 |
| `--decision-id` | ○ | `D-` + 영문·숫자 1~16자 | 종료 코드 2 |
| `--reversible` | | `쉬움`·`보통`·`어려움` | 종료 코드 2 |
| `--seq` | | `순번/전체`(예 `3/9`), 1 ≤ 순번 ≤ 전체 ≤ 999 | 종료 코드 2 |

- 다섯 인자는 `--kind decide` 에서만 쓴다. `--recommend`·`--reversible`·`--decision-id`·`--seq` 는 `--options` 와 함께만 쓴다. `--choices` 와 `--options` 는 함께 쓸 수 없다.
- 문구에 줄바꿈·제어 문자·방향 제어 문자가 있으면 거부한다. 줄바꿈이 있으면 가짜 `👉 답:` 줄이나 가짜 선택지 줄을 만들 수 있기 때문이다.
- `--decision-id` 를 필수로 둔 이유: 한 허브가 같은 `--tag` 로 결정을 여러 개 보내므로 태그에서 만든 번호는 겹친다. 번호가 겹치면 답이 다른 결정에 붙는다. 이것이 가장 나쁜 실패라 추정하지 않고 거부한다.

## 할 일 카드 (`--kind todo --todo-id`)

- `--todo-id T-xxxx`(`T-` + 영문·숫자 1~16자)는 `--kind todo` 에서만 쓴다. 주면 보낸 기록에 `todo_id` 가 남는다.
- `--todo-id` 가 있고 본문에 `👉 답:` 줄이 없으면 `👉 답: 끝나면 :white_check_mark: (또는 :hammer_and_wrench:) · 보류는 :x:` 줄과 `참고: 할 일 T-xxxx` 를 붙인다. 없으면 기존 동작 그대로다.
- 답 줄을 직접 쓸 때는 ✅ 글자 대신 `:white_check_mark:` 이름을 쓴다. 줄 중간의 ✅ 글자는 `:비서-추천대로:` 로 바뀌고, 할 일 카드에서 그 이모지는 완료로 읽지 않는다.

## 종류별 이모지

| `--kind` | 뜻 | 유니코드 | Slack 에 보이는 이름 |
|---|---|---|---|
| `decide` | 결정 필요 | 🙋 | `:비서-선택해주세요:` |
| `todo` | 직접 할 일 | 🛠️ | 🛠️ (치환 없음) |
| `done` | 완료 | ✅ | `:white_check_mark:` (줄머리 ✅ 는 완료 표시라 표준 ✅ 로 둠) |
| `progress` | 진행 중 | 🔄 | `:비서-진행중:` |
| `warn` | 문제·주의 | ⚠️ | `:비서-긴급:` |
| `doc` | 문서 | 📄 | `:비서-공유합니다:` |

- 첫 줄에 6종 중 하나가 이미 있으면(유니코드 또는 위 이름) 다시 붙이지 않는다.
- 라벨 글자("결정 필요:")는 붙이지 않는다. 이모지만 붙고 주제는 호출한 쪽이 쓴 그대로 간다.
- ✅ 는 위치로 뜻이 갈린다. 줄 머리(앞 공백이나 `•` 불릿 뒤 포함)의 ✅ 는 완료 표시라 `:white_check_mark:` 로, 줄 중간의 ✅ 는 반응 선택지라 `:비서-추천대로:` 로 바뀐다. `-`·`*` 불릿 뒤 ✅ 는 넓히지 않아 `:비서-추천대로:` 가 된다. `--kind` 가 없는 호출에도 적용한다(아래 호출 방법의 예외).

## 렌더 예시 (가짜 내용)

결정 필요:

```
🙋 알림 보내는 시각

• 무엇: 아침 알림을 몇 시에 보낼지 정해야 함
• 왜: 지금은 시각이 제각각이라 놓치는 경우가 있음
• 결과: 정하면 다음 날부터 같은 시각에 도착

👉 답: :비서-a: A · :비서-b: B · :비서-c: C · :비서-추천대로: 추천대로 · :비서-보류: 보류

참고: 샘플-123
```

완료:

```
✅ 알림 시각 통일

• 무엇: 모든 알림을 오전 9시로 맞춤
• 결과: 내일부터 한 번에 도착

참고: 샘플-123
```

문제:

```
⚠️ 알림 하나가 안 나감

• 무엇: 어제 저녁 알림 1건이 전송되지 않음
• 왜: 연결이 잠시 끊긴 것으로 보임
• 결과: 다시 보내 두었고 오늘은 정상

👉 답: 확인만 해 주세요 (:비서-보류: 로 보류)
```

## 이모지로 답하기

결정 메시지 끝의 `👉 답:` 줄에 있는 이모지를 눌러 답한다.

| 이모지 | 뜻 | 표준 대체 이름 |
|---|---|---|
| `:비서-a:` | A | `:a:` |
| `:비서-b:` | B | `:b:` |
| `:비서-c:` | C | `:regional_indicator_c:` |
| `:비서-d:` | D | `:regional_indicator_d:` |
| `:비서-추천대로:` | 추천대로 | `:white_check_mark:` |
| `:비서-보류:` | 보류 | `:x:` |

- 선택지 수는 `--choices 2~4` 로 정한다. 줄에는 고른 수만큼만 A 부터 나열하고 추천대로·보류는 항상 붙는다.
- 기본 문구는 커스텀 이모지(`:비서-*:`)다. 커스텀 이모지가 아직 없으면 `--emoji-set std` 로 표준 이름 문구를 낼 수 있다.
- 충돌하는 기준이 하나 있다. 기준 메모리(slack-plain-language)는 결정 선택지를 2~3개로 권장하고, 이모지 답은 4개(A~D)까지 지원한다. **4개는 예외로 허용한다.** 선택지가 많을 때만 쓰고, 기본은 2~3개다.
- 같은 메시지에 반응이 여러 개면 마지막 반응이 답이다(`slack_pending.sh` 규칙).

## 호출 방법

```sh
# 완료 알림: 이모지 자동, 양식 검사
slack_notify.sh --kind done "알림 시각 통일"

# 결정 요청: 선택지 3개와 안내 줄 자동
slack_notify.sh --tag ui-hub --kind decide --choices 3 $'알림 보내는 시각\n\n• 무엇: …\n• 왜: …\n• 결과: …'

# 표준 이모지 문구
slack_notify.sh --kind decide --choices 2 --emoji-set std "…"

# 긴급해서 양식 검사를 건너뜀 (기록에 unchecked:true)
slack_notify.sh --no-check --kind warn "…"

# 결정이 2개면 거부 — 결정마다 한 번씩 따로 호출
slack_notify.sh --kind decide --choices 3 "결정 1 알림 시각 …"
slack_notify.sh --kind decide --choices 2 "결정 2 알림 문구 …"

# 이행 모드
LRM_FORMAT=strict slack_notify.sh --kind todo "…"    # 위반이면 미전송, 종료 코드 2
LRM_FORMAT=off    slack_notify.sh --kind todo "…"    # 검사 안 함
```

- `--kind` 가 없는 기존 호출은 동작·출력이 그대로이며 검사도 하지 않는다. 예외는 하나다: 줄머리 ✅ 는 `--kind` 가 없어도 `:white_check_mark:` 로 바뀐다. 본문 줄머리 ✅ 를 완료 표시로 확정한 기준(11-09)을 호출자 구분 없이 적용하려는 결정이다. 🅲·🅳 치환은 `--kind`(또는 `--choices`)가 있을 때만 하므로 `--kind` 없는 호출의 🅲·🅳 는 원문 그대로 간다.
- `--choices` 는 `--kind decide` 와 함께만 쓴다. 범위(2~4)나 조합이 틀리면 종료 코드 2.
- 본문에 `👉 답:` 줄이 이미 있으면 안내 줄을 붙이지 않는다. 마지막 `참고:` 줄이 있으면 그 앞에, 없거나 첫 줄뿐이면 맨 끝에 끼운다.
- 규칙 7(`multi`)은 위반 건수에 세지 않고 모드와 무관하게 거부한다. 그 외 위반은 warn 에서 전송한다.
- 검사 결과는 stderr 로 나온다: warn 은 `경고: …` 줄과 마지막 `양식 위반 N건(전송함)`, strict 는 `거부: …` 줄과 `양식 위반 N건(전송 안 함)`.
- python3 실행이 실패하면 `--kind decide` 는 모드와 무관하게 미전송·종료 코드 2다(로그 코드 `check-fail`). 다른 kind 는 warn 이 `양식 검사 실패 — 검사 없이 전송` 한 줄을 남기고 보내며, strict 는 미전송·종료 코드 2다. 안내 줄 부착이 실패해도 같다(warn 은 안내 줄 없이 전송). strict 의 python 실패는 decide 가 아닌 kind 에서도 로그에 `check-fail` 한 줄을 남긴다.

## 이행 단계

| 단계 | 내용 | 기준 |
|---|---|---|
| 1 | 기본 `warn`: 위반해도 전송, 경고와 집계 로그만 남김 | 1주 |
| 2 | `~/.config/lrm-hubs/slack-format.log` 를 집계해 위반이 잦은 호출처(`--tag`)부터 고침. `--kind` 없이 부르는 호출처도 `slack-sent.jsonl` 에서 `form_kind` 가 없는 기록으로 찾아 `--kind` 를 붙임 | 위반이 거의 안 남을 때까지 |
| 3 | 기본값을 `strict` 로 전환 | **사용자 승인 필요** |

집계 예:

```sh
# 규칙별 위반 건수
cut -f3 ~/.config/lrm-hubs/slack-format.log | tr ',' '\n' | grep -Ev '^(ok|bypass-no-check|bypass-off)$' | sort | uniq -c | sort -rn
# 위반이 있는 호출처(--tag)별 건수
awk -F'\t' '$3 != "ok" && $3 !~ /^bypass-/ {print $5}' ~/.config/lrm-hubs/slack-format.log | sort | uniq -c | sort -rn
# 우회(--no-check·LRM_FORMAT=off) 횟수: 위반이 아니라 검사를 건너뛴 기록이라 위 두 명령에서 뺀다
awk -F'\t' '$3 ~ /^bypass-/ {print $3}' ~/.config/lrm-hubs/slack-format.log | sort | uniq -c
```

로그 한 줄은 탭으로 나눈 5칸이다: 시각, 종류, 위반 코드(쉼표로 이은 목록, `ok`, 또는 우회 표시 `bypass-no-check`·`bypass-off`), 모드(우회는 `no-check`·`off`), `--tag` 값(없으면 `-`). 본문·제목은 기록하지 않고 파일 권한은 600이다. 로그 쓰기에 실패해도 전송에는 영향이 없다.

## 알려진 한계

- 이모지 `:비서-c:` `:비서-d:` `:비서-보류:` 가 워크스페이스에 있는지 확인하지 못했다(앱에 `emoji:read` 권한이 없음). 없으면 안내 줄에 글자로 보인다. 확인 전에는 `--emoji-set std` 를 쓴다.
- 반응 → 답 변환표(`slack_poll.sh` 의 `REACTION_ACTION`)에 표준 대체 이름(`regional_indicator_c`·`regional_indicator_d`)이 아직 없다. `--emoji-set std` 로 C·D 를 눌러도 답으로 해석되지 않는다. 표 확장은 `slack_poll.sh` 쪽 후속 작업이다.
- 줄머리 ✅ 의 `:white_check_mark:` 치환은 `--kind` 없는 호출에도 걸려 `slack-sent.jsonl` 의 `title` 값이 달라진다. `slack_pending.sh` 의 제목 중복 제거가 전환 시점에 한 번 다르게 보일 수 있다(추정, 확인 전).
- `:비서-c:` `:비서-d:` 가 있는지 확인되기 전이라 `--kind` 없는 호출의 🅲·🅳 는 치환하지 않는다. 존재를 확인하면 치환 범위를 넓힐지 정한다.
- 대기 목록(`slack_pending.sh`)은 제목에 "결정"이 든 메시지를 결정으로 본다. `--kind decide` 는 라벨 글자를 붙이지 않으므로 주제에 "결정"이 없으면 대기 목록에 안 잡힐 수 있다. 보낸 기록의 `form_kind` 로 판별하도록 바꾸는 것은 후속이다.
- 번호 검사는 숫자·영문이 섞인 7자 이상 hex 와 `LRM-숫자` 만 잡는다. `deadbeef` 같은 영문 전용, 숫자 전용, 6자 이하 짧은 해시, 다른 형식의 티켓 번호는 통과한다.
- 닫히지 않은 ``` 코드 블록 안은 제외 구간이 아니라 검사한다. 그 안의 hex 형태가 오탐일 수 있다(warn 에서는 전송되므로 허용).
- `decade2026` 처럼 영단어에 숫자가 붙은 값은 hex 로 오탐할 수 있다(허용).
- 티켓·커밋 번호 검사는 마지막 `참고:` 줄부터 끝까지를 제외하므로, `참고:` 줄이 하나뿐이고 그 뒤에 본문이 이어지면 그 본문의 번호는 검사하지 않는다(결정 개수는 `참고:` 줄 자체만 제외).
- 파일 첨부 호출은 첨부 설명글에만 이모지·검사·안내 줄이 적용된다.
- 결정 개수 판별은 휴리스틱이다. 못 잡는 것(누락): `결정` 낱말 없는 번호 제목(`1. 시각 정하기` / `2. 장소 정하기`), 답 줄 없이 쓴 다중 결정, 번호 머리가 두 자리 넘는 표기(`결정 100)`)와 로마 숫자·알파벳(`결정 A`·`결정 II`), 줄 중간에서 공백만 뒤따르는 `결정 2 …`, 접두에 이모지·`▶`·`■` 같은 다른 기호가 붙은 줄(`▶ 결정 1`), 줄바꿈으로 이어진 제목, 줄 중간에만 이어 쓴 둘째 결정(`결정 1) … 결정 2) …` 는 경고만 하고 전송), `참고:` 뒤에 이어 쓴 번호 제목. 반대로 거부하는 오탐: 번호 목록 두 줄 이상이 번호 바로 뒤에 `결정` 으로 시작하는 선택지(`1. 결정 유지` / `2. 결정 철회`), 줄 머리에서 서로 다른 번호로 시작하는 `결정 3 건` 같은 수량 표현. 거부하지 않는 쪽으로 처리한 것: 정상 1건 본문 안의 `지난주 결정 3)` 참조(경고만), 같은 번호의 반복 참조, 표 줄(`| 결정 1) | 결정 2) |`), `참고:` 블록 안의 결정 참조. 이 경우 1건씩 나누거나 `--no-check` 를 쓴다.
- 줄 구조(규칙 2, 3)와 쉬운 말·고유명사 여부는 검사하지 않는다.
- 같은 이모지를 여러 사람이 누르거나 반응을 취소하는 경우의 처리(충돌 표시, 취소 이벤트)는 아직 없다.
