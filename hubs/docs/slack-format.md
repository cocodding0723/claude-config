# Slack 메시지 고정 양식 (양식 A)

## 쉬운 말 3줄 요약

- 무엇이 바뀌었나: 봇이 보내는 메시지 모양을 하나로 고정했다. 첫 줄은 "종류 이모지 + 주제", 그 아래 무엇·왜·결과를 한 줄씩 쓴다.
- 왜: 메시지마다 모양이 달라 읽기 힘들다는 지적(11-09)이 있었다. 사용자가 "양식 A로 간다"고 확정했다.
- 사용자가 할 일: 없다. 보내는 쪽 스크립트가 `--kind` 를 붙여 부르면 `slack_notify.sh` 가 양식을 검사하고 이모지를 붙인다. 처음 1주는 어겨도 그대로 전송하고 경고만 남긴다.
- 추가(11-10): `--kind` 별 색 띠(주황·빨강·파랑·초록)와 제목 자동 굵게. 아래 「색 띠와 제목 굵게」.
- 추가(11-10): 결정 카드에 선택지를 붙이면(`--options`) 사용자는 번호 이모지(:one: :two: :three:) 하나로 고른다. ✅ 는 추천대로, ❌ 는 보류다. 아래 「이모지로 고르는 결정 카드」.
- 추가(11-12, 같은 날 경고→거부): 사용자에게 가는 문서·이미지·영상은 hub_report.py --file 로 Slack 첨부한다. 본문·참고에 .html·.png·.jpg·.gif·.mp4·.pdf 로컬 경로가 있는데 같은 파일이 첨부로 오지 않으면 접수(hub_report.py)·전송(알림 스크립트) 모두 거부(종료 코드 2). decide 보고는 문서를 --file 로 첨부해야 하고, 문서 없는 결정만 --no-doc 로 명시한다. 비밀 파일(.env·키·인증서·~/.ssh)은 첨부 거부. 결정 카드를 다른 글에서 언급할 때는 알림 스크립트 --link-to <ts> 로 그 카드 링크를 본문 끝에 넣는다. 손으로 쓴 본문에 D-번호가 있으면 `check-text` 가 slack-sent 의 가장 최근 카드를 찾아, 열려 있으면 정식 링크(chat.getPermalink)를 번호별 한 줄로 자동 첨부하고, 이미 답한 결정을 같은 줄에서 '대기·선택·눌러' 로 쓰면 경고(전송은 함)한다. 결정 카드(--kind decide) 자체는 대상이 아니다. 전송기가 파일을 본문 뒤 같은 스레드(결정 카드는 카드 스레드)에 올린다. 폴더 없는 파일명만 있는 본문은 거부하지 않고 경고만 한다. 백틱 코드·URL·`<링크>` 안의 이름은 경로로 세지 않는다. 판정은 `hub_report.py` 한 곳(`check-text`)이고, 직접 호출한 결정 카드 본문도 전송기와 같은 줄 양식(`- ` 항목, `참고:` 줄은 머리표 없이 맨 아래)으로 정리된다.

## 양식 A 규칙

| 번호 | 규칙 | 검사 | 위반 시 |
|---|---|---|---|
| 1 | 첫 줄 = 종류 이모지 + 주제. 이모지·공백 제외 40자 이내 | 자동 | 위반 `title-len` |
| 2 | 첫 줄 다음은 빈 줄 | 안 함 | - |
| 3 | `- 무엇:` `- 왜:` `- 결과:` 순서, 한 줄에 사실 하나. 한 칸에 항목이 둘 이상이면 칸 제목 아래에 항목마다 줄을 나눠 `- ` 로 시작한다. ` / ` 로 한 줄에 잇지 않는다. 가운뎃점(`·`)으로 사실을 나열하지 않는다 | 자동(11-17): ` / ` 로 이은 줄은 거부(종료 2, 모드·`--kind` 무관), 가운뎃점 나열은 경고. 판정은 `board_cards.text_gaps` 한 곳이고 알림 스크립트·`hub_report.py add` 가 부름 | 거부 `line` / 경고 `line-dot` |
| 4 | 결정·할 일이면 `👉 답: …` 줄 필수. 줄 머리의 `👉 답:` 또는 `:point_right: 답:` 만 답 줄로 친다 | 자동 (`--kind decide`·`todo`) | 위반 `no-answer` |
| 5 | 티켓·커밋 번호, 파일명은 맨 아래 `참고:` 줄에만 | 번호만 자동 (`LRM-숫자`, 숫자·영문이 섞인 7자 이상 hex) | 위반 `ticket`·`hex` |
| 6 | 굵게(`*…*`)는 본문에서 메시지당 1곳. 첫 줄(제목)은 도구가 굵게 하므로 세지 않는다 | 자동, 경고만 | 경고 `bold` |
| 7 | 결정 카드는 결정 1건 = 메시지 1개 | 자동 (`--kind decide` 만) | 거부 `multi` (모드와 무관) |
| 8 | 결정 카드는 본문 `배경:`(지금 작업·질문이 생긴 이유, 처음 보는 사람 기준 1~2줄)·`용어:`(낯선 말 풀이, 없으면 `용어: 없음`) 줄과 선택지마다 결과(`--options '1=문구 => 고르면 달라지는 점,…'`)가 있어야 한다 | 자동 (`--kind decide`, `decide_card.py` 한 곳) | 거부 종료 코드 2 (`--no-check`·`LRM_FORMAT` 으로 못 풂). `--choices` 카드는 배경·용어만 |
| 9 | Slack 에서 온 질문의 답은 그 스레드로 올린다. 하달문의 `답할 곳: Slack thread <ts>` 를 `hub_report.py add --kind info --reply-to <ts>`(`--thread` 와 같음, info·done·warn)에 넣는다. 채널 새 글 금지 | 접수 하달문에 ts 자동 기재, 스레드 지정 접수는 `hub_report.py` 가 ts 형식·종류 검사 | 거부 종료 코드 2 |

검사에서 빼는 구간: 코드 블록, 인라인 코드, URL, 마지막 `참고:` 로 시작하는 줄부터 끝까지. 첫 줄이 `참고:` 로 시작해도 제외 구간으로 보지 않는다. 답 줄(`👉 답:`) 판정도 이 구간 앞의 본문에서만 한다. 파일명·고유명사·내부 기호(규칙 3, 5 의 파일명 부분)는 기계가 판정하지 못하므로 사람이 지킨다.

## 한 줄 한 사실 검사 (규칙 3, 11-17)

본문은 항목마다 줄을 나눈다. 사용자 규칙(11-12): "/로 구분하면 분간이 안 된다". 검사기는 ` / ` 로 이은 줄을 막고, 원인과 조치를 한 줄로 알린다.

```
거부: 한 줄에 사실 여러 개가 이어짐: 3번째 줄(빗금(/)으로 사실을 이음) — 항목마다 줄을 나눠 '- ' 로 시작하세요. 예: '- 무엇: 시각 변경' 한 줄, '- 왜: 놓침 방지' 한 줄 (이 줄은 '- 무엇: A' 줄과 '- B' 줄로)
```

- 판정 한 곳: `hubs/scripts/board_cards.py` 의 `text_gaps()`. 줄 판정은 설명서 HTML 검사와 같은 `line_gaps()`. 알림 스크립트(`slack_notify.sh`)와 접수(`hub_report.py add`)가 같은 함수를 부른다.
- 기준 한 곳: 같은 파일의 `LINE_LEVEL` 블록. 위반 종류별로 `reject`(거부)·`warn`(경고)를 정한다. 오탐이 확인되면 `reject` 를 `warn` 으로 내려 시작한다.
  - ` / ` 로 이은 줄: `reject`. 11-17 최근 보고 300건 점검에서 걸린 14건이 모두 실제로 사실을 이은 줄이라 오탐이 없었다.
  - 가운뎃점 나열: `warn`. `(A·B·C)` 같은 낱말 나열과 구분이 안 돼 오탐이 남았다.
- 검사에서 빼는 것: 코드 블록·인라인 코드·URL, 짧은 따옴표 문구(`"이어하기 / 새로 시작"` 같은 화면 글자, 30자 이하), 양옆이 숫자인 분수(`2 / 3`), 표·`👉 답:` 줄·번호 선택지 줄, 마지막 `참고:` 줄부터 끝까지. 첫 줄(제목)은 알림 스크립트와 결정 보고에서 뺀다. `11/17`·`/tmp/a/b` 처럼 공백 없는 `/` 는 애초에 걸리지 않는다.
- 우회: 알림 스크립트의 `--no-check`·`LRM_FORMAT=off`. 접수(`hub_report.py add`)에는 우회가 없다. 항목을 줄로 나누면 된다.
- 자동 전송기(`report_sender.py`·`ci_watch.py`)가 만든 문구도 같은 검사를 지난다. 안내·경고 문구 자체에 ` / ` 를 쓰지 않고(거부 문구가 자기 검사에 걸려 경고가 안 나가는 일 방지), 바깥 시스템이 준 이름(GitHub 검사 이름 `Run Unity validation / Unity validation` 등)은 백틱으로 감싸 보낸다. 카드 설명에서 뽑는 부모 메시지의 `무엇`·`왜` 값은 ` / ` 에서 줄을 나눈다.
- 이 규칙으로 규칙 3 의 옛 경고 `oneline`(` / `·` · ` 3개 이상)은 없어졌다.

## 작업 스레드 안의 결정 카드와 알림 (11-18)

작업 하나의 보고·질문·결정은 그 작업 스레드 하나에 모인다. 결정 카드도 같다.

- `hub_report.py add --kind decide --card <카드> --ws <작업 공간>` 으로 올리면 결정 버튼 카드가 그 카드 스레드의 답글로 올라간다. 그 카드의 첫 보고면 스레드를 먼저 연다. `--card` 없는 결정은 지금처럼 맨 위 글이다.
- 기능 코디네이터(`feat-<slug>`)의 결정은 `--card` 를 빼먹어도 그 기능 스레드 안에 올라간다(11-19). 계획을 다시 올릴 때 카드 지정이 빠져 한 기능이 맨 위 글 여럿으로 갈라졌기 때문이다. 기능 스레드가 아직 없을 때만 맨 위 글이다.
- 예외: 작업 공간 세션이 하위 카드로 올린 결정(`--card <하위 카드> --ws`)과 기능 허브가 아닌 곳의 결정은, 기능 스레드를 같이 쓰더라도 맨 위 글로 보낸다. 같이 쓰는 스레드의 글 답은 기능 코디네이터가 받으므로, 그 결정을 넣으면 글 답이 올린 세션이 아닌 곳으로 간다. 판정은 `report_sender.in_thread` 한 곳이고 경우는 `tests/report_sender/test_feature_route.py` 의 표다.
- 사용자가 "새 메시지로 올려"라고 하면 `hub_report.py add --kind decide … --top` 으로 스레드 밖 새 메시지로 올린다(11-19). 스레드 안 카드는 DM 목록에 같이 떠도 눈에 안 띌 수 있다. `--card`·`--ws` 는 그대로 줘서 답이 올린 세션으로 가게 한다.
- 기능 스레드에 쓴 글은 기능 카드 코멘트와 기능 상자에 적힌 뒤 코디네이터 창에 한 줄 알림으로 이어진다(11-19). 그 전에는 결정 카드에 단 글만 알렸다. 기능 카드 설명에 `기능 코디네이터 허브:` 줄이 없는 옛 기능은 기록만 한다.
- 스레드 답글은 스레드를 팔로우해야 알림이 온다. 그래서 사용자가 봐야 하는 글은 DM 목록에도 함께 보이게 한다(`reply_broadcast`).

| 보고 | DM 목록에도 보이나 |
|---|---|
| 결정 카드(decide), 완료(done), 경고(warn), 차단(block) | 항상 |
| 진행(info) | `--broadcast` 를 준 것만. 확인·검수 요청처럼 사용자가 봐야 하는 글에 쓴다 |

- 규칙의 값은 `hub_report.BROADCAST_KINDS` 한 곳에 있다. 지정 스레드(`--thread`) 답글은 `--broadcast` 를 준 것만 보인다.
- 스레드 안 카드에 버튼이나 직접 입력으로 답하면 수신기가 카드 원문을 그 스레드에서 읽어 고쳐 쓴다. 원문을 못 읽으면 카드를 고치지 않고 답만 기록한다(빈 내용으로 덮어쓰면 본문이 지워진다).
- 스레드에 결정 번호로 시작하는 글(`D-xxxx 가 먼저`, `결정 D-xxxx: …`)을 쓰면 그 결정의 글 답이다. 담당 세션 상자에 `[결정 D-xxxx 답] 원문` 으로 들어가고 대기 목록의 그 카드에 `글 답 도착, 담당 확인 중` 이 붙는다. 글 답은 카드를 닫지 않는다. 담당이 읽고 `decide-answer` 로 닫는다(닫는 법은 카드 코멘트에 함께 남는다). 번호로 시작해도 질문이면 `[결정 D-xxxx 질문] 원문` 으로 가고 대기 목록에 표시하지 않는다. 번호 앞의 인용 표시(`>`), 봇 호출, 붙여 쓴 `결정`, 소문자 번호는 같은 것으로 본다. 번호가 글 중간에 있거나 번호가 없는 글은 일반 피드백이다(판정 `pending_judge.written_answer`).
- 대기 목록과 옆 패널은 스레드 안 카드도 결정으로 센다(`pending_judge.is_decision`).
- 버튼 답과 직접 입력 답도 그 결정을 올린 세션으로 바로 간다(11-18). 결정을 올린 보고에 작업 카드(`--card`)와 작업 공간(`--ws`)이 있으면 스레드 글 답과 같은 길을 탄다: 세션 상자 한 줄, 카드 코멘트, 입력창 한 줄 알림. 기능 카드로 올린 결정은 기능 코디네이터 상자로 간다. 작업 카드 없이 올린 결정만 옛 길(허브 목록 `hubs.tsv` → 메인)로 간다. 새로 연 코디네이터는 그 목록에 없으므로 결정은 `--card`·`--ws` 와 함께 올린다(`answer_route.Router.send_to`).
- 기능 코디네이터(`feat-<slug>`)가 작업 카드 없이 맨 위 글로 올린 결정도 그 코디네이터에게 간다(11-18). 허브 이름으로 그 기능의 카드와 작업 공간을 찾아 버튼 답을 전달하고, 그 카드 스레드에 쓴 글은 `[결정 D-xxxx 답]`·`[결정 D-xxxx 질문]` 머리말을 붙여 기능 상자에 넣은 뒤 코디네이터 창에 한 줄 알린다(`feedback_route.feature_session`·`route_card_reply`). 기능이 끝났거나 못 찾으면 옛 길로 간다.

## 보고 스레드 부모 메시지 양식 (카드 주제)

작업판 카드(`lrm-q5o` 같은 id)를 주제로 한 보고 스레드의 첫 메시지(부모)는 카드 내용으로 만든다. 내부 기호만 있는 부모는 보내지 않는다. 전송기(`report_sender.py`)가 만든다.

```
구조 개선: Slack 봇·작업판 정상화        ① 쉬운 이름(없으면 카드 제목)

- 무엇: …                                 ② 카드 설명의 '무엇:' 줄
- 왜: …                                   ③ 카드 설명의 '왜:' 줄
- 지금: 하위 작업 2/3 완료                ④ 하위 카드 닫힘 수 / 전체
- 답하는 법: 이 스레드에 진행·질문·결과가 올라옴. 답은 이 스레드에 달면 작업 카드로 감   ⑤

참고: lrm-q5o · 허브 structure-v2          ⑥ 카드 번호·허브 이름은 여기에만
```

- 내용 출처: `bd show <카드> --json` 의 제목·설명, `bd list --parent <카드> --all --json` 의 상태. 설명에 `쉬운 이름:`·`무엇:`·`왜:` 줄을 쓴다.
- 원료 폴백: `무엇:` 줄이 없으면 설명의 첫 문장(머리줄 `#`·`순서:` 같은 메타 줄·목록 기호·카드 번호 제외, `## 지시` 앞까지). 그래도 비면 카드 제목에서 `[impl]` 같은 머리표·카드 번호·머리말 '카드'를 뺀 것(`title_what()`). `왜:` 줄이 없으면 `원문(…): "…"` 줄의 사용자 말, 없으면 `## 지시` 칸 첫 줄. 줄이 있으면 그 줄이 먼저다.
- '왜'가 끝내 비면 보류하지 않는다. `- 왜: 카드에 이유가 안 적혀 있음 — 담당 허브가 채울 예정` 줄(`WHY_MISSING`)로 보내고, 그 보고를 낸 허브 앞으로 안내를 카드당 하루 1회 보낸다(상태 `card_warn`). 카드에 '왜:' 줄이 생기면 열린 스레드 부모가 고쳐 쓰기로 바뀐다.
- 검사: 폴백(제목 포함)으로도 `무엇`이 비면 영구 중단이 아니라 보류한다. 회차마다 카드를 다시 읽고, 고쳐지면 같은 보고가 그대로 나간다(상태 `bad` 에 넣지 않음). 보류 중에는 허브 앞으로 원인+조치 경고를 카드당 하루 1회 보낸다(같은 `card_warn`). 보류는 보고 접수 뒤 6시간(`HOLD_MAX_S`, 환경 `LRM_HOLD_MAX_S`)까지만이다. 넘으면 있는 칸만으로 보내(옛 양식) 보고가 끝없이 막히지 않는다. 조치는 카드 설명에 '무엇:'·'왜:' 줄 추가(`bd update <카드> -d ...`)이고, 추가하면 자동 전송. 판정은 `card_gaps()` 한 곳. 카드를 못 읽으면(bd 실패·없는 카드) 옛 양식으로 보내고, 읽히면 다음 보고에서 새 양식으로 고쳐 쓴다.
- 하위 카드 조회가 실패하면 `지금` 줄을 뺀다(0개와 구분).
- 고쳐 쓰기: 이미 열린 스레드 부모는 보고가 올 때마다 새 양식으로 `chat.update` 한다. 상태 `topics[주제].fmt` 에 양식 버전(`PARENT_FORMAT`)과 내용 해시를 두어 바뀐 때만 고친다(진행률이 바뀌면 갱신). 실패는 보고를 막지 않고 다음 보고에서 다시 시도한다(`message_not_found`·`cant_update_message` 는 `topics[주제].update_dead` 로 표시해 더는 시도하지 않음). 칸이 빈 카드의 열린 스레드는 고치지 않고 로그 경고만 남긴다.
- 작업 공간 스레드 수 상한(기능당 `WS_THREAD_MAX`=10)은 `--ws` 를 준 작업 공간 카드 보고에만 걸린다. `--card` 만 준 보고는 상한과 무관하게 새 스레드를 열고, 한 번 기능 스레드를 같이 쓰게 된 카드는 자리가 나도 그대로 쓴다.
- 스레드 답이 담당 세션에 닿지 못하면(입력 스위치 `.thread-wake.on` 꺼짐, 입력 막힘·입력 칸에 쓰던 글·터미널 없음이 5회 이어짐, 알림이 1시간(`WAKE_MAX_AGE_S`) 넘게 대기) 부모 기능 코디네이터 상자 `feat-<slug>` 에 답마다 "작업 공간 카드 <id> 에 Slack 답 도착, 세션에 알리지 못함(사유). 답 첫 줄: …" 한 줄(ref 에 답글 ts)을 넣고(기능이 없거나 끝났으면 확인 카드) 작업 공간 카드 코멘트에 넘긴 곳을 남긴다. 한 답글의 전달(bd 쓰기·상자 쓰기)이 3회 실패하면 확인 카드로 넘기고 다음 답글로 진행한다(상자를 먼저 쓰고 코멘트를 달아 재시도 때 코멘트가 겹치지 않는다. 본문·첨부가 없는 답글은 "(본문 없음)"). 부모로 넘기기 자체가 3회 실패하면 포기한다.
- 토큰 경로: 알림 스크립트 `slack_notify.sh --update <ts>` 가 기존 토큰·`chat.update` 로 고친다. 전송기는 토큰을 읽지 않는다.
- 작업 번호 주제(`C0012`)와 허브 주제(`hub:`)는 옛 양식(제목 + 허브 + 요청)을 유지한다. 요청이 비면 로그에 '무엇' 줄 없음 경고를 남긴다.

## 결정 1건 = 메시지 1개 (규칙 7)

한 메시지에 결정이 여러 개면 이모지 답이 어느 결정에 대한 것인지 모호하다. 그래서 `--kind decide` 본문에 결정이 둘 이상이면 보내지 않는다. 결정 개수를 검사할 수 없을 때(python3 실패)도 보내지 않는다.

- 결정 개수 판별은 보수적으로 둘 중 큰 값이다. 코드 블록·인라인 코드·URL은 세지 않는다. 마지막 `참고:` 줄 이후는 `👉 답:` 줄만 센다(그 뒤의 번호 머리·불릿 안 결정 참조는 세지 않음). 표(`|` 로 시작) 줄도 번호 판정에서 뺀다. 검사 앞에서 NFC 로 정규화하므로 조합형 한글도 같다.
  - `👉 답:` 줄(또는 `:point_right: 답:`) 개수.
  - 번호 매긴 결정 제목의 **서로 다른 번호** 개수(같은 번호 반복은 1개). 줄 머리 접두(인용 `>`, 불릿 `•`·`-`·`*`·`·`, 굵게 `**`/`*`, 머리글 `#`, 대괄호 `[`)를 허용하고 아래 둘 중 하나면 제목이다.
    - 접두 바로 뒤에 `결정` + (`-`·`#`)? + 번호. 번호는 `①`~`⑳` 또는 1~2자리 숫자(+ 선택 `번`)이고, 숫자는 뒤가 `)`·`.`·`:`·공백·굵게 끝·`]`·줄 끝일 때만 인정한다(`결정 1번:`·`### 결정 1`·`[결정 1]` 포함. 줄 머리에 있어야 해서 오탐 위험이 낮다고 보고 넣었다)(`결정 2026-11-01`·`결정 100건` 은 제외).
    - 번호 머리(`①`~`⑳`, `1.`, `1)`, `(1)`, `1번`, 키캡 `1️⃣`) **바로 뒤**의 `결정`(`1. 결정 시각`). 번호 머리 뒤 중간에 낀 `결정`(`1. 기존 결정 유지`)과 줄 중간의 `② 결정 변경` 은 선택지 문구라 세지 않는다.
    - 줄 중간의 `결정 N`(앞이 글자가 아니고, 뒤가 `)`·`.`·`:`·`*` 이거나 번호가 `①`~`⑳`)은 **세지 않고 경고만** 한다(`경고: 줄 중간에 다른 번호의 '결정 N' 이 있음`). 본문 참조(`지난주 결정 3) 과 충돌`)와 한 줄에 이어 쓴 `결정 1) … 결정 2) …` 를 구분할 수 없어서다. 이 경고는 warn·strict 모두 거부하지 않는다. 같은 번호 반복은 경고도 없다.
- 2개 이상이면 `LRM_FORMAT=warn`(기본)이어도 미전송·종료 코드 2다. `거부: 결정이 N개임(전송 안 함) — 1건씩 따로 보내세요. 예: …` 한 줄이 stderr 로 나오며, 다른 경고·위반 줄이 있어도 그 뒤 마지막 줄에 온다.
- 세지 않는 경우(오탐 방지): 결정 1건 안의 선택지 나열(`A 9시 / B 10시`, `① A안 ② B안`, `1. 기존 결정 유지` / `2. 결정 철회`), 번호 머리 뒤에 `결정` 이 바로 오지 않는 번호 목록(`1. 이미 결정된 것`), 날짜·수량(`결정 2026-11-01:`), `--choices` 가 붙이는 안내 줄(검사가 부착보다 먼저 돈다).
- 우회: `--no-check` 와 `LRM_FORMAT=off` 는 그대로 통한다(python3 실패 때도 마찬가지). 다만 `--kind decide` 일 때 집계 로그에 한 줄(`bypass-no-check` 또는 `bypass-off`, 본문 없음)을 남긴다.
- `todo`·`done`·`progress`·`warn`·`doc` 과 `--kind` 없는 호출은 영향이 없다.
- 보낼 때는 결정마다 `slack_notify.sh --kind decide` 를 따로 부른다. 분할을 대신 해 주는 `--split` 옵션은 두지 않았다.

## 이모지로 고르는 결정 카드 (`--options`)

결정 1건을 메시지 1개로 보내고, 사용자는 번호 이모지 반응 하나로 고른다. 선택지·추천·답하는 법 줄은 도구가 만든다. 호출한 쪽은 제목과 배경만 쓴다.

### 카드 모양 (가짜 내용)

```
:비서-선택해주세요: 알림 보내는 시각

• 왜: 지금은 시각이 제각각이라 놓치는 경우가 있음

:one: 오전 9시
:two: 오전 10시
:three: 정하지 않고 지금처럼
:star: 추천: :one: · 되돌리기: 쉬움
👉 답: :one: :two: :three: 중 하나 · :white_check_mark: 추천대로 · :x: 보류

참고: 결정 D-0001 · 3/9
```

| 줄 | 누가 쓰나 | 내용 |
|---|---|---|
| 제목 | 호출한 쪽 | 첫 줄. 양식 A 규칙 1(40자) 그대로 |
| 배경 | 호출한 쪽 | 한두 줄. 선택지·답 줄은 쓰지 않는다 |
| 선택지 | 도구 | `--options` 의 번호마다 `:one:`~`:four:` 한 줄. 2~4개 |
| 추천·되돌리기 | 도구 | `:star: 추천: :N:`, `--reversible` 이 있으면 ` · 되돌리기: 쉬움\|보통\|어려움` |
| 답하는 법 | 도구 | `👉 답:` 줄 1개. 이 카드의 유일한 답 줄이다 |
| 결정 번호·순번 | 도구 | 메시지 맨 끝(= `참고:` 블록 맨 끝). 마지막 `참고:` 줄 뒤에 다른 줄이 더 있으면 그 뒤에 붙는다. 본문에 `참고:` 가 없으면 `참고: 결정 D-0001 · 3/9` 줄을 새로 만든다 |

- 양식 검사(규칙 1~7)는 **호출한 쪽 본문에만** 돈다. 도구가 붙이는 줄은 검사가 끝난 뒤 붙으므로 선택지 문구에 "결정"이 들어가도 결정 개수(규칙 7)에 세지 않는다. `--choices` 안내 줄과 같은 방식이다.
- 답 줄(규칙 4)은 도구가 채우므로 `no-answer` 위반이 나지 않는다. 본문에 `👉 답:` 줄을 직접 쓰면 답 줄이 둘이 되므로 **거부한다**(종료 코드 2, `--no-check`·`LRM_FORMAT=off` 여도 거부).
- 본문 줄 머리에 `:one:`·`1️⃣` 같은 선택지 줄이 있으면 경고만 하고 보낸다(도구가 만든 선택지와 겹쳐 보임).
- 선택지 줄·추천 줄은 `참고:` 블록 앞에 들어간다. 규칙 5(번호는 `참고:` 줄에만)를 지키려고 결정 번호는 `참고:` 블록에 둔다.

### 이모지 표준표

같은 이모지라도 카드 종류에 따라 뜻이 다르다. 표에 없는 조합은 해석하지 않고 이모지 이름을 그대로 넘긴다.

| 이모지 (반응 이름) | 결정 카드 `--options` | 옛 결정 카드 (`--choices`·종류 없음) | 시안 `review` | 할 일 `todo` |
|---|---|---|---|---|
| :one: :two: :three: :four: (`one`~`four`) | 선택 N. 선택지 수보다 큰 번호는 이름 그대로 | 이름 그대로 | 이름 그대로 | 이름 그대로 |
| ✅ `white_check_mark` | 추천대로(추천 번호를 고른 것으로 봄) | 승인 `approve` | 합격 `pass` | 완료 `done` |
| ❌ `x` | 보류 `hold` | 보류 `hold` | 불합격 `fail` | 보류 `hold` |
| 🛠️ `hammer_and_wrench` | 이름 그대로 | 이름 그대로 | 이름 그대로 | 완료 `done` |
| `:비서-a:`~`:비서-d:` | 이름 그대로 | `a`~`d` | `pick_a`·`pick_b`(c·d 는 이름 그대로) | 이름 그대로 |
| `:비서-추천대로:` 등 | 이름 그대로 | `approve` | 이름 그대로 | 이름 그대로 |
| `:비서-보류:` | 이름 그대로 | `hold` | 이름 그대로 | 이름 그대로 |

- 새 카드는 사용자 결정(11-10)대로 번호 이모지(1️⃣2️⃣3️⃣)를 쓴다. 🅰️🅱️·`:비서-a:` 는 옛 카드·시안 전용으로 남겨 뜻이 섞이지 않게 했다.
- 옛 카드(`--options` 없이 보낸 것)의 해석은 바뀌지 않는다.

### 호출

```sh
slack_notify.sh --tag ui-hub --kind decide \
  --options '1=오전 9시 => 출근 전에 도착,2=오전 10시 => 업무 시작 뒤에 도착,3=지금처럼 => 시각이 계속 제각각' \
  --recommend 1 --reversible 쉬움 --decision-id D-0001 --seq 3/9 \
  $'알림 보내는 시각\n배경: 알림 개편 중, 시각이 화면마다 달라 놓치는 경우가 있어 하나로 맞추려 함\n용어: 푸시 — 앱 밖 알림\n이유: 출근 전 열람률이 높음'
```

| 인자 | 필수 | 형식 | 틀리면 |
|---|---|---|---|
| `--options` | ○ | `N=문구 => 고르면 달라지는 점` 을 쉼표로 이음(결과 칸 필수, 1~100자). 번호는 1부터 연속 2~4개, 문구 1~80자. 문구 안 쉼표는 뒤에 `숫자=` 가 오지 않으면 그대로 둔다. 두 자리 번호(`22=`)도 구분자로 보므로 범위 오류가 된다 | 종료 코드 2 |
| `--recommend` | ○ | 선택지 번호 중 하나 | 종료 코드 2 |
| `--decision-id` | ○ | `D-` + 영문·숫자 1~16자 | 종료 코드 2 |
| `--reversible` | | `쉬움`·`보통`·`어려움` | 종료 코드 2 |
| `--seq` | | `순번/전체`(예 `3/9`), 1 ≤ 순번 ≤ 전체 ≤ 999 | 종료 코드 2 |

- 카드 순서(도구가 만든다): 제목 → `배경:` → 선택지(각 `↳ 고르면:` 결과) → 추천(+본문 `이유:` 줄) → `용어:` → `👉 답:` 줄 → `참고:`. 본문 전체는 Slack 블록 상한 3000자 안이어야 하며 넘으면 미전송이다.
- `배경:`·`용어:` 줄이 없거나 결과 칸이 빈 선택지가 있으면 종료 코드 2 다. 접수 경로(`hub_report.py add`)와 직접 호출이 `decide_card.py` 한 곳의 같은 규칙을 쓴다. 옛 `1=문구,2=문구` 형식은 결과 칸이 없어 거부된다(요구가 바뀐 것이라 호환 모드를 두지 않았다).
- 다섯 인자는 `--kind decide` 에서만 쓴다. `--recommend`·`--reversible`·`--decision-id`·`--seq` 는 `--options` 와 함께만 쓴다. `--choices` 와 `--options` 는 함께 쓸 수 없다.
- 문구에 줄바꿈·제어 문자·방향 제어 문자가 있으면 거부한다. 줄바꿈이 있으면 가짜 `👉 답:` 줄이나 가짜 선택지 줄을 만들 수 있기 때문이다.
- 문구에 이모지 이름(`:two:`·`:white_check_mark:`), `👉`, ✅, ❌, 키캡 숫자(1️⃣)가 있어도 거부한다. 카드가 `:two: :two: 가짜` 처럼 보여 사용자가 답 이모지와 헷갈리기 때문이다. `10:30:00` 같은 콜론 숫자는 이모지 이름이 아니라 통과한다.
- `--thread` 와 `--options` 를 함께 주면 결정 카드가 그 스레드 안에 올라간다(11-18, 작업 하나 = 스레드 하나). 버튼과 직접 입력으로 답한다. 스레드 카드의 답 줄은 `👉 답: 아래 버튼으로 고르기` 다. 스레드 답글의 이모지 반응은 수집되지 않는다(DM 목록에도 보이게 올린 카드는 채널 이력에 나와 반응이 잡히지만, 안내는 버튼 하나로 맞춘다). 옛 `--choices` 카드는 스레드에서 답을 받을 길이 없다.
- 같은 `--decision-id` 로 최근 7일 안에 보낸 카드가 있으면 경고 1줄을 내고 보낸다(막지 않음: 재전송일 수 있다). 두 카드의 답이 메인 전달문 `결정 D-0001 = …` 에서 구분되지 않기 때문이다. 폴러·대기 목록은 메시지(`parent_ts`)로 구분하므로 답이 섞이지는 않는다.
- `--decision-id` 를 필수로 둔 이유: 한 허브가 같은 `--tag` 로 결정을 여러 개 보내므로 태그에서 만든 번호는 겹친다. 번호가 겹치면 답이 다른 결정에 붙는다. 이것이 가장 나쁜 실패라 추정하지 않고 거부한다.


## 결정 카드 답의 메인 전달 문구 (11-12)

버튼·스레드 글·반응이 모두 같은 머리 `결정 D-xxxx = …` 로 메인에 간다.

| 답 | 메인 전달 문구 |
|---|---|
| 버튼 | `[Slack→메인] 결정 D-xxxx = 선택 N(문구) (버튼)` |
| 버튼 '직접 입력' | `[Slack→메인] 결정 D-xxxx 답(자유 글): 원문` |
| 스레드 글 `A`·`🅰️`·`1`·`:one:`·`2번` | 배치 줄 `→ 결정 D-xxxx = 선택 N(문구) (스레드 글)` |
| 스레드 글 `추천`·`전부 추천`·`추천대로` | 배치 줄 `→ 결정 D-xxxx = 추천대로(선택 N) (스레드 글)` |
| 그 밖의 스레드 글(질문·의견·선택지 밖 번호) | 배치 줄 `→ 결정 D-xxxx 답(자유 글)` + 원문 인용 |
| 이모지 반응 | 기존 그대로 `결정 D-xxxx = 선택 N(문구)` |

- 글 **전체**가 선택 표기 하나일 때만 선택으로 본다. `1. 좌에서 우로…` 처럼 긴 글의 머리 숫자는 자유 글이다.
- 알파벳은 선택지 번호 순서다(A=1, B=2). 선택지 수를 넘는 번호·글자는 자유 글이다.
- 옵션 기록이 없는 옛 카드(`--options` 없이 보낸 것)의 스레드 글은 해석하지 않고 기존 전달문 그대로다.
- `--kind decide` 를 `--options` 없이 보내면 stderr 에 `선택지 버튼 없음` 경고가 나온다(전송은 한다). 끄려면 `LRM_BTN_WARN=off`.

## 할 일 카드 (`--kind todo --todo-id`)

- `--todo-id T-xxxx`(`T-` + 영문·숫자 1~16자)는 `--kind todo` 에서만 쓴다. 주면 보낸 기록에 `todo_id` 가 남는다.
- `--todo-id` 가 있으면 `참고:` 블록 끝에 `할 일 T-xxxx` 를 붙이고, 본문에 `👉 답:` 줄이 없을 때만 `👉 답: 끝나면 :white_check_mark: (또는 :hammer_and_wrench:) · 보류는 :x:` 줄도 붙인다. `--todo-id` 가 없으면 기존 동작 그대로다.
- 반응 해석: ✅·🛠️ 는 완료, ❌ 는 보류, 그 밖은 이름 그대로다(`slack-reactions.md`).
- `--kind todo` 는 본문의 ✅·❌ 글자를 줄 중간이어도 `:white_check_mark:`·`:x:` 로 바꾼다(`--todo-id` 유무와 무관). 카드가 시키는 대로 그 이모지를 누르면 완료·보류로 읽히게 하려는 것이다. 다른 `--kind` 의 줄 중간 ✅·❌ 는 전처럼 `:비서-추천대로:`·`:비서-보류:` 이다.
- `--todo-id` 카드는 `--thread` 와 함께 쓸 수 없다(반응으로만 답하는데 스레드 답글의 반응은 수집되지 않는다).
- 이 변경 전에 보낸 `--kind todo` 카드(`form_kind=todo`)도 반응을 읽을 때 ✅ 가 `approve` 가 아니라 `done` 으로 바뀐다. 메인에는 이모지 이름이 함께 넘어가 읽을 수 있다. 그 카드 본문에 줄 중간 ✅ 글자가 있었다면 `:비서-추천대로:` 로 나갔으므로 이름 그대로 전달된다.

## 색 띠와 제목 굵게 (11-10)

`--kind` 를 주면 본문을 Slack attachment 에 담아 종류별 색 띠 안에 보여 준다. 보고(진행·완료·문서)와 확인할 일(결정·할 일·문제)을 색으로 구분하려는 것이다.

| `--kind` | 색 | 코드 |
|---|---|---|
| `decide`·`todo` | 주황 | `#F2994A` |
| `warn` | 빨강 | `#EB5757` |
| `progress` | 파랑 | `#2F80ED` |
| `done`·`doc` | 초록 | `#27AE60` |

- 색 값은 `slack_notify.sh` 의 `KIND_COLOR` 한 곳에만 있다. 색을 바꾸려면 거기만 고친다.
- 첫 줄(제목)은 자동으로 `*굵게*` 된다. 첫 줄에 `*` 가 이미 있으면 그대로 둔다(중복 방지).
- 굵게 검사(규칙 6)는 첫 줄을 빼고 센다. 제목을 직접 굵게 써도 본문 굵게 1곳과 함께 경고가 나지 않는다.
- 알림 미리보기용 `text`·`fallback` 에는 제목(별표 없이)만 넣는다.
- `--kind` 가 없는 호출은 색 띠도 굵게도 없이 전과 같다.
- 한계:
  - 파일 첨부 호출은 Slack 의 파일 업로드 API 가 attachment 를 받지 않아 색 띠가 없다(설명글만 간다).
  - `text` 와 attachment 를 함께 보내면 Slack 이 제목을 색 띠 위에 한 번 더 보여 줄 수 있다. 실제 화면은 아직 확인하지 않았다. 겹쳐 보이면 `text` 를 비우고 `fallback` 만 두는 한 줄 수정으로 푼다.
  - 대기 목록(`slack_pending.sh`)이 답한 카드를 고칠 때 `text` 만 보낸다. 색 띠 본문이 그대로 남는지는 확인하지 않았다.
  - 대기 목록이 이력에 남기는 원문(`original_text`)은 `text`, 곧 제목뿐이다. 반응 수집(`slack_poll.sh`)은 메시지 `ts` 로 찾으므로 영향이 없다.

## 종류별 이모지

| `--kind` | 뜻 | 유니코드 | Slack 에 보이는 이름 |
|---|---|---|---|
| `decide` | 결정 필요 | 🙋 | `:비서-선택해주세요:` |
| `todo` | 직접 할 일 | 🛠️ | 🛠️ (치환 없음) |
| `done` | 완료 | ✅ | `:white_check_mark:` (줄머리 ✅ 는 완료 표시라 표준 ✅ 로 둠) |
| `progress` | 진행 중 | 🔄 | `:비서-진행중:` |
| `warn` | 문제·주의 | ⚠️ | `:비서-긴급:` |
| `doc` | 문서 | 📄 | `:비서-공유합니다:` |

- 첫 줄에 6종 중 하나가 이미 있으면(유니코드 또는 위 이름) 다시 붙이지 않는다.
- 라벨 글자("결정 필요:")는 붙이지 않는다. 이모지만 붙고 주제는 호출한 쪽이 쓴 그대로 간다.
- ✅ 는 위치로 뜻이 갈린다. 줄 머리(앞 공백이나 `•` 불릿 뒤 포함)의 ✅ 는 완료 표시라 `:white_check_mark:` 로, 줄 중간의 ✅ 는 반응 선택지라 `:비서-추천대로:` 로 바뀐다. `-`·`*` 불릿 뒤 ✅ 는 넓히지 않아 `:비서-추천대로:` 가 된다. `--kind` 가 없는 호출에도 적용한다(아래 호출 방법의 예외).

## 렌더 예시 (가짜 내용)

결정 필요:

```
🙋 알림 보내는 시각

• 무엇: 아침 알림을 몇 시에 보낼지 정해야 함
• 왜: 지금은 시각이 제각각이라 놓치는 경우가 있음
• 결과: 정하면 다음 날부터 같은 시각에 도착

👉 답: :비서-a: A · :비서-b: B · :비서-c: C · :비서-추천대로: 추천대로 · :비서-보류: 보류

참고: 샘플-123
```

완료:

```
✅ 알림 시각 통일

• 무엇: 모든 알림을 오전 9시로 맞춤
• 결과: 내일부터 한 번에 도착

참고: 샘플-123
```

문제:

```
⚠️ 알림 하나가 안 나감

• 무엇: 어제 저녁 알림 1건이 전송되지 않음
• 왜: 연결이 잠시 끊긴 것으로 보임
• 결과: 다시 보내 두었고 오늘은 정상

👉 답: 확인만 해 주세요 (:비서-보류: 로 보류)
```

## 이모지로 답하기

결정 메시지 끝의 `👉 답:` 줄에 있는 이모지를 눌러 답한다.

| 이모지 | 뜻 | 표준 대체 이름 |
|---|---|---|
| `:비서-a:` | A | `:a:` |
| `:비서-b:` | B | `:b:` |
| `:비서-c:` | C | `:regional_indicator_c:` |
| `:비서-d:` | D | `:regional_indicator_d:` |
| `:비서-추천대로:` | 추천대로 | `:white_check_mark:` |
| `:비서-보류:` | 보류 | `:x:` |

- 선택지 수는 `--choices 2~4` 로 정한다. 줄에는 고른 수만큼만 A 부터 나열하고 추천대로·보류는 항상 붙는다.
- 기본 문구는 커스텀 이모지(`:비서-*:`)다. 커스텀 이모지가 아직 없으면 `--emoji-set std` 로 표준 이름 문구를 낼 수 있다.
- 충돌하는 기준이 하나 있다. 기준 메모리(slack-plain-language)는 결정 선택지를 2~3개로 권장하고, 이모지 답은 4개(A~D)까지 지원한다. **4개는 예외로 허용한다.** 선택지가 많을 때만 쓰고, 기본은 2~3개다.
- 같은 메시지에 반응이 여러 개면 마지막 반응이 답이다(`slack_pending.sh` 규칙).

## 호출 방법

```sh
# 완료 알림: 이모지 자동, 양식 검사
slack_notify.sh --kind done "알림 시각 통일"

# 결정 요청: 선택지 3개와 안내 줄 자동
slack_notify.sh --tag ui-hub --kind decide --choices 3 $'알림 보내는 시각\n\n• 무엇: …\n• 왜: …\n• 결과: …'

# 표준 이모지 문구
slack_notify.sh --kind decide --choices 2 --emoji-set std "…"

# 긴급해서 양식 검사를 건너뜀 (기록에 unchecked:true)
slack_notify.sh --no-check --kind warn "…"

# 결정이 2개면 거부 — 결정마다 한 번씩 따로 호출
slack_notify.sh --kind decide --choices 3 "결정 1 알림 시각 …"
slack_notify.sh --kind decide --choices 2 "결정 2 알림 문구 …"

# 이행 모드
LRM_FORMAT=strict slack_notify.sh --kind todo "…"    # 위반이면 미전송, 종료 코드 2
LRM_FORMAT=off    slack_notify.sh --kind todo "…"    # 검사 안 함
```

- `--kind` 가 없는 기존 호출은 동작·출력이 그대로이며 검사도 하지 않는다. 예외는 하나다: 줄머리 ✅ 는 `--kind` 가 없어도 `:white_check_mark:` 로 바뀐다. 본문 줄머리 ✅ 를 완료 표시로 확정한 기준(11-09)을 호출자 구분 없이 적용하려는 결정이다. 🅲·🅳 치환은 `--kind`(또는 `--choices`)가 있을 때만 하므로 `--kind` 없는 호출의 🅲·🅳 는 원문 그대로 간다.
- `--choices` 는 `--kind decide` 와 함께만 쓴다. 범위(2~4)나 조합이 틀리면 종료 코드 2.
- 본문에 `👉 답:` 줄이 이미 있으면 안내 줄을 붙이지 않는다. 마지막 `참고:` 줄이 있으면 그 앞에, 없거나 첫 줄뿐이면 맨 끝에 끼운다.
- 규칙 7(`multi`)은 위반 건수에 세지 않고 모드와 무관하게 거부한다. 그 외 위반은 warn 에서 전송한다.
- 검사 결과는 stderr 로 나온다: warn 은 `경고: …` 줄과 마지막 `양식 위반 N건(전송함)`, strict 는 `거부: …` 줄과 `양식 위반 N건(전송 안 함)`.
- python3 실행이 실패하면 `--kind decide` 는 모드와 무관하게 미전송·종료 코드 2다(로그 코드 `check-fail`). 다른 kind 는 warn 이 `양식 검사 실패 — 검사 없이 전송` 한 줄을 남기고 보내며, strict 는 미전송·종료 코드 2다. 안내 줄 부착이 실패해도 같다(warn 은 안내 줄 없이 전송). strict 의 python 실패는 decide 가 아닌 kind 에서도 로그에 `check-fail` 한 줄을 남긴다.

## 이행 단계

| 단계 | 내용 | 기준 |
|---|---|---|
| 1 | 기본 `warn`: 위반해도 전송, 경고와 집계 로그만 남김 | 1주 |
| 2 | `~/.config/lrm-hubs/slack-format.log` 를 집계해 위반이 잦은 호출처(`--tag`)부터 고침. `--kind` 없이 부르는 호출처도 `slack-sent.jsonl` 에서 `form_kind` 가 없는 기록으로 찾아 `--kind` 를 붙임 | 위반이 거의 안 남을 때까지 |
| 3 | 기본값을 `strict` 로 전환 | **사용자 승인 필요** |

집계 예:

```sh
# 규칙별 위반 건수
cut -f3 ~/.config/lrm-hubs/slack-format.log | tr ',' '\n' | grep -Ev '^(ok|bypass-no-check|bypass-off)$' | sort | uniq -c | sort -rn
# 위반이 있는 호출처(--tag)별 건수
awk -F'\t' '$3 != "ok" && $3 !~ /^bypass-/ {print $5}' ~/.config/lrm-hubs/slack-format.log | sort | uniq -c | sort -rn
# 우회(--no-check·LRM_FORMAT=off) 횟수: 위반이 아니라 검사를 건너뛴 기록이라 위 두 명령에서 뺀다
awk -F'\t' '$3 ~ /^bypass-/ {print $3}' ~/.config/lrm-hubs/slack-format.log | sort | uniq -c
```

로그 한 줄은 탭으로 나눈 5칸이다: 시각, 종류, 위반 코드(쉼표로 이은 목록, `ok`, 또는 우회 표시 `bypass-no-check`·`bypass-off`), 모드(우회는 `no-check`·`off`), `--tag` 값(없으면 `-`). 본문·제목은 기록하지 않고 파일 권한은 600이다. 로그 쓰기에 실패해도 전송에는 영향이 없다.

## 알려진 한계

- 이모지 `:비서-c:` `:비서-d:` `:비서-보류:` 가 워크스페이스에 있는지 확인하지 못했다(앱에 `emoji:read` 권한이 없음). 없으면 안내 줄에 글자로 보인다. 확인 전에는 `--emoji-set std` 를 쓴다.
- 반응 → 답 변환표(`slack_poll.sh` 의 `REACTION_ACTION`)에 표준 대체 이름(`regional_indicator_c`·`regional_indicator_d`)이 아직 없다. `--emoji-set std` 로 C·D 를 눌러도 답으로 해석되지 않는다. 표 확장은 `slack_poll.sh` 쪽 후속 작업이다.
- 줄머리 ✅ 의 `:white_check_mark:` 치환은 `--kind` 없는 호출에도 걸려 `slack-sent.jsonl` 의 `title` 값이 달라진다. `slack_pending.sh` 의 제목 중복 제거가 전환 시점에 한 번 다르게 보일 수 있다(추정, 확인 전).
- `:비서-c:` `:비서-d:` 가 있는지 확인되기 전이라 `--kind` 없는 호출의 🅲·🅳 는 치환하지 않는다. 존재를 확인하면 치환 범위를 넓힐지 정한다.
- 대기 목록(`slack_pending.sh`)은 제목에 "결정"이 든 메시지를 결정으로 본다. `--kind decide` 는 라벨 글자를 붙이지 않으므로 주제에 "결정"이 없으면 대기 목록에 안 잡힐 수 있다. 번호 카드(`--options`)는 보낸 기록으로 판별해 제목과 무관하게 잡는다. `--options` 없는 `--kind decide` 를 `form_kind` 로 판별하도록 바꾸는 것은 후속이다.
- 번호 검사는 숫자·영문이 섞인 7자 이상 hex 와 `LRM-숫자` 만 잡는다. `deadbeef` 같은 영문 전용, 숫자 전용, 6자 이하 짧은 해시, 다른 형식의 티켓 번호는 통과한다.
- 닫히지 않은 ``` 코드 블록 안은 제외 구간이 아니라 검사한다. 그 안의 hex 형태가 오탐일 수 있다(warn 에서는 전송되므로 허용).
- `decade2026` 처럼 영단어에 숫자가 붙은 값은 hex 로 오탐할 수 있다(허용).
- 티켓·커밋 번호 검사는 마지막 `참고:` 줄부터 끝까지를 제외하므로, `참고:` 줄이 하나뿐이고 그 뒤에 본문이 이어지면 그 본문의 번호는 검사하지 않는다(결정 개수는 `참고:` 줄 자체만 제외).
- 파일 첨부 호출은 첨부 설명글에만 이모지·검사·안내 줄이 적용된다.
- 결정 개수 판별은 휴리스틱이다. 못 잡는 것(누락): `결정` 낱말 없는 번호 제목(`1. 시각 정하기` / `2. 장소 정하기`), 답 줄 없이 쓴 다중 결정, 번호 머리가 두 자리 넘는 표기(`결정 100)`)와 로마 숫자·알파벳(`결정 A`·`결정 II`), 줄 중간에서 공백만 뒤따르는 `결정 2 …`, 접두에 이모지·`▶`·`■` 같은 다른 기호가 붙은 줄(`▶ 결정 1`), 줄바꿈으로 이어진 제목, 줄 중간에만 이어 쓴 둘째 결정(`결정 1) … 결정 2) …` 는 경고만 하고 전송), `참고:` 뒤에 이어 쓴 번호 제목. 반대로 거부하는 오탐: 번호 목록 두 줄 이상이 번호 바로 뒤에 `결정` 으로 시작하는 선택지(`1. 결정 유지` / `2. 결정 철회`), 줄 머리에서 서로 다른 번호로 시작하는 `결정 3 건` 같은 수량 표현. 거부하지 않는 쪽으로 처리한 것: 정상 1건 본문 안의 `지난주 결정 3)` 참조(경고만), 같은 번호의 반복 참조, 표 줄(`| 결정 1) | 결정 2) |`), `참고:` 블록 안의 결정 참조. 이 경우 1건씩 나누거나 `--no-check` 를 쓴다.
- 줄 구조(규칙 2, 3)와 쉬운 말·고유명사 여부는 검사하지 않는다.
- 반응 취소 이벤트는 보지 않는다. 번호 카드에서 답이 갈리면 충돌로 표시하고(`slack-reactions.md` 「번호 카드·할 일 카드」) 옛 카드는 전처럼 두 줄 모두 전달한다.
- 번호 이모지의 실제 반응 이름(`one`~`four`)은 실제 Slack 에서 확인하지 않았다. 이름이 다르면 해석하지 않고 이름 그대로 넘어간다.
- 결정 원장 파일은 없다. 결정 번호는 보낸 기록(`slack-sent.jsonl`)과 inbox 를 잇는 데만 쓴다.
- 파일을 첨부한 번호 카드(`--options` + 파일, 11-12 변경)는 버튼 카드를 먼저 `chat.postMessage` 로 올리고 파일을 그 스레드에 붙인다(첨부 메시지에는 버튼 블록을 달 수 없다). 카드가 최상위 메시지라 `ts` 가 기록되어 대기 목록·닫기 대상에 잡힌다. 파일 기록은 카드 필드 없이 따로 남는다.
- 본문에 쓴 ✅ 글자가 `:비서-추천대로:` 로 바뀌는 것은 번호 카드도 같다. 그 이모지를 누르면 번호 카드에서는 해석하지 않고 이름 그대로 넘어간다(추천대로는 도구가 만든 답 줄의 `:white_check_mark:` 이다).
