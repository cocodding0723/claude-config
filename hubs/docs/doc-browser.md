# 문서 모아보기 (로컬 페이지)

주소: http://127.0.0.1:17420/ (내 컴퓨터에서만 열림). launchd 가 상시 실행함(`ai.lrm.docbrowser`).

## 하는 일

- 정리기록·hub-inbox·작업 공간 `docs/out` 의 html 을 최신순으로 모음. 허브 필터, 제목 검색, 도식 유무·답 상태·보냄 필터.
- 문서마다 결정 번호(D-…)와 답 상태(대기·답함·보류·충돌)를 표시함. 출처는 `slack-sent.jsonl`(첨부 기록)과 `slack-inbox.jsonl`(버튼·반응 답).
- 도식 썸네일 또는 '도식 없음' 표시. 판정은 doc-kit `check.py --json`(`diagram_info`)을 그대로 씀. 검사기가 옛 버전이면 '판정 불가'.
- 행 클릭 시 페이지 안에서 열람(스크립트·외부 요청 없는 격리 창).
- [보내기] → 받는 사람 선택 → 메시지(제목·핵심 3줄 초안, 수정 가능) → 확인 후 전송 → 봇이 그 사람 DM 에 파일과 메시지를 보냄. 기록은 `doc-sent.jsonl`.
- 결정 번호(D-…) 칩을 누르면 선택지가 뜸. 선택 → 서버가 만든 전달 문구 확인 → [이 답으로 전달] 순서이고, 결정을 올린 허브 코디네이터에 `사용자 원문: … (출처: 문서 사이트)` 로 직접 전달함(실패하면 메인에 대리 전달, 허브 기록이 없으면 메인으로). 기록은 Slack 버튼과 같은 지점(`answer_store`)에 남고, 먼저 온 답만 인정함. 감사 로그: `docsite-audit.jsonl`.

## 확인 목록 사용법 (첫 화면)

사용자가 확인할 것(결정·PR 병합·검수·직접 실행 명령·시트 작업·창 승인)을 한 목록에 모음. 줄마다 바로 처리함. 안 함이 위, 함은 아래.

| 종류 | 누르는 것 | 일어나는 일 |
|---|---|---|
| 결정 카드 | 답하기 → 선택 → [이 답으로 전달] | 선택 문구를 서버가 만들어 담당 허브에 `사용자 원문` 으로 전달. 먼저 온 답만 인정 |
| 검수·명령·시트·창 승인 | 했음 | 확인 기록 + 담당 허브에 `확인 완료: …` 한 줄. 허브를 모르면 메인으로 |
| PR 병합 | 병합 승인 | Mac 에 확인 창이 뜸(승인·취소, 60초). 승인하면 그 시점 PR 헤드 커밋과 함께 기록 + 담당 허브에 `PR 저장소#번호 병합 승인(헤드 abc1234) — 헤드가 같을 때만 병합, 다르면 다시 승인 요청` 전달. 취소·시간 초과면 아무것도 안 함 |

- **문서 사이트 병합 승인 = 그 PR(기록된 헤드 커밋)에 대한 사용자 승인 기록.** 병합 실행 주체는 기존 규칙 그대로(사용자 직접 병합 대상은 계속 사용자가 함). 병합 승인 버튼은 병합·`gh pr merge`·push 를 실행하지 않음. 헤드가 바뀌면 승인 무효.
- 승인했지만 아직 병합 안 된 PR 은 목록에서 `승인함·병합 대기` 로 표시하고 안 함에 둠. 병합되면 함으로 넘어감. 승인 뒤 헤드가 바뀌면 `승인 낡음 — 새 커밋` 으로 안 함에 두고 다시 승인받음. 병합 없이 닫히면 함으로 넘기되 `승인 무효(미병합 닫힘)` 로 표시하며, 다시 열려도 옛 승인은 되살리지 않음.
- 승인 기록은 `pr-approve.jsonl`(종류 pr-approve, 먼저 온 것만), 전달 결과는 `answer-delivery.jsonl`, 누른 기록은 `docsite-audit.jsonl`. 전달이 실패했으면 같은 버튼을 다시 누를 때 1회만 재전달함.
- 확인 창은 서버 프로세스(launchd)가 띄움. 화면 잠금·로그아웃 상태면 창을 못 띄워 승인이 거부됨(기록·전달 없음).

## 처음 한 번 해야 할 일

1. 받는 사람 설정: `~/.config/lrm-hubs/doc-recipients.json` 의 `slack_id` 를 채움(예시는 `doc-recipients.example.json`). ID 는 저장소에 올리지 않음.
2. 폴더 접근 권한: 시스템 설정 → 개인정보 보호 및 보안 → 전체 디스크 접근 권한(또는 파일 및 폴더)에서 launchd 가 쓰는 python3 허용. 정리기록 폴더가 `~/Documents` 안이라 이 권한이 없으면 그 폴더 문서가 목록에서 빠짐.
3. 적재: `bash install.sh --reload-launchd` 또는 `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/ai.lrm.docbrowser.plist`.

## 보안 규칙

- 바인드는 코드 상수 `HOST=127.0.0.1` 고정(설정·환경 변수로 못 바꿈). Host 헤더가 127.0.0.1·localhost 가 아니면 403.
- 보내기는 `POST /api/send` 한 곳. Origin 이 서버 주소가 아니거나 없으면, `Sec-Fetch-Site` 가 same-origin 이 아니면, `X-CSRF-Token` 이 페이지 열 때 발급한 값과 다르면 403.
- 결정 답은 `POST /api/decide`. 같은 Origin·Sec-Fetch-Site·토큰 검사를 거치고, 요청에는 결정 번호·선택 번호·intent 만 허용(그 밖의 키는 400). 문구는 서버가 카드 기록에서 조립하며, 확인 단계(preview)가 발급한 1회용 intent(120초, 페이지 토큰에 묶임)가 있어야 전달함. 이미 답한 결정·감시기 카드는 거부.
- PR 병합 승인은 `POST /api/approve`. 같은 Origin·Sec-Fetch-Site·토큰 검사를 거치고 요청에는 항목 키 하나만 허용. 서버가 확인 목록의 열린 PR 줄인지 확인한 뒤 macOS 확인 창(`osascript`, 문구는 argv 로 전달)을 띄우고, '승인'일 때만 기록·전달함. 닫힌 PR·목록에 없는 키는 거부. 확인 창 전·후로 PR 을 재조회해 닫힘·헤드 변경이면 기록 없이 거부.
- 전송 함수(`doc_send.send`)·결정 처리(`doc_decide.Decider.handle`)를 부르는 곳은 서버의 POST 처리기뿐. 명령줄 진입점·자동 호출 경로 없음. 허브·스크립트는 보내기를 호출할 수 없음.
- 문서는 수집된 id 로만 엶. 경로를 받지 않음. 비밀 파일(.env·키·인증서)은 첨부 단계에서 한 번 더 거부함.
- `slack_notify.sh --to-user` 는 `doc-recipients.json` 에 등록된 ID 만 허용함.

## 문제 해결

| 증상 | 원인·조치 |
|---|---|
| 정리기록 문서가 목록에 없음 | python3 폴더 접근 권한 없음. 위 2번 |
| 보내기 창에서 'Slack ID 미설정' | `doc-recipients.json` 의 `slack_id` 비어 있음 |
| '보안 토큰 없음·만료' | 페이지를 새로 고침(토큰은 페이지를 열 때마다 발급, 12시간 유효) |
| 결정 답이 '확인 단계가 없거나 만료됨' | 선택부터 다시(확인은 120초 유효, 페이지 하나에서만 유효) |
| 결정 답이 '답은 기록했지만 전달 결과가 확실하지 않음' | 허브 전송 시간 초과 또는 메인 대리 전달 실패. 허브·메인에 직접 알림(재전송은 중복 위험이라 하지 않음) |
| 병합 승인이 '확인 창을 띄우지 못함' | 서버가 화면 세션 밖에서 돌거나 화면이 잠김. Mac 을 잠금 해제한 뒤 다시 누름 |
| 병합 승인이 '승인은 기록했지만 담당에게 전달하지 못함' | 같은 버튼을 다시 누르면 1회 재전달(확인 창 없음). 그래도 실패면 허브·메인에 직접 알림 |
| 접속 안 됨 | `tail ~/.config/lrm-hubs/doc-browser.log`. 포트 충돌이면 `LRM_DOC_PORT` 로 바꾸고 plist 에 환경 변수 추가 |

구조·결정 근거: `docs/out/doc-browser/doc-browser.html`.
