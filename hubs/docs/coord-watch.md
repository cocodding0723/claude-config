# 멈춘 코디네이터 깨우기 (coord_watch)

## 쉬운 말 3줄 요약

- 무엇이 생겼나: 이어갈 일이 있는데 20분 넘게 쉬는 기능 코디네이터 창에 이어서 하라는 한 줄을 보낸다. 두 번 깨워도 멈춰 있으면 그 기능 스레드에 경고 1건을 올린다.
- 왜: 코디네이터는 사용자 글, Slack 답, 작업자 알림이 있어야 움직인다. 알림을 한 번 놓치면 아무도 깨우지 않아 몇 시간씩 멈췄다(11-25 기능 21개 중 14개). `stall_watch` 는 작업자만 본다.
- 사용자가 할 일: 경고가 오면 그 기능 창을 연다. 깨우는 줄은 승인이 아니라서 계획 승인·PR·병합은 그대로 사용자가 정한다.

## 깨우지 않는 경우

| 구분 | 조건 |
|---|---|
| 작업 중 | 세션이 응답 중이거나 백그라운드 명령을 돌린다 |
| 작업자 대기 | 그 허브의 작업자가 최근 30분 안에 관찰됐다. 응답 없는 작업자는 `stall_watch` 가 알린다 |
| 사용자 차례 | 답을 기다리는 결정 카드가 있다, 접수·검수·반영 단계다, 모아 검수를 기다리는 작은 기능이다 |
| 오래 쉼 | 하루 넘게 대화가 없다. 남은 작업은 `work_remind` 가 알린다 |
| 창 여럿 | 같은 기능 창이 둘 이상이다. 맡은 창을 고를 수 없어 깨우지 않고 경고만 올린다 |
| 조용한 시간 | 22시~8시 |

- 쉰 시각은 세션 기록의 대화 시각으로 본다. 터미널의 마지막 출력 시각은 화면 갱신만으로 바뀌어 쓰지 않는다.
- 깨우는 횟수는 쉼 한 번에 2회, 한 회차에 창 3개까지다. 새 입력(사용자 글, Slack 답, 작업자 메시지)이 오면 처음부터 센다. 자기 백그라운드 명령의 끝 알림은 새 입력으로 세지 않는다.
- 질문을 창에만 적고 멈춘 코디네이터도 깨운다. 깨우는 줄이 결정 카드로 올리라고 알린다.

## 확인·끄기

```sh
python3 ~/.config/lrm-hubs/coord_watch.py check --dry-run   # 보내지 않고 판정만 출력
bash tests/coord_watch/run.sh
```

- `ai.lrm.slacksocket` 의 감시 루프(120초)에서 돈다. 병합·설치 뒤 `launchctl kickstart -k gui/$(id -u)/ai.lrm.slacksocket` 으로 다시 띄워야 적용된다.
- 이 감시만 끄기: `slack_socket.py` 의 `WATCHERS` 에서 `coord_watch.py` 삭제.
- 기준 바꾸기: `LRM_COORD_IDLE_MIN`(20), `LRM_COORD_GAP_MIN`(20), `LRM_COORD_MAX_AGE_MIN`(1440), `LRM_COORD_WAKE_MAX`(2), `LRM_COORD_PER_RUN`(3), `LRM_COORD_QUIET`(22-8, `off` 면 끔).

## 범위 밖

- Slack 발송이 거부됐다는 통보와 이미 샌 답의 재전달: Slack 보고 전송 문제 정리(lrm-hugd)가 맡는다.
- PR 병합 뒤 마무리: `board_sweep` 의 `feature_merged` 가 맡는다.
- 빈 검수 창(지시가 입력되지 않은 Codex 창): 따로 감지하지 않는다. 깨우는 줄이 기다리는 창이 실제로 시작됐는지 확인하라고 알린다.
