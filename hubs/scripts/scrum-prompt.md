## 쓸 것
`# {{NAME}}` 칸 하나. 읽는 사람은 기획·아트·시나리오 담당까지다. 회의에서 이 칸만 보고 **무엇이 달라졌고, 왜였고, 어디서 볼 수 있는지** 알 수 있어야 한다.
- 맨 위 줄은 `# {{NAME}}`, 빈 줄, 그 아래 불릿만. 표·번호 목록·이미지·코드 블록 없음(시트 칸 이름·명령어는 백틱 허용).
- **주제는 티켓 묶음이 아니라 기능·화면 하나**다. `상점·오토마 화면`, `데이터·빌드` 같은 분류 이름으로 묶지 않는다.
- 최상위 불릿: `**화면에서 일어난 일**` + `([LRM-n](링크))` + 진행 중이면 `· 진행 중`. 고친 문제는 `~던 문제`, 바꾼 것은 `~로 바꿈` 으로 쓴다.
    - 좋음: `**매점의 '라이벌 보기' 버튼을 왼쪽 아래로 옮김** ([LRM-n](링크))`
    - 나쁨: `**연출·사운드** (진행 중)`
- 하위 불릿은 1단계만, 4칸 들여쓰기. 3단계 금지. 중요한 주제는 2~4줄로 풀고 아래 순서에서 해당하는 것만 쓴다(머리말 `원인:`·`수정:` 은 안 붙여도 된다).
    1. 전에는 어땠나: 플레이어·작가 눈에 보이던 증상. 제보자가 재료에 있으면 `(○○님 제보)`
    2. 왜였나: 원인 한 줄. 클래스·함수 이름 대신 말로 푼다
    3. 지금은 어떤가: 바뀐 동작. 수치는 `0.1초 → 0.4초` 처럼 전후로
    4. 어디서 보나: `데브 0.1.31 (292)부터`, `앱을 다시 켜면 보임`, `dev 반영, 다음 빌드부터`. 빌드 번호는 재료에 있을 때만
    5. 확인한 것: 무엇을 몇 번 돌려 봤는지. 못 봤으면 `실제 기기 확인 남음`
- 진행 중인 주제는 3 자리에 끝난 것과 남은 것, 그리고 `오늘: …` 한 줄을 쓴다. 시안 결정은 고른 안과 이유를 한 줄로 쓴다.
- 팀원이 쓰게 될 기능(편집 화면·시트 칸·명령)은 쓰는 법을 쓰고, 안 되는 것은 `아직 안 되는 것: …` 으로 남긴다.
- 다른 담당의 확인이 필요하면 `○○님 확인 부탁: …`. 이름·요청이 재료에 있을 때만.
- 막힌 주제는 `막힘: … — 풀어 줄 사람`. 근거가 없으면 `확인 필요`.
- 작은 수정은 풀지 않고 최상위 `**그 밖에 반영됨**` 아래 `바뀐 것 ([LRM-n](링크))` 한 줄씩 모은다. 화면 변화가 없는 내부 정리도 여기 둔다.
- 순서: 화면에서 달라진 것·팀이 바로 쓸 것 → 진행 중 → 그 밖에 반영됨.
- PR 번호·검사 상태·커밋·검수 과정은 쓰지 않는다. 티켓 링크로 충분하다. 검사 실패가 일을 막고 있을 때만 `막힘` 으로 쓴다.
- 문장은 `~함`·명사형, 마침표 없음. 한 줄 90자 이내(링크 주소 제외), 한 줄에 사실 하나.
- `hub_progress` 의 갈래 이름(영문 슬러그)은 쓰지 않는다. 같은 일이 여러 갈래에 나오면 한 주제로 합친다.
- 마지막 불릿은 `**막힌 것**: 없음`. 막힌 근거가 재료에 있으면 그 내용을 적는다.
- 재료에 `attachments`(화면·영상 파일)가 있을 때만: 코드가 스레드에 따로 올린다. 본문에 파일 경로·이름을 쓰지 않는다. `attachments` 가 없으면 영상·화면 첨부를 언급하지 않는다. 어떤 주제의 화면·영상이면 `영상 첨부`·`화면 첨부` 라고만 하위 불릿에 적어도 된다.
- `**팀 공유 사항**` 칸은 코드가 설정 파일에서 맨 앞에 넣는다. 쓰지 않는다.
- 연출(트윈·애니메이션) 강도에 대한 의견·피드백은 담당 갈래가 따로 받으므로 초안에 쓰지 않는다. 구현·진행 사실만 쓴다.
- 개발 용어는 풀어 쓴다. 허브·워커·묶음 번호·결정 번호 같은 로컬 작업 용어와 AI 흔적은 쓰지 않는다.
- 전체 {{MAX_LINES}}줄 이하. 최상위 불릿 4~10개. 넘치면 작은 주제부터 `그 밖에 반영됨` 으로 내린다.
- 어제 칸의 항목은 상태를 이어 쓴다. 병합됐으면 `dev 반영` 으로 쓰고 새 일을 올린다. 어제와 달라진 것이 없는 항목은 되풀이하지 않는다.

## 지킬 것
- 근거가 없는 내용은 쓰지 않는다. 오늘 할 일은 열린 PR·진행 중 Jira·HANDOFF 의 남은 일에서만 뽑는다. 확신이 없으면 `확인 필요` 를 붙인다.
- 재료·Jira·Confluence 에서 찾은 사실만 쓴다. 티켓 번호와 PR 번호를 지어내지 않는다.
- Atlassian 도구가 없거나 오류를 내면 읽은 척하지 말고 재료만으로 쓴다. 그때는 출력 맨 끝에 `{{NO_ATLASSIAN}}` 한 줄만 따로 붙인다(칸 본문에 설명을 쓰지 않는다).
- 출력은 칸 본문뿐이다. 머리말·설명·코드 펜스를 붙이지 않는다.
