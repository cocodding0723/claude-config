워크스페이스 자동 정리(11-06 사용자 지시): 내 허브 하위 워크스페이스 중 안 쓰는 것은 사용자에게 묻지 않고 스스로 정리한다. 대상 = 도는 워커·터미널 없음 + 결과를 커밋했거나 보관함 + 다른 허브가 쓰지 않음. 순서: ① 보관 rsync(gitignore 결과물 포함: TestResults/report·docs/_*·*.html·*.md·녹화) → ~/Documents/90_정리기록/workspace-archive/YYYYMMDD/<이름>/ ② 보관 폴더 파일 수 확인 ③ orca worktree rm (브랜치는 지우지 않음). 강제 삭제는 서브모듈 때문에 거부될 때만 허용(11-06 사용자 A): 본체·서브모듈 모두 미커밋 0·안 올린 커밋 0·stash 0·보관 완료를 확인한 뒤 git worktree remove --force. 미커밋 변경이 남은 곳은 지우지 말고 보관만 한 뒤 보고에 "미커밋 남음"으로 적는다. 허브 자기 워크스페이스·원격 Unity 작업 중인 것은 지우지 않는다(브랜치는 남으므로 로컬 커밋은 안전). 시점: 워커가 끝나 결과를 받은 직후 + 하루 1회 훑기. 보고는 "[허브→메인] 🧹 정리 N개(보관 경로)" 한 줄.

Jira 수정 댓글(회사 프로젝트 원칙, 11-06): Jira 티켓을 고치면 작업 브랜치 커밋 직후 그 티켓에 댓글을 단다(사용자 승인 불필요). 형식은 짧게 — 원인 1줄 / 수정 1줄 / 커밋(브랜치·해시, PR 있으면 번호) / 확인 방법 1줄. 쉬운 말로 핵심만, AI 흔적 금지. 코드 변경 없이 닫는 경우(기획 반영·중복·재현 안 됨)도 이유를 댓글로 남긴다. 댓글을 단 뒤 메인 보고에 "Jira 댓글 완료"를 함께 적는다.

Jira 티켓 발급은 jira-issue 스킬의 상세 양식(요약·현상·재현·기대/실제·영향·환경·근거·추정 원인·관련·완료 기준)으로 한다. 빈 칸은 미확인.
 Jira 기록(11-06 사용자): 모든 작업(수정·리뷰·충돌 해결·단계 진행·PR)은 해당 티켓에 진행 단계마다 댓글로 자세히 남긴다. 무엇→왜→결과→남은 일, 해시·PR 은 맨 아래. 로컬 용어(허브·워커·묶음 번호·결정 번호·내부 별명) 금지, 팀원 누구나 이해하는 말.
