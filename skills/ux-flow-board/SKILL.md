# UX 흐름 보드

UX 피드백은 글보다 화면으로 받는다. 이 스킬은 **실제 게임 화면**을 프레임으로 놓고, 화면 안의 **버튼에서** 다음 화면으로 분홍 화살표를 이은 보드를 만든다. 실제 화면이 없으면 실제 게임 화면 위에 버튼·팝업 배치를 정한 목업을 올린다. 피그마 프로토타입 보드와 같은 모양이다. 결과물은 팀에 링크로 공유하는 아티팩트다.

**완성 예 — 먼저 열어 본다.**
- 소스: `examples/asset-delivery-flow.html` (이 스킬 폴더 안). 에셋 배달(PAD/ODR) 추가 데이터 받기 흐름 보드다. 이미지는 빼 두어 `img/*.jpg` 경로만 남아 있다. 머리의 경우 표, 보드 8개의 화면 배치, `EDGES` 좌표를 그대로 본뜨면 된다.
- 게시본: https://claude.ai/artifact/QmSZtuMu47paV2Lo3aGtfr — Artifact 도구 `action: "read"` 로 연다. 이미지까지 보인다.
- 다룬 경우는 10개다: 부팅 필수 받기(처음·받은 적 있음·실패·3번째부터 문의하기·차단 끔), 인게임 작은 받기, 인게임 큰 받기(받을지 묻기·[나중에]·[취소]·실패·문의 안내), 판 시작·이어하기와 Android Play 시트, 노벨 29화 [나중에]·취소·실패, 창 없는 받기.
- 배경 문서는 `docs/Tech Records/애셋 종합/`(2026-09-28, `feature/asset-lazy-download` 브랜치).

## 1. 흐름부터 표로 — UI 가 달라지는 경우를 빠짐없이

먼저 **유저가 보는 UI 가 달라지는 경우**를 전부 적는다. 조건(크기·설정·플랫폼·처음/다시)마다 창이 달라지면 각각 한 줄이다. 이 목록을 페이지 맨 위 "경우 표"(경우 · 유저가 보는 것 · 보드 링크)로 그대로 싣는다. 경우 하나가 빠지면 리뷰어는 그 경우가 없는 줄 안다.

- **취소·거절·실패 경로를 꼭 그린다.** [취소]·[나중에]·시스템 시트 닫기·실패 뒤 재시도/취소가 어디로 가는지, 무엇이 그대로 남는지(재화·진행·세이브)까지 적는다. 행복 경로만 있으면 보드가 아니다.
- 지금 쓰는 곳이 없는 UI 도 코드에 남아 있으면 보드를 두고 "지금 쓰는 곳 없음"이라고 적는다.
- 창이 전혀 없는 경로(조용한 처리·대체 화면)도 한 보드로 둔다.

그다음 보드마다 아래를 정한다. 보드 하나는 한 상황이다(예: "부팅", "인게임 큰 받기").

| 화면 | 어디서 오나 | 누르는 것 → 가는 곳 | 조건 라벨 |
|---|---|---|---|

- 한 보드는 2행 × 4열 안에 둔다. 넘치면 보드를 나눈다.
- 조건이 갈리는 곳(크기, 설정, 성공/실패)은 화살표 라벨로 쓴다. 따로 도형을 만들지 않는다.

## 2. 화면 확보 — 캡처가 먼저, 없으면 렌더, 그것도 안 되면 목업

**기기 캡처(AVD)** — `~/Library/Android/sdk/platform-tools/adb exec-out screencap -p > x.png` (1080x2400).
- 동작 하나에 한 장씩 찍고 매번 확인한다. 레이아웃이 밀리면 다음 탭이 엉뚱한 곳을 누른다.
- 전에 찍은 캡처가 있으면 재사용한다. 모음 이미지의 한 칸만 남아 있으면 `scripts/find_capture.py <칸.png> <폴더>` 로 원본을 찾는다.
- AVD 잠금·치트 진입 요령은 프로젝트 로컬 지침과 메모를 따른다.
- 에뮬레이터 상태(앱 설치 여부 등)가 예상과 다르면 건드리지 말고 묻는다. 다른 세션이 테스트 중일 수 있다.

**기기에 아직 없는 화면(새 팝업, 새 문구)** — 실제 프리팹을 Unity 에서 렌더한다.
1. 같은 프로젝트의 Unity 에디터가 닫혀 있어야 한다. 같은 프로젝트에서 batch 테스트가 돌고 있어도 안 된다.
2. `scripts/render_prefab.cs` 를 `Assets/Editor/_TmpRender/` 에 복사한다.
3. spec.json 을 쓴다. 형식은 스크립트 머리 주석에 있다. 모달 스크립트의 직렬화 필드 이름으로 글자·버튼·채움·켜기·끄기를 지정한다. 모달 스크립트를 떼고 그리므로 데이터가 끄던 것(예: 버튼 하나짜리 창의 `cancelButton`)은 `inactive` 로 직접 꺼야 한다 — 안 그러면 프리팹 기본값이 그대로 찍힌다.
4. 실행: `UXBOARD_SPEC=spec.json Unity -batchmode -projectPath <워크트리> -executeMethod UxBoardRender.Run -logFile render.log`. **`-nographics` 를 붙이면 빈 그림이 나온다.**
5. 끝나면 `Assets/Editor/_TmpRender` 폴더와 `.meta` 를 지운다. batch 실행이 건드린 파일은 `git checkout` 으로 되돌린다: `ProjectSettings/ProjectSettings.asset`, `ProjectSettings/EditorBuildSettings.asset`, `Assets/RawAssets/Local/Font/KoreanFallback_Dynamic.asset`, `Assets/Render/Universal Render Pipeline Asset.asset`.

결과는 모달만 있는 투명 PNG 다. 다음 단계에서 캡처 배경 위에 합성한다. 컨트롤러 싱글톤이 주는 아이콘·스프라이트는 비어 나온다 — 글자·버튼 모달에 쓴다.

**실제 화면을 구할 수 없거나 주어지지 않았으면 — 목업.** 프리팹이 아직 없는 기획 단계, 기기·에디터를 쓸 수 없을 때, 화면을 받지 못했을 때다. 실제 게임 화면 위에 회색 박스로 버튼·팝업의 위치·크기·순서·문구를 정해 둔 배치안(기획서 와이어프레임)을 올린다. 템플릿의 `.wf` 예를 본뜬다.
- 배경은 그 팝업이 뜨는 실제 화면 캡처(3단계로 줄인 360x800)다. 팝업이면 `.wf-in.dim` 으로 어둡게 한다. 캡처도 없으면 배경 없이 둔다.
- 요소는 360x800 좌표로 놓는다: `.mk`(회색 채움 — 창·버튼), `.mk.txt`(글자만), `.mk.slot`(테두리만 — 아이콘·이미지 자리). 색·그림으로 꾸미지 않는다. 정하는 건 배치와 문구다.
- 요소마다 분홍 번호(`.mk-n`)를 달고, 보드 아래 번호 표(`table.mkspec`: 번호 · 요소 · 내용·누르면)에 설명한다. 번호는 보드 안에서 겹치지 않게 이어 간다.
- 화살표 시작점은 `열 x + (left + width/2) / 2`, `행 y + (top + height/2) / 2` 다.

## 3. 합성·가리기·축소

`scripts/prep_images.py <spec.json> <out_dir>` — 캡처 위에 렌더를 어둡게 합성하고, 가릴 영역을 블러하고, 360x800 JPEG 로 줄인다. 화면 20장이면 700 KB 안팎이다.

- **계정 식별자는 반드시 가린다.** 부팅 화면 왼쪽 위 `uid-…`(1080x2400 기준 대략 `[0,150,700,330]`), 닉네임, 이메일.
- 캡처에 광고 배너가 찍혀 있으면 `광고` 칩을 단다. 고칠 대상이면 그렇다고 캡션에 쓴다.

## 4. 버튼 위치 읽기

`scripts/grid.py sheet.png a.png b.png …` 로 10% 격자를 그린 확인 시트를 만든다. Read 로 열어 버튼이 이미지의 몇 % 지점인지 읽는다. 보드 좌표는 `열 x + 비율 × 180`, `행 y + 비율 × 400` 이다.

## 5. 보드 쓰기 — `scripts/board_template.html`

템플릿을 스크래치패드로 복사해 `{{…}}` 를 채운다. 규칙:

- **배치** — 화면 180x400. 열 x = 150 / 440 / 730 / 1020(사이 틈 110), 행 y = 90 / 680. 왼쪽 0~130 은 분홍 행 라벨 자리다. 보드 크기는 `data-w="1240"`, 1행이면 `data-h` 620 안팎, 2행이면 1190 안팎.
- **화살표** — `EDGES[section id]` 에 꺾은선 좌표를 직접 쓴다. 첫 점은 누르는 버튼(흰 점), 마지막 점은 도착 화면의 가장자리(화살촉)다.
  - 세로 구간은 열 사이 틈(x 330~440, 620~730, 910~1020)이나 이미지 위를 지나게 한다. **캡션(이미지 아래 약 80px)을 가로지르지 않는다.**
  - 건너뛰는 선은 행 위로 돌린다. 1행은 y = 45, 2행은 y = 640 이다.
  - 되돌아가는 선은 이미지 아래쪽(y ≈ 행 + 370) 가로로 보낸다.
  - 라벨은 `l: [x, y]` 로 틈에 둔다. 가장 긴 가로 구간 가운데가 보통 맞다.
- **칩** — 모든 화면에 출처 칩을 단다: `실기`(기기 캡처), `렌더`(프리팹 렌더·합성), `목업`(회색 박스 배치안), `다음 빌드`(아직 기기에 없음), `광고`. 목업을 실기처럼 보이게 두지 않는다.
- **메모** — 화살표로 못 담는 규칙(기억되는 상태, 다음 실행 때 동작)은 `.note` 상자에 3줄 안으로.
- 맨 아래에 **피드백 받고 싶은 것**을 번호로 적는다. 문구, 버튼 순서, 빠진 안내, 눈에 띈 결함처럼 사람이 정해야 하는 것만 넣는다.

## 6. 한 번 보고 게시

1. `scripts/preview.sh index.html preview.png` 로 한 번 찍는다. 화살표·라벨이 캡션과 겹치지 않는지만 보고 한 번 고친다. 여러 번 반복하지 않는다.
2. Artifact 게시: `file_path` = index.html, `root` = 그 폴더, `files` = `{"img/a.jpg": "img/a.jpg", …}`, 첫 게시에는 `icon: "diagram"`.
3. 고칠 때는 같은 파일 경로로 다시 게시한다. 안 쓰게 된 이미지는 `files` 에 `"img/x.jpg": null` 로 지운다.
4. 아티팩트는 비공개다. 팀에 보이려면 페이지의 공유 메뉴에서 열어야 한다고 사용자에게 알린다.

## 하지 말 것

- 추상 박스·mermaid 순서도로 대신하지 않는다. 이 보드의 값은 실제 화면이고, 화면이 없으면 화면 모양의 목업을 그린다.
- 캡처가 없는 화면을 다른 화면 캡처로 흉내 내지 않는다. 렌더하거나 목업으로 그린다. 자리표시(`.phbox`)는 여러 화면 중 하나로 가는 자리(예: "들어간 화면")에만 쓴다.
- 보드에 개발 내부 이름(클래스·RC 키)을 도배하지 않는다. 화면 캡션은 유저가 보는 말로 쓰고, 설정값은 머리 표 하나에 모은다.
