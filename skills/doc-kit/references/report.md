# 보고서

여러 커밋·여러 항목에 걸친 작업 결과를 남에게 넘길 수 있는 문서로 만든다. 독자는 이 문서를 보고 **무엇을 받아들일지 결정하는 사람**이다. 전부 적용하지 않을 수 있다.

## 구조

- 산출물은 자체 완결 HTML 이다. 스타일은 `templates/doc.html` 의 `<style>` 을 쓴다.
- 맨 위 순서: 쉬운 말 3줄 요약(무엇을 했나 / 왜 / 사용자가 할 일) → 🙋 결정 카드 → 일람표 → 상세(접힘). 결정이 없으면 "결정 없음".
- **읽기 구조는 두 층이다.** 1층(결론·표·추천 조합)만 읽어도 결정할 수 있어야 한다. 나머지는 독자가 원할 때 여는 더보기다. 전부 본문에 눌러담으면 실패한 보고서다.
  - 더보기 수단: ① 표의 앵커로 상세 문단 이동 ② 트랙별 별도 문서로 위임하고 `→ 상세:` 링크 ③ 결정을 바꾸지 않는 정보는 부록(TMI)으로 내리거나 삭제.
  - 부록 후보: 계측·도구 상세, 탐색 과정 서사, 측정 환경 잡설, 다음 작업을 위한 단서.
- 요약과 상세에 같은 내용을 두 번 쓰지 않는다. 요약은 표와 추천 조합이고 상세는 근거다.
- 다룬 축은 전부 섹션을 유지한다. 구현이 0건인 축도 "구현 0건" 과 이유를 적는다.
- 최상위 섹션 사이에는 구분선을 넣는다.

## 항목 번호와 일람표

- 모든 항목에 `N번` 번호를 붙이고 문서 전체에서 번호로 상호 참조한다.
- 항목마다 **독립 적용** 가능 여부를 밝힌다. 선행 필수 항목·의존성·시너지를 반드시 표기한다.
- 시간이 없는 독자를 위해 **추천 조합**을 제시한다. 제외한 항목도 사유를 적는다.
- 작업 축(트랙) 단위 보고는 선택 단위가 항목이 아니라 커밋이다. 커밋 표의 영향성·리스크 컬럼과 선행 필수 커밋 표기로 같은 목적을 달성한다.

일람표 컬럼(맞지 않는 컬럼은 뺀다):

```
| # | 대상 | 상태 | 세대/단계 | 커밋 | 효과 | 리스크 | 독립 적용 |
```

- 효과가 큰 순으로 정렬하고 상위 항목은 굵게 쓴다. 중요도가 꺾이는 지점에 "이 밑으로는 적용하지 않아도 무방하다" 구분선을 둔다.
- 상태 어휘: `완료` / `⚠️ 무효` / `⚠️ 실효 없음` / `기각` / `미착수`. 실패·무효 항목도 표에서 지우지 않는다. 왜 무효인지가 독자에게 정보다.
- 효과·리스크의 판정 기준을 표 근처에 명시한다. 기준 없는 "큼/작음" 은 인상이다.

## 항목 상세

항목마다: 상태·세대/단계·커밋 해시 한 줄 → **문제**(실측 수치·코드 조각) → **변경** → 필요하면 **왜 이 방법인가**(기각한 대안과 이유) → **리스크**(검증 항목 포함) → **독립 적용**.

## 커밋 재정리 선행 확인

커밋 표를 만들기 전에 히스토리가 보고 단위(문제 단위)로 읽히는지 본다. 한 문제의 수정이 여러 커밋에 흩어졌거나 여러 문제가 한 커밋에 뭉쳤으면 바로 쓰지 말고 사용자에게 묻는다. 재정리(스쿼시·분할·재배열)할지, 히스토리는 두고 문서에서만 묶을지 정한다. 재정리는 푸시 여부를 확인한 뒤 사용자 승인으로만 한다.

## 실패 모드

- 트랙 하나를 조용히 누락한다 → 0건이어도 섹션을 유지한다.
- 추정 수치를 실측처럼 쓴다 → 출처 없는 숫자는 쓰지 않는다.
- 존재하지 않는 용어로 분류한다 → 쓰기 전에 코드·문서에 실재하는지 확인한다.
- 참고 정보가 본문에 산재한다 → 부록으로 격리한다.
- 요약이 장황하다 → 1층은 결론·표·요점만 둔다.

검수는 SKILL.md «검수» 를 따르고 `scripts/check.py --report <문서>` 로 검사한다. 커밋·푸시는 사용자가 지시할 때만 한다.
도식은 최소 1개이며 `<meta name="doc-kit-kind" content="보고서">` 를 적는다. `--report` 도 도식 0개면 실패한다. 사용량 절약 모드여도 생략하지 않는다.
