# doc-kit — 문서 통합 규칙

문서 규칙의 단일 출처다. 규칙은 여기서만 고친다. 프로젝트마다 다른 값은 설정 파일(`projects.toml`)에만 있고 이 스킬 본문에는 없다.

## 순서

1. **유형을 고른다.** 아래 표. 애매하면 묻는다.
2. **설정을 읽는다.** 프로젝트·독자·받는 사람·채널·저장 위치를 정한다. 방법은 [config.md](references/config.md).
3. **독자를 정한다.** 설정 `audience` 가 기본이다. 요청에 독자가 있으면 그것이 우선한다.
4. **유형 파일과 [style.md](references/style.md) 를 읽는다.** 유형 파일은 골격과 그 유형만의 규칙이다.
5. **근거를 모은다.** 코드·커밋·실측. 기준 커밋과 실측 날짜를 적는다. 근거가 없는 칸은 "미확인" 으로 쓴다.
6. **쓰고 검사한다.** HTML 은 `scripts/check.py` 를 통과해야 완성이다.
7. **검수 3단계를 거친다.** 아래 «검수».
8. **전달한다.** 아래 «저장·전달».

## 유형

| 유형 | 언제 | 읽을 파일 | 기본 산출 |
|---|---|---|---|
| 구조안 | 구조 변경·리팩토링·개선안을 보여 주고 결정받을 때 | [structure.md](references/structure.md) | 자체 완결 HTML |
| 해설 | 코드 변경(디프·브랜치·PR·커밋 범위)의 설계 의도를 설명할 때 | [explain.md](references/explain.md) | 자체 완결 HTML |
| 기록 | 설계 기록·계획·계약·규약·데이터 명세·런북·README·가이드 | [record.md](references/record.md) | 저장소 문서(md) |
| 보고서 | 여러 커밋에 걸친 작업 결과를 남에게 넘길 때 | [report.md](references/report.md) | 자체 완결 HTML |
| 비주얼 | 화면이 바뀌는 변경을 받는 사람에게 보여 줄 때 | [visual.md](references/visual.md) | 자체 완결 HTML |

## 공통 규칙

### 형식

- 사용자 검토용 문서는 **자체 완결 HTML** 한 파일이다. CSS·JS 인라인, 외부 요청 0건.
- 저장소에 커밋되는 기술 문서(기록 유형)만 md 로 쓴다. 위치는 설정 `docs_dir` 또는 저장소 관례를 따른다.
- 도식은 PUML 을 SVG 로 렌더해 내장한다. 원본 `.puml` 은 보존한다. ASCII 도식은 md 문서에서만 쓴다.

### 읽기 규칙

- **인과 규칙(최우선).** 결정 카드·표 칸·요약은 "지금 문제 → 그래서 하는 조치 → 그러면 달라지는 것" 으로 잇는다. 추천 이유는 다른 선택지와의 비교로 끝내지 않는다. 그 차이가 왜 중요한지, 무엇이 막히거나 깨지는지를 쓴다.
- **길이 상한.** 3줄 요약은 합계 180자 이하. 결정 카드 한 장 본문은 450자 이하. 문장은 평균 45자 안팎. 가운뎃점(·) 나열 대신 문장. 검수 기록·참고는 `<details>` 로 접는다.
- **한 줄 한 사실.** 가운뎃점·화살표로 여러 사실을 한 줄에 몰지 않는다. 읽는 순서는 무엇 → 왜 → 결과 → 할 일. 표는 선택지 비교에만 쓰고 칸에는 짧은 한 가지를 쓴다.
- **쉬운 말.** 독자가 처음 보는 사람이라고 가정한다. 내부 기호(P1·fixup·ctx_·항목 코드)를 쓰지 않고 풀어 쓴다. 용어는 처음 나올 때 한 줄로 풀이한다.
- 헤더 이모지: 🙋 결정 · 🛠️ 사용자 할 일 · ✅ 완료·유지 · 🔄 진행·변경 · ⚠️ 위험 · 📄 문서·그림. 색 배지: 🟢 추가 · 🟡 변경 · 🔴 삭제 · 🔵 테스트.

### 도식 3장 + 화면 샷

- 이전 구조 도식 → 문제 위치(⚠️ 빨강 표시) → 변경 후 구조 도식(바뀐 곳 색). `scripts/puml_diff.py` 가 바뀐 곳을 칠한다.
- UI 수정은 스모크 스크린샷 전/후를 나란히 놓고 바뀐 영역에 상자를 그린다(`scripts/image_diff.py`). 문제·병목 위치를 표시한다.
- 문장은 도식 아래 한두 줄이다. 샷이 없으면 "샷 없음" 을 밝히고 렌더·기존 샷으로 대체한다.

### 결정 카드

결정이 필요한 문서(구조안·보고서)는 아래 형식을 쓴다. 결정이 없으면 "결정 없음" 이라고 적는다.

- 맨 위 요약표: 결정 번호 · 질문 한 문장 · 추천 기호. 그 위에 "한 번에 답하기: `전부 추천` 또는 `결정1 A, 결정2 B`".
- 결정마다 카드 1장이다.
  1. 질문은 A/B 로 답할 수 있는 한 문장.
  2. 지금 문제 한 줄. 안 정하면 멈추는 것(고정 항목).
  3. 선택지 표. 이름과 용어 한 줄 풀이 · 고르면 어떻게 되나 · 되돌리기(`쉬움/보통/어려움` 라벨을 맨 앞에). 셀은 2문장 이하. 선택지는 2~3개이고 서로 겹치지 않는다. "검토", "추후 결정" 은 선택지가 아니다.
  4. 추천 1개(✅ 표시) + 이유. 이유는 "지금 X 때문에 Y 가 생긴다 → 그래서 A 는 X 를 없앤다" 와 인정하는 단점("감수하는 단점") 한 구절이다.
  5. 답하는 법 `결정1 A`.
- 선택지 '결과' 칸은 "~하므로 ~된다", "~하면 ~된다" 꼴이다. 비용 단위(근무일·파일 수 등)는 카드 안에서 정의한다. 결정 칸에는 카드만 둔다. 미룬 결정도 카드로 둔다.

### 문장 규칙과 충돌 해결

| 충돌 | 해결 |
|---|---|
| 평서 `~다` 와 명사형 압축 | 제목·표·목록·배지 줄은 명사형 압축이다. 서술이 필요한 칸만 `~다`. `~합니다`·`~입니다` 는 쓰지 않는다. |
| 고유명사 허용 여부 | 문서마다 독자를 정하고 갈라 적용한다. 개발자 독자는 클래스·함수·파일 이름을 쓴다. 기획자 독자는 역할로 풀어 쓰고 고유명사는 코드 조각과 참고 칸에만 둔다. |
| 저장 위치 | 새 문서는 설정 `out_dir` 한 곳이다. 저장소에 커밋하는 기술 문서만 `docs_dir` 관례를 따른다. |

문체·머리말·정정·반복 장치의 상세는 [style.md](references/style.md).

### 독자 규칙

- **개발자 독자.** 파일·클래스·함수 이름과 `파일:줄` 을 쓴다. 코드 조각이 근거다.
- **기획자 독자.** 쉬운 말 3줄 요약, 역할로 부르기, 고유명사·AI 내부 기호 금지. 코드는 before/after 조각과 참고 칸에만 둔다. `scripts/check.py` 가 본문 고유명사와 내부 기호를 검사한다.
- 같은 문서를 두 독자에게 줄 때는 문서를 둘로 나눈다.

### 근거

- 수치는 실측만 적는다. 규모는 `git show --shortstat`, 성능은 캡처 같은 출처가 있는 값이다. 추정은 추정이라고 쓴다.
- 사실 대조 기준은 설정 `base_branch` 다. 확인하지 못한 것은 "(미확인)" 을 붙인다.
- 틀린 서술은 지우지 않고 정정으로 덧쓴다(style.md «정정»).
- 범위 밖 발견은 본문에 섞지 않고 번외로 분리한다.

## 검수

사용자에게 보내기 전 3단계를 거친다. 구조안·보고서는 필수이고 나머지는 변경이 큰 문서에 적용한다.

| 단계 | 누가 | 보는 것 | 통과 기준 |
|---|---|---|---|
| 1차 독자 검수 | 작성자와 다른 Claude 워커가 코드·대화 맥락 없이 문서만 읽음 | 3줄 요약만 읽고 무엇이 바뀌는지 말할 수 있나, 모르는 용어, 그림과 본문 일치, before/after 가 주장과 맞나 | `check.py` 통과 + 지적 0 또는 반영 |
| 2차 교차 검수 | 다른 모델. 논리·사실·누락은 추론 강한 모델, 시각(1080폭·390폭 렌더 캡처, 표 넘침, 다크 모드)은 비주얼 모델 | 기준 브랜치 사실 대조, 추천 근거, 그림 깨짐 | 심각 0, 보통은 반영 또는 이유 기록 |
| 3차 최종 | 사용자 | 결정 | — |

- 검수 결과는 문서 맨 아래 참고 칸에 한 줄(날짜·모델·지적 수·반영 수)로 남긴다. 지적 목록은 `<details>` 로 접는다.
- 1·2차 기록이 없는 구조안·보고서는 전달하지 않는다.
- 헤드리스 캡처에서 Unity 를 활성화하지 않는다.

## 저장·전달

- 저장: 설정 `out_dir` 아래 `name_rule` 이름으로 저장한다. 폴더 안에 `<이름>.html`.
- 문서를 만드는 세션에 채널 인증이 없으면 업로드하지 않는다. 완성된 파일 경로와 핵심 3줄을 메인에 넘기고 메인이 설정 `channel` 로 올린다.
- 받는 사람은 설정 `recipients` 만 쓴다. 직접 전달 허용 여부(`직접전달 안 함`)를 지킨다. 허용되지 않은 사람에게는 사용자를 거쳐서만 전달한다.
- 메인에 보내는 제목은 `[허브명→메인] 📄 <유형>: <주제>` 이다. 본문은 파일 경로 · 핵심 3줄 · 받는 사람 · 검수 단계 한 줄이다.
- 설정이 없거나 프로젝트가 안 잡히면 기본값으로 진행하고 파일 경로만 보고한다. 보고에 "설정 없음 — 기본값" 한 줄을 적는다.
- 커밋·푸시는 사용자가 지시할 때만 한다. 문서를 만들었다고 커밋하지 않는다.
- 영상은 HTML 에 넣지 않는다. HTML 에는 GIF 미리보기(5MB 이하)와 장면 띠 이미지만 넣고 원본 영상(H.264, 720p 이하)은 채널에 별도 파일로 올린다. 장면 띠·GIF 는 `scripts/screen_flow.sh`.

## 도구

| 파일 | 하는 일 |
|---|---|
| `scripts/check.py <문서.html>` | 구조안·보고서 검사. 설정의 `ticket_pattern` 이 있으면 티켓 키도 본문에서 검사한다 |
| `scripts/doc_config.py` | 설정 읽기. 프로젝트 판별과 값 조회 |
| `scripts/puml_diff.py before.puml after.puml` | 두 PUML 비교. 추가=초록·변경=노랑·삭제=빨강 점선 |
| `scripts/image_diff.py before.png after.png out.png` | 화면 캡처 비교 이미지. 바뀐 영역에 빨간 상자 |
| `scripts/screen_flow.sh 영상.mp4 출력폴더` | 장면 바뀐 프레임 띠와 미리보기 GIF |
| `templates/doc.html` | 구조안·보고서 HTML 템플릿 |
| `templates/before.puml`·`after.puml` | 도식 시작점 |

문장 다듬기는 `writing-clearly-and-concisely`, 상투어는 `writing-humanizer`, 표현 검사는 `prose-lint`.
