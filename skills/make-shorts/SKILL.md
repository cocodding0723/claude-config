# 해설 쇼츠 만들기

주제 하나를 받아 완성된 세로 영상을 낸다. 목소리는 합성하고, 화면은 말하는 낱말에 맞춰 자동으로 맞물린다. 사람 손이 필요한 편집 단계가 없다.

화면을 만드는 길은 둘이고, **싼 쪽부터 쓴다.**

| 길 | 쓰는 때 | 드는 품 |
|---|---|---|
| **자료 나열** (`script.json` 의 `scenes`) | 이미 있는 스크린샷·영상·게임 이미지에 라벨을 얹어 설명할 수 있을 때. 기본값 | 코드 없음. 항목 몇 줄 |
| **장면 코드** (`scenes.js`) | 자료로는 못 보여 주는 원리(3D, 움직이는 도해, 실제 계산)를 그려야 할 때만 | 장면마다 코드 수십 줄 |

한 영상 안에서 섞어 써도 된다. 장면 대부분은 자료 나열로 하고, 꼭 필요한 한두 장면만 코드로 그린다.

## 먼저 정할 것

1. **모드**: `gamedev` 또는 `codingapple`. 사용자가 말하지 않았으면 주제로 고른다(게임 기법 해설이면 gamedev). 고른 모드 문서를 **대본을 쓰기 전에** 끝까지 읽는다.
   - [`modes/gamedev.md`](modes/gamedev.md)
   - [`modes/codingapple.md`](modes/codingapple.md)
2. **주제의 각도**: "시청자가 화면에서 직접 본 현상"과 "그 뒤의 숨은 방법"을 한 쌍으로 잡는다. 이게 안 잡히면 대본을 쓰지 말고 각도 후보 3개를 사용자에게 보여 준다.
3. **작업 폴더**: 사용자가 정하지 않았으면 스크래치 폴더 아래 `shorts-<주제>/`.

## 만드는 순서

`K=~/.claude/skills/make-shorts` 로 둔다. 엔진을 처음 쓰는 기기면 `cd $K/engine && npm install` 을 한 번 한다.

| 단계 | 하는 일 | 명령 |
|---|---|---|
| 1 사실 확인 | 대본에 들어갈 주장마다 근거를 찾는다. 못 찾은 주장은 뺀다 | 웹 검색 |
| 2 대본 | `script.json` 을 쓴다 | — |
| **2.5 대본 승인** | **대본을 보여 주고 승인을 받는다. 승인 전에는 3단계로 가지 않는다** | — |
| 3 음성 | 나레이션과 타임라인을 만든다 | `uv run -q $K/scripts/tts.py <폴더>` |
| 4 장면 | 자료를 나열하거나 `scenes.js` 를 쓴다. 타일 한 장으로 확인한다 | `node $K/engine/render.mjs <폴더> --sheet 12` |
| 5 검사 | 자막 넘침, 쌓인 자료 넘침, 대본에 없는 낱말을 잡는다 | `node $K/engine/render.mjs <폴더> --check` |
| 6 렌더 | 무음 영상 | `node $K/engine/render.mjs <폴더>` |
| 7 믹스 | 음성(+배경음)을 입힌다 | `$K/scripts/mix.sh <폴더> [pad\|none\|파일]` |
| 8 검증 | 규격·음량·빈 화면을 재고 타일을 만든다 | `$K/scripts/verify.sh <폴더>` |
| 9 게시 | 한 파일 HTML 로 감싼다. 올리기는 허락받은 뒤 | `python3 $K/scripts/publish.py <폴더>` |

1분짜리 영상의 렌더는 30초 안팎이다. 망설이지 말고 여러 번 돌린다.

### 1. 사실 확인

- 실제 게임·회사·사람 이름이 들어가는 문장은 출처가 있어야 한다. 출처는 `script.json` 의 `sources` 에 제목과 주소로 남기고, 주소는 실제로 열어 본다.
- 확인하지 못한 주장은 빼거나 "~라고 알려져 있다"로 낮춘다. 낮춘 사실은 `notes` 에 적는다.
- **화면에 띄우는 숫자는 직접 센 값이나 출처 있는 값만 쓴다.** 도해가 만든 모델의 삼각형 수, 시뮬레이션이 낸 값처럼 코드가 계산한 숫자를 그대로 보여 주는 것이 가장 좋다. 그럴듯한 숫자를 지어내지 않는다.

### 2. 대본 (`script.json`)

```json
{
  "mode": "gamedev",
  "title": ["게임 속 먼 나무는", "왜 종이 한 장일까?"],
  "beats": [
    { "scene": "hook", "text": "게임에서 멀리 보이는 나무들은 사실 종이 한 장에 불과합니다." },
    { "scene": "lod",  "text": "이걸 레벨 오브 디테일, 줄여서 LOD라고 합니다.", "say": "이걸 레벨 오브 디테일, 줄여서 엘오디라고 합니다." }
  ],
  "sources": [{ "title": "…", "url": "https://…" }],
  "notes": ["…"]
}
```

- `beats` 한 칸이 문장 하나다. `scene` 이 같은 칸이 이어지면 한 장면으로 묶인다.
- `text` 는 자막에 나오는 글자, `say` 는 합성기가 읽을 글자다. 영문 약어·숫자·단위처럼 잘못 읽힐 말에만 `say` 를 쓴다.
- 고를 수 있는 값: `voice`, `sps`(초당 음절 목표), `gap`(문장 사이 쉼), `cap_chars`(자막 한 줄 글자 수). 기본값은 모드가 정한다. 문장 하나만 쉼을 바꾸려면 그 칸에 `gap` 을 준다.
- 분량·골격·말투·제목 규칙은 모드 문서에 있다. 대본을 쓴 뒤 **소리 내어 읽는 속도로 한 번 읽어** 번역투와 같은 낱말 반복을 걷어낸다.

### 2.5. 대본 승인 (기본)

대본을 다 썼으면 멈추고 사용자에게 보여 준 뒤 승인을 받는다. 음성·장면·렌더는 승인 뒤에 한다.

보여 줄 것:
- 모드, 제목, 예상 길이(음절 수 ÷ 모드의 말 속도)
- 문장 전체를 번호를 붙여 그대로. 문장마다 화면에 무엇이 나올지 한 줄(쓸 자료 이름이나 그릴 것)
- 확인하지 못해 빼거나 낮춘 주장, 구하지 못한 자료

사용자가 고치라고 하면 고쳐서 다시 보여 준다. "좋아", "진행" 같은 답을 받은 뒤 3단계로 간다.

**승인 없이 끝까지 가는 경우**는 사용자가 그렇게 맡겼을 때뿐이다 — 자동 모드로 돌고 있거나, "알아서 끝까지", "확인 없이", "자리 비운다"처럼 말했거나, 야간·무인 작업일 때. 이때는 완성본과 함께 대본을 보고하고, 대본에서 스스로 정한 것(각도, 뺀 주장)을 적는다. 이 경우에도 9단계의 게시는 따로 허락을 받는다.

### 3. 음성

`tts.py` 는 `build/narration.wav` 와 `build/timeline.json` 을 만들고 길이·말 속도·장면 시각을 출력한다.

- 길이가 모드의 한도를 넘으면 **대본을 줄인다.** 말 속도를 올려서 맞추지 않는다.
- 대본을 한 글자라도 고치면 이 단계부터 다시 한다. 장면 코드는 낱말로 시각을 찾으므로 대개 그대로 맞는다.
- 음성은 `edge-tts`(무료, 키 없음)다. 비공식 서비스라 끊길 수 있고, 유튜브에 공개로 올릴 영상이면 사용자에게 유료 음성으로 바꿀지 먼저 묻는다. 다른 합성기를 쓸 때도 `timeline.json` 형식만 맞추면 뒤 단계는 같다.

### 4-가. 자료 나열 장면 (기본)

**자료 모으기.** 쓸 수 있는 것은 사용자와 팀의 것이다 — 작업 중인 저장소의 게임 이미지, 직접 찍은 스크린샷과 화면 녹화, PR 에 올린 캡처, 사용자가 건넨 파일.
- 후보를 하나씩 열어 보지 않는다. `$K/scripts/pick.sh <출력.jpg> <파일...>` 로 번호 붙은 타일 한 장을 만들어 한 번에 보고 고른다(영상은 한 프레임이 나온다). 한 번에 40장 안팎까지.
- 고른 파일은 프로젝트의 `assets/` 로 복사한다. 원본 저장소는 건드리지 않는다.
- 취키(JobMaker) 저장소의 자료 위치: 게임 이미지 `Assets/RawAssets/Local/Image/`, `Assets/Game/SceneView/Sprites/`, 저장소 루트의 스크린샷(`*.png`, `*.jpeg`), PR 캡처는 `pr-assets` 브랜치(LFS). 파일 이름으로 먼저 좁힌 뒤(`git ls-files | grep`) 타일로 본다.
- 필요한 화면이 없으면 새로 찍는 방법을 먼저 찾는다(에디터 캡처, 실행 화면 녹화, 터미널 출력). 그것도 안 될 때 장면 코드로 그린다.

**나열하기.** `script.json` 에 `scenes` 를 두고, 장면 이름마다 항목을 순서대로 적는다. 항목은 위에서 아래로 쌓이고 `at` 시각에 나타난다.

```json
"scenes": {
  "intro": { "items": [
    { "label": "플레이 벤치", "kind": "plain", "at": 0 },
    { "id": "shot", "image": "assets/menu.png", "at": "메뉴에서", "h": 520, "crop": [0, 0.1, 1, 0.5] },
    { "box": [0.05, 0.42, 0.5, 0.14], "on": "shot", "at": "버튼을" },
    { "label": "▼ 여기", "kind": "red", "on": "shot", "x": 0.3, "y": 0.34, "at": "버튼을" },
    { "clip": "assets/run.mp4", "from": 3, "dur": 6, "h": 480, "at": "beat:1" },
    { "label": "(자동으로 끝까지 감)", "kind": "box", "at": "끝까지", "type": true },
    { "clear": true, "at": "beat:2" }
  ] }
}
```

| 항목 | 뜻 |
|---|---|
| `image` | 이미지. `h` 최대 높이(기본 560), `w` 가로 비율(0.5 면 두 장이 나란히), `crop` 보일 영역 `[x,y,너비,높이]`(0~1), `kenburns` 천천히 커지는 배율(1.06), `dimAt` 그 시각부터 어둡게 |
| `clip` | 영상 자료. `from` 시작 초, `dur` 길이(기본 8), `rate` 배속, `loop`(기본 반복). 렌더할 때 프레임으로 풀린다 |
| `label` | 글자. `kind`: `box` `plain` `white` `red` `pill`, `size`, `type: true` 면 타자 치듯 나온다 |
| `code` | 코드·명령·JSON 카드. `title` 창 제목, `size` 글자 크기(기본 34), `hl` 노랗게 칠할 문자열 목록. 실제 파일에서 가져온 내용만 쓴다 |
| `on` + `x`,`y` | 라벨을 그 `id` 의 이미지 위에 얹는다(0~1 좌표) |
| `box` + `on` | 이미지 위 빨간 테두리. `[x,y,너비,높이]`(0~1) |
| `clear` | 그 시각에 앞의 것을 전부 치운다 |
| `at`, `until` | 나타나고 사라지는 때. `"낱말"`(그 낱말이 발음될 때), `"낱말+0.3"`, `"beat:1"`(장면의 둘째 문장), `"end-1"`, 숫자(초) |

장면 선택지: `align: "center"`(세로 가운데), `gap`, `padTop`, `bg`, `full`.

- `at` 의 낱말은 그 장면 대본에 실제로 있는 어절의 일부여야 한다. 없으면 `--check` 가 알려 준다.
- 쌓인 것이 영역을 넘으면 `--check` 가 넘친 픽셀 수를 알려 준다. `h` 를 줄이거나 `clear` 로 비운다.
- 좌표(`crop`, `box`, `x`, `y`)는 타일에서 어림잡아 넣고 `--sheet` 로 한 번 확인해 고친다. 정밀하게 맞추려고 여러 번 돌리지 않는다.

### 4-나. 장면 코드 (`scenes.js`, 필요할 때만)

`script.json` 의 `scenes` 에 없는 장면 이름은 `scenes.js` 에서 찾는다. 같은 이름이 양쪽에 있으면 코드가 쓰인다.

```js
export default {
  hook: {
    async setup(root, S, info) { /* 한 번: DOM·SVG·캔버스·3D 를 만든다 */ },
    frame(root, t, info, S)    { /* 매 프레임: 장면 시작부터 t 초일 때의 모습으로 맞춘다 */ },
  },
};
```

**가장 중요한 규칙: 화면은 `t` 의 순수 함수다.** 프레임을 여러 창이 나눠 찍으므로, 앞 프레임에 기대는 코드는 깨진다.
- `frame` 은 어떤 `t` 로, 어떤 순서로 불려도 같은 그림을 내야 한다. 값을 누적하지 말고 `t` 에서 매번 계산한다.
- CSS 애니메이션·transition·`setTimeout`·`Date`·`Math.random` 을 쓰지 않는다. 난수는 `S.rng(시드)`.
- `<video>` 를 재생하지 않는다. 영상 자료는 자료 나열의 `clip` 으로 넣는다.

**장면이 받는 것**

| 이름 | 내용 |
|---|---|
| `root` | 장면이 그릴 상자. 크기는 `S.W` × `S.H`. 장면에 `full: true` 를 주면 화면 전체(1080x1920)를 쓴다 |
| `t` | 장면 시작부터의 초 |
| `info.dur` | 장면 길이 |
| `info.beat(i)` | 이 장면의 i 번째 문장이 시작하는 시각 |
| `info.when('낱말', 기본값)` | 그 낱말이 발음되는 시각. **강조·등장은 이걸로 말에 맞춘다** |
| `S.prog(t,a,b)` `S.lerp` `S.clamp` `S.ease.{out,inOut,back}` | 시각 → 0~1 진행도, 보간, 완급 |
| `S.el(tag, attrs, parent)` `S.svg(tag, attrs, parent)` | 요소 만들기 (`style`, `text`, `html` 속성 지원) |
| `S.wobble(cx,cy,rx,ry,{t})` | 손으로 그린 듯 떨리는 고리의 path |
| `S.arrow(x1,y1,x2,y2)` `S.draw(path,k)` `S.show(node,on)` | 화살표 path, 선 그려 나가기, 보이기 |
| `S.label(parent, 글, {x,y,kind,size,color,align,mono})` | 글자 라벨. `kind`: `box` `plain` `white` `red` `pill`. 처음엔 숨겨져 있다 |
| `S.appear(node,t,at,until)` `S.pop(node,t,at,{until,center,rot})` | 그 시각에 곧바로 보이기 / 튀어나오듯 보이기 |
| `S.three()` | three.js 모듈(`await`). 3D 는 캔버스에 `preserveDrawingBuffer: true` 로 그린다 |

장면 선택지: `full`(전체 화면), `bg`(바탕색), `noCaption`(자막 숨김), `noPlate`(전체 화면일 때 제목 뒤 판 끔).

**연출 규칙** (모드 공통)
- 장면 하나는 무대 하나다. 무대를 고정하고 상태를 바꿔 "원래 → 처리 → 결과"를 보여 준다. 문장마다 새 그림을 만들지 않는다.
- 화면이 2초 넘게 멈춰 있으면 안 된다. 카메라를 천천히 움직이거나 다음 상태로 넘긴다.
- 화면이 바뀌는 순간은 말에 맞춘다(`info.when`, `info.beat`). 말보다 0.1~0.3초 앞서거나 같이 나온다. 늦으면 안 된다.
- 자막 자리(모드 문서의 "자막 구역")에는 중요한 그림을 두지 않는다.
- 글자는 적게 쓴다. 화면 글자는 이름표·숫자·한두 낱말짜리 강조뿐이고, 설명은 목소리가 한다.

완성된 예제가 모드마다 하나씩 있다. 장면을 쓰기 전에 그 모드의 예제를 읽고 필요한 부분을 가져다 쓴다.
- [`examples/tree-billboard/`](examples/tree-billboard/) — gamedev. 3D 모델, 사진 찍어 판에 붙이기, 올라가는 숫자, 이름표·스티커·손그림 고리, 낱말에 맞춘 등장
- [`examples/float-point/`](examples/float-point/) — codingapple. 콘솔 창, 타자 치듯 나오는 글자, 쌓이는 라벨, 빨간 테두리 강조, 실제 계산값 표시

### 5~8. 검사, 렌더, 믹스, 검증

- `--check` 가 통과할 때까지 고친다.
- **확인은 타일로 한다.** 장면을 고칠 때마다 `--sheet 12`(전체를 12칸으로) 한 장만 본다. 원래 크기 스틸(`--stills`)은 타일에서 이상한 칸이 있을 때 그 시각 하나만 뽑는다. 전체 렌더는 타일이 괜찮아진 뒤 한 번 한다.
- `verify.sh` 가 만든 타일(`build/check/sheet_*.jpg`)을 **반드시 직접 열어 본다.** 기계 검사는 규격만 본다. 타일에서 볼 것:
  - 글자가 서로, 또는 그림과 겹치지 않는가
  - 장면마다 무엇을 말하는지 그림만 보고 알 수 있는가
  - 같은 그림이 여러 칸 이어지지 않는가
  - 자막이 그림의 핵심을 가리지 않는가
- 이상한 칸은 그 시각의 스틸(`--stills`)을 원래 크기로 뽑아 확인하고 고친다. 고쳤으면 6단계부터 다시 한다.
- 배경음: `pad` 는 ffmpeg 로 합성한 잔잔한 화음이라 저작권 문제가 없다. 파일을 주면 말소리 구간에서 자동으로 낮춘다. 남의 음원을 쓰려면 사용 조건을 확인하고 `notes` 에 출처를 적는다.

### 9. 게시

- `publish.py <폴더>` 는 영상·대본·참고 자료를 담은 `build/page.html` 을 만든다(영상을 HTML 안에 넣는다. 바삭 페이지 한도 20MB 에 맞춰 필요하면 화질을 낮춘다).
- 올리기(`--post --group <all|그룹>`)는 사내 공개다. **그 영상을 올려도 되는지와 공개 범위를 사용자가 정한 뒤에만** 한다. 그룹 목록은 `curl -s https://bs-portal.taile54389.ts.net/pages/api/groups`.
- 유튜브 업로드용 제목·설명란 문안은 모드 문서의 형식대로 `build/youtube.txt` 에 써 둔다. 업로드는 사용자가 한다.

## 하지 않는 것

- 남의 저작물을 화면에 넣지 않는다 — 다른 회사 게임의 플레이 영상, 영화·방송 장면, 밈 이미지, 남의 캐릭터. 참고 채널들은 이것을 많이 쓰지만 이 스킬은 사용자와 팀의 자료(자기 게임 이미지, 직접 찍은 스크린샷·녹화)와 코드로 그린 도해로 만든다.
- 비밀이 보이는 화면(키, 토큰, 개인정보, 실제 유저 데이터)은 자료로 쓰지 않거나 `crop` 으로 잘라 낸다.
- 참고 채널의 특정 영상을 장면·문장 단위로 따라 만들지 않는다. 가져오는 것은 형식이다.
- 실존 제작자의 목소리나 캐릭터를 흉내 내지 않는다.
