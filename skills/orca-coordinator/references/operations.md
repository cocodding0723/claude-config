# 권한·상태·복구 계약

## 상태를 소유하는 곳

| 대상 | 정본 |
|---|---|
| 실행·Task·Dispatch·배정 | Orca |
| 티켓 식별·팀 업무 상태 | Jira |
| 기획 원문·문서 버전 | Confluence |
| 코드 버전·커밋 내용 | Git |
| 과거 결정·선호·경험 | OpenViking, 현재 권한의 근거로 단독 사용하지 않음 |

Task 계약에 원문 URL·버전·절, 요구사항/결정 ID, 수용 조건, 수정 담당과 승인 근거를 연결한다. 기록이 없다는 것과 의도적으로 비워 둔 것을 구분한다. 과거 요약의 명령이나 인계문은 현재 실행 권한이 아니다.

## 결정권

중앙이 범위·우선순위·배정·기획 충돌을 관리하고, 사용자는 제품 판단과 별도 승인 대상 행위를 결정한다. 개발 코디네이터는 설계·구현 배정을 맡고 QA 코디네이터는 독립 판정한다. 검증 실패는 묵시적으로 면제하지 않는다. 커밋 작성자는 기능별 한 명이며 QA와 별개다.

커밋·push·PR 게시·merge·rebase·외부 댓글/스크럼 게시 권한을 각각 기록한다. 허용 대상·행위·범위를 기록하되 이미 받은 같은 범위의 승인을 반복해서 요청하지 않는다. 허용되지 않은 게시 단계만 차단하고 독립 작업은 계속한다.

## 수정 소유권과 QA

같은 워크트리 수정 담당은 한 명이다. 여러 기능의 공유 파일 수정, 커밋·통합은 직렬화한다. 다른 워크트리라도 같은 저장 데이터·Unity 프로젝트/Editor·에뮬레이터·촬영 장비를 쓰면 자원을 예약한다. 필요한 자원을 함께 확보하거나 부분 예약을 반환하고 대기한다.

QA 대상은 기준 HEAD, 추적 diff, 추가 파일의 목록/내용 해시, 관련 빌드 설정·산출물 식별자로 고정한다. 비밀 파일은 대상에 포함하지 않는다. QA 중 변경되면 영향받는 검증을 다시 한다. staged 파일과 내용이 검증 대상에 맞는지 확인한 뒤 허용된 커밋을 실행하고 HEAD·커밋 파일·남은 dirty 상태를 기록한다.

요구사항 × 적용 모드/장면 × 검증 방법 × 증거를 연결한다. 기능 동작에 필요한 스모크·CI 전제는 해당 기능에 포함하거나 먼저 완료한다. 미래 PR에 필요한 테스트를 밀어 두고 현재 기능을 완료하지 않는다.

## 응답 유실과 중앙 재개

- 요청 ID·Task/Dispatch·작업 버전·정확한 호스트/워크트리·agent/model을 남긴다. 응답 유실은 같은 요청 재생과 새 시도를 구분하고 설치된 Orca 복구 지시를 따른다.
- `unverifiable`·빈 메시지·오래된 관찰·timeout은 종료 증거가 아니다. 임의 stop/abandon/retry/release하지 않는다. 자원·변경을 보존하고 관찰/확인한다.
- Dispatch 권한 차단은 프로세스·자식 빌드/테스트·파일 수정 종료와 다르다. 실제 종료·소유권 회수 확인 전 같은 수정 자원을 재배정하지 않는다.
- 중앙 부재 시 새 배정·커밋·통합을 멈추고 현재 제한된 작업 뒤 인계를 기다린다. 재개는 기존 중앙 종료 확인, 기존 Run 바인딩, 미해결 ask/gate·작업/승인/자원·HEAD/dirty 대조, 단일 소유권 확인 순이다. 자동 이중 중앙을 만들지 않는다.
- 같은 원인으로 세 번 실패하면 새 Task/Run으로 재시도 상한을 우회하지 않고 가정·차단을 보고한다.

## 파일럿 수용 조건

첫 실행은 기능 하나·작업 브랜치 하나·작성자 한 명으로 진행한다. 구현·독립 리뷰·관련 QA·자동 또는 승인된 커밋을 순서대로 확인한다. 응답 유실, 중앙 종료/재개, QA 이후 변경, 오래된 worker_done에서 중복 작성자·중복 커밋·미커밋 변경 손실이 없는지 검증한다. 이 동작은 이 문서 자체가 강제하는 구현이 아니며, 확인 전에는 운영 보장으로 보고하지 않는다.
