# orca-feature — 기능 코디네이터 열기·끝내기

사용자가 터미널 명령 대신 이 스킬로 코디네이터를 만든다. **사용자가 직접 부른 때에만 실행한다.** 세션이 스스로 판단해 코디네이터를 만들거나 끝내지 않는다(만든 뒤 지시·보고도 옮기지 않는다. 사용자가 코디네이터 창이나 그 Slack 스레드에 직접 지시한다).

스크립트: `~/orca/claude-config/hubs/scripts/feature_open.sh`, `feature_close.sh`. 옵션은 각 `--help` 가 기준이다.

## 인자

| 부르는 법 | 하는 일 |
|---|---|
| `/orca-feature` 또는 `list` | 열려 있는 기능 코디네이터 목록 |
| `open <티켓> <기능 이름> [기준 브랜치] [slug]` | 코디네이터 열기 |
| `close <slug>` | 코디네이터 끝내기 |

## 목록

```
cd ~/orca/board && bd list --type epic --status open,in_progress --label-pattern 'feature:*' --limit 0 --json \
  | jq -r '.[] | [.id, ((.labels // [])[] | select(startswith("feature:")) | sub("feature:"; "")), .title] | @tsv'
```

출력은 카드 번호, slug, 기능 이름 순이다. 표로 보여 준다. 그 밖의 조사는 하지 않는다.

## 열기

1. 인자를 맞춘다. 티켓(`LRM-n`)과 기능 이름은 필수다. 빠졌으면 한 번만 묻는다. 기준 브랜치를 안 줬으면 `dev` 로 하고 그렇게 했다고 말한다. Jira 티켓이 아직 없으면 만들지 말고 멈춘다(발급은 `jira-issue`).
2. 미리 보기: `feature_open.sh --ticket <티켓> --name "<이름>" --base <기준> --dry-run`. 만들 것(브랜치·작업 공간·작업판 카드·코디네이터·Slack 스레드)을 그대로 보여 준다.
3. 실행: 같은 명령에서 `--dry-run` 을 빼고 `--json` 을 붙인다. 사용자가 `open` 을 부른 것이 실행 승인이다. 훅이 확인 창을 띄우면 사용자가 누른다.
4. 결과 보고(3줄 이내): 코디네이터 작업 공간 경로, 기능 브랜치, slug. 그리고 "이제 코디네이터 창이나 그 기능의 Slack 스레드에 직접 지시"라고 알린다.

종료 코드가 0 이 아니면 스크립트가 낸 원인 줄을 그대로 전하고 멈춘다. 종료 5 는 사용자 검수를 기다리는 기능이 상한(기본 3)에 찼다는 뜻이다. 상한을 우회하지 않는다.

## 끝내기

1. 점검: `feature_close.sh --slug <slug>`. 아무것도 바꾸지 않는다. 종료 0 은 남은 것이 없다는 뜻, 4 는 남은 것이 있다는 뜻이다.
2. 점검 결과(진행 중 카드, 기능 브랜치에 합쳐지지 않은 워커 브랜치)를 보여 주고 **실행 여부를 묻는다.** 남은 것이 있으면 무엇이 버려지지 않고 남는지(브랜치·코드 변경이 있는 작업 공간은 지우지 않음)도 함께 말한다.
3. 사용자가 그러라고 하면 `feature_close.sh --slug <slug> --yes --json`. 워커 반납, 하위 작업 공간 정리, 코디네이터 창 닫기, 스레드 마무리 보고, 기능 카드 닫기가 한 번에 된다.
4. 결과 보고: 끝낸 것과 남긴 것(브랜치, 코디네이터 폴더).

`close` 는 되돌리기 어렵다(코디네이터 세션이 닫힌다). 점검 없이 `--yes` 부터 실행하지 않는다.

## 하지 않는 것

- 코디네이터에게 줄 지시문을 대신 보내지 않는다. 사용자가 원하면 맡길 문장(목표 + 확인 방법) 초안만 준다.
- 이미 살아 있는 코디네이터를 다시 띄우지 않는다(`feature_open.sh` 가 재사용한다).
- 티켓 없는 개인·설정 작업용 허브는 만들지 않는다. `orca-hub-create` 로 안내한다.
