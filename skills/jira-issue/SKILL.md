# Jira 이슈 등록

원칙: **티켓만 읽고 일할 수 있게.** 받는 사람이 대화·로그를 다시 뒤지지 않고 재현하고, 착수하고, 끝났는지 확인할 수 있어야 한다.
길게 쓰되 문단으로 쓰지 않는다. 한 줄에 사실 하나, 섹션마다 불릿.

## 기본값

- 사이트 `basakansoft.atlassian.net`, cloudId `a59b16fd-c171-4342-97ca-1f4ae9841192`
- 프로젝트 `LRM`. 유형은 `버그` 또는 `작업`(영문 Bug·Task 아님)
- 담당자: 사용자 본인(`atlassianUserInfo` 의 accountId). 누락 금지
- 우선순위: 진행 막힘·데이터 손실·재화 오류는 `High` 이상, 표시·문구는 `Medium` 이하. 근거를 `영향` 섹션에 적는다
- 도구 목록에 없는 작업 이름은 atlassian `discover` 로 찾아 `executeRead`/`executeWrite` 로 실행
- 다른 프로젝트·유형이면 `getVisibleJiraProjects`·`getJiraProjectIssueTypesMetadata` 로 실제 이름 확인

## 절차

1. **자료 모으기.** 대화·로그·스크린샷·녹화·커밋·PR·기획 문서·시트 행에서 템플릿 칸을 채울 근거를 찾는다. 코드 위치는 직접 grep 해서 파일:줄로 확인한다. 끝내 모르는 칸은 지우지 말고 `미확인`(무엇을 보면 알 수 있는지 한 줄).
2. **중복 검사:** `searchJiraIssuesUsingJql` 로 `project = LRM AND text ~ "핵심어"` 조회(핵심어 2~3개로 각각). 비슷한 게 있으면 링크를 보여주고 멈춘다.
3. **초안 보여주기.** 템플릿으로 쓴 초안을 보여준다. 등록 승인 전 생성 금지(요청에 "바로 올려"가 있거나 허브 선발급 규칙이 있으면 생략).
4. **생성:** `createJiraIssue`. 첨부(스크린샷·녹화·로그)는 `uploadAttachmentToJiraIssue` 2단계(filePath → 받은 curl 실행). 관련 티켓은 이슈 링크로도 건다.
5. **확인:** `getJiraIssue` 로 다시 읽어 키·URL·담당자·첨부 수를 한 줄로 보고한다. 응답이 끊겼으면 재생성 전에 같은 제목부터 검색.

## 제목

`[영역] 현상` 형식, 40자 이내, 명사형 종결. 영역은 화면·모듈 이름(매점·튜토리얼 1-1·인벤토리·서버 등).
예: `[매점] 전부 품절 상태에서 새로고침 가능`, `[튜토리얼 1-1] 3일차 돈 코칭 중간에 끊김`

## 수정 뒤 댓글 (회사 원칙)

티켓을 고치면 작업 브랜치 커밋 직후 그 티켓에 댓글을 단다. 별도 승인 불필요.

```
원인: 한 줄
수정: 한 줄
커밋: 브랜치 · 해시 (PR 있으면 #번호)
확인: QA 가 확인하는 방법 한 줄
```

- 코드 변경 없이 닫는 경우(기획 반영·중복·재현 안 됨)도 이유를 댓글로 남긴다.
- 범위 밖으로 남긴 것은 "범위 밖, 별도 티켓 필요"로 한 줄 덧붙인다.
- 실제 화면 확인을 못 했으면 그렇다고 적는다.
