# 주석 정리

주석은 코드가 말하지 못하는 **이유·제약·근거**만 남긴다. 무엇을 하는지는 코드와 이름이 말한다.

## 절차

1. 대상 파일의 주석만 뽑는다: `grep -n '^\s*///\|^\s*//' <file>`. 파일이 많으면 한 파일씩.
2. 아래 유형표로 분류하고 유형별 처리.
3. 사람이 쓴 것으로 보이는 주석(오타·끊긴 문장·리뷰 메모)은 삭제하지 말고 **확인 목록**으로 보고. 오타만 고친다.
4. 결과 보고: 파일별 `삭제 n / 압축 n / 유지 n / 확인 n`. 근거를 지운 게 없는지 마지막에 다시 본다.

## 유형과 처리

| 유형 | 예 | 처리 |
| --- | --- | --- |
| 테스트 본문 내레이션 | `// 서버가 true를 보내면 → 앱 값 true, 저장 true, 알림 1번` 위에 같은 내용의 `test('...')` | **삭제.** 테스트 이름·expect가 이미 말함. "이 케이스가 왜 필요한가"만 남김 |
| 식별자 반복 | `/// 저장할 때 사용.` on `encode()`, `/// 재시도 안 함` on `none` | **삭제** |
| 같은 규칙 여러 곳 | 검증 규칙이 클래스 doc + 테스트 헤더 + 인터페이스 doc에 반복 | lib 한 곳만 남기고 나머지 **삭제**. 필요하면 `[ClassName] 참조` 한 줄 |
| 튜토리얼체·비유 | `"우리 앱만 만들 수 있는 도장(HMAC)"`, `창구`, `부품`, `갈아끼운다`, `흘려보낸다`, `폰`, `글자`, `날것 값` | **압축.** 통용 용어로: HMAC, 인터페이스, 구현, emit, 기기, 문자열, 원문 |
| 서술형 문장 | `값을 가져옵니다`, `~하게 됩니다`, `~할 수 있다` | **명사형 압축.** `값 조회`, `~됨`, `~가능` |
| 리뷰·작업 메모 | `[검수 1]`, `TODO 나중에`, `이거 맞나?` | **확인 목록**으로 보고. 임의 삭제 금지 |
| 근거 있는 주석 | `// 재시도 3회 제한. 4회부터 서버가 429 반환` | **유지.** 압축하더라도 숫자·이유·출처는 지우지 않음 |
| 문서 ID 참조 | `(D03)`, `E06`, `X07` | **유지.** 단, 파일 상단 또는 클래스 doc에 해당 문서 경로 한 줄이 있어야 함. 없으면 추가 |
| docstring 파라미터·반환·예외 | `/// [timeout]이 지나면 ...` | 첫 줄만 압축. 파라미터·반환·예외 설명은 **삭제 금지**(IDE·문서 생성기가 읽음) |

## 판단 기준

- 지우기 전에 묻는다: **이 줄이 없으면 6개월 뒤 내가 코드만 보고 이 결정을 복원할 수 있는가?** 없으면 유지.
- "왜"가 있는 긴 주석은 줄 수가 아니라 밀도를 본다. 5줄 근거를 2줄로 압축하되 핵심 단어(공격 벡터, SDK 제약, 정책 번호)는 유지.
- 주석 스타일은 주변 코드를 따른다. 저장소가 영어 주석이면 영어, 한국어면 한국어. 섞지 않는다.
- 한국어 주석은 전역 CLAUDE.md "한국어 텍스트 규칙 > 인라인 주석" 기준을 따른다.

## 산출

- 코드 파일 변경 → 리뷰 게이트 적용. 삭제·압축 diff와 확인 목록을 제시하고 승인 뒤 커밋.
- 보고 형식: 유형별 건수 + 확인 목록 + before/after 예 3개 이내.
