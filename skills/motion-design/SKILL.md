# 모션 디자인 기준

결론 규칙만 둔다. 출처·채택/기각 근거는 `references/research.md`. 두 독립 리서치(Claude·Codex)가 같은 근거에 닿은 항목은 "합의"로 표시했다.

## 1. 먼저 목적을 정한다

- 연출마다 목적 하나를 적는다: **입력 확인 · 상태 변화 · 화면 관계 · 보상 강조**. 목적이 없으면 넣지 않는다. 트윈이 없던 곳에 일괄 추가하지 않는다.
- 일상 조작(버튼·탭·반복 구매)과 특별 순간(레벨업·큰 보상)의 세기를 나눈다. 세게는 특별 순간에만.
- 같은 정보를 흔들림·확대·파티클·숫자 팝업으로 겹쳐 강조하지 않는다. 하나씩 빼 보고 의미가 남으면 뺀다.

## 2. 시간·Ease (합의: NN/g·Material)

| 대상 | 시간 | Ease |
|---|---|---|
| 버튼 눌림·단순 피드백 | 0.08~0.12초 | OutQuad |
| 작은 요소 등장·값 변화 | 0.15~0.25초 | OutQuad / OutCubic |
| 팝업·패널 진입 | 0.20~0.30초 | OutCubic |
| 팝업·패널 퇴장 | 진입보다 짧게 0.15~0.20초 | InQuad |
| 화면 전환 | 0.30~0.40초 | InOutCubic |

- 일상 UI 는 **0.4초를 넘기지 않는다**. 0.5초 이상은 대기로 느껴진다. 시간은 개별 트윈이 아니라 **Sequence 전체**로 잰다.
- 기본은 감속(Out). 튕김(OutBack·Elastic)은 보상·캐릭터 강조에만, 오버슈트 작게.
- 팝업은 scale 0 에서 시작하지 않는다(0.9~0.95 + 페이드).
- 연출 완료를 다음 입력의 조건으로 삼지 않는다. 반복 조작 중 다시 누르면 즉시 끝 상태로 보낸다.
- 위 표는 시작값이다. 게임 장르 실험 근거는 없으므로 녹화로 보고 조정한다.

## 3. 디즈니 12원칙 중 UI 에 쓰는 것

- **기본 적용**: Timing, Slow in/out, Staging(한 번에 한 곳으로 시선).
- **강조에만**: Anticipation, Follow-through/Overlap, Squash & Stretch, Arcs, Secondary action, Exaggeration. 글자·숫자는 늘이거나 찌그러뜨리지 않는다.
- 캐릭터 연출과 버튼·HUD 는 다른 기준. 캐릭터는 더 과장해도 되고, 조작 UI 는 절제.

## 4. 과하다는 피드백을 받았을 때

- 주스는 "없음"도 "극단"도 나쁘고 **중간이 가장 좋다**(합의: 실증 연구 + GDC 비판 발표).
- 줄이는 순서: 반복 조작의 튕김·대기 → 겹친 강조 → 화면 흔들림 → 파티클 수 → 시간.
- 참고 영상이 있으면 그 세기가 상한이다. 참고에 없는 효과는 빼는 게 기본.
- 감소·손실에도 짧은 트윈·물결 같은 피드백은 준다(증가만 연출하면 상태 변화를 놓침). 세기는 증가보다 약하게.

## 5. DOTween 수명 관리 (공식 문서 근거)

- `SetLink`·`SetUpdate`·`SetEase` 등 수명·업데이트 설정은 **바깥 Sequence 에** 건다. Sequence 안 트윈에 건 SetLink·SetUpdate 는 효과가 없다.
- 오브젝트에 묶는다: `SetLink(gameObject)`(기본 KillOnDestroy). 꺼졌다 켜지는 UI 는 `LinkBehaviour` 를 명시.
- 다시 시작할 때 같은 대상의 이전 트윈을 정리한다(핸들 보관 후 `Kill`). `Kill(false)` 는 현재 값에서 멈추고 `Kill(true)` 는 끝값으로 보낸다 — 어느 쪽인지 정한다.
- 일시정지(timeScale 0) 중에도 움직일 UI 는 `SetUpdate(true)`(unscaled).
- 보상 지급·데이터 변경을 `OnComplete` 에 걸지 않는다. 상태 변경 먼저, 연출은 표시만.
- UI 클릭 핸들러 안에서 트윈을 동기 Kill·Cancel 하면 콜백 안에서 트윈 목록이 중첩 수정돼 예외가 날 수 있다(사내 선례). 콜백 중 정리는 다음 프레임으로 미룬다.

## 6. 성능 예산 먼저

- 설계 메모 첫 줄에 예산: 추가 Draw·SetPass, 오버드로 면적(화면 대비), 활성 트윈 수, 파티클 상한, **프레임당 GC 0**, 저사양 단계(끄기·절반).
- 자주 움직이는 UI 는 별도 Canvas. 정적 UI 와 섞지 않는다. 중첩 LayoutGroup 안에서 크기를 트윈하지 않는다.
- UI 연출은 Animator 대신 트윈(Animator 는 값이 같아도 매 프레임 dirty).
- 전면 반투명 오버레이·플래시는 오버드로 1배 — 국소 글로우·색 틴트와 비교해 고른다.
- 숫자 카운트업은 표시값이 바뀔 때만 텍스트 갱신. 반복 생성물은 풀링.
- 후보 2안 이상을 같은 장면에서 ProfilerRecorder 로 재고 고른다.

## 7. 움직임 줄이기

- 설정에 "움직임 줄이기"를 둔다. 켜면 흔들림·확대·회전·배경 루프를 끄고 짧은 페이드·하이라이트로 바꾼다. 의미 있는 상태 변화는 남긴다.
- 단순히 재생 속도를 올리는 것은 대안이 아니다.
- 시스템 설정 연동은 Unity 기본 API 로 안 되므로 네이티브 호출이 필요하다(iOS Reduce Motion, Android 애니메이션 배율). 기기에서 켜고 실제로 바뀌는지 확인한다.

## 8. 판정은 녹화로

- 사용자가 말한 효과 이름을 체크리스트로 적고, 효과마다 녹화 프레임 경로와 "보임/안 보임"을 남긴다. 정지 화면·코드 연결·EditMode 통과만으로 완료라 하지 않는다.
- 녹화로 시간(프레임 수)을 재서 위 표와 맞는지 본다.

## 프로젝트 기준 (연애혁명 키우기)

- 인게임 연출 색은 메인 메뉴 팔레트(밝은 파스텔 + 진한 자두색 외곽선). 맵 화면만 중저채도.
- 텐션업 연출 세기 상한은 참고 영상. 그 밖의 UI 트윈은 0.15~0.35초, OutQuad/OutCubic, 튕김 최소.
- UI 는 프리팹으로 만들고 레이아웃 그룹으로 배치. 열기·닫기·눌림 기초 트윈을 점검 항목에 넣는다.
- 새 셰이더는 허용하되 성능 예산과 변형 수 전후를 보고한다.
