# decision-log

사용자가 자리를 비운 동안 내린 판단을 나중에 빠르게 검토하고 되돌릴 수 있게 한다. 기록은 한 곳, 한 형식이다.

## 언제 쓰나

- 사용자 확인 없이 선택지 중 하나를 골랐다(설계·범위·순서·도구·우회).
- 실패를 보고 방향을 바꿨다.
- 규칙 해석이 갈리는 곳에서 한쪽으로 판단했다.

단순 실행(컴파일 돌림, 파일 읽음)은 적지 않는다. 사용자 승인이 필요한 것(push·PR·구조 변경 등)은 기록으로 대신하지 않고 결정으로 올린다.

## 형식

작업 공간 루트의 `decisions.tsv`. 탭 구분, 한 결정 한 줄, 칸 안에 줄바꿈·탭 금지.

```
시각	무엇	왜	근거	결과	되돌리기
```

| 칸 | 쓰는 법 |
|---|---|
| 시각 | ISO8601 (`2026-11-05T14:02+09:00`) |
| 무엇 | 고른 것 한 줄 |
| 왜 | 쉬운 말 이유 한 줄. 버린 선택지가 있으면 함께 |
| 근거 | 가리키는 것만: 커밋 해시, `파일:줄`, 로그·스크린샷 경로. 문단 금지 |
| 결과 | `컴파일 통과`, `테스트 실패`, `되돌림`, `미결` 같은 상태 |
| 되돌리기 | 되돌리는 방법 한 줄(`커밋 abc 되돌림`, `설정 X 원복`). 불가면 `불가` + 이유 |

파일이 없으면 머리 줄부터 만든다. 기존 줄은 고치지 않고 아래에 새 줄을 더한다(결과가 바뀌면 새 줄로 갱신).

## 위치와 커밋

- 기본은 로컬 기록이다. 저장소에 커밋하지 않는다. 워크스페이스를 지우기 전에 담당 허브가 보관한다.
- 리뷰어가 경로를 따라가야 믿을 수 있는 큰 작업(대규모 이식·이관)일 때만 사용자 승인 뒤 커밋한다.

## 보고할 때

- 완료·진행 보고에 `decisions.tsv` 경로와 이번 보고 구간의 줄 수를 적는다.
- 되돌리기가 `불가`이거나 결과가 `미결`인 줄은 본문에 다시 꺼내 🙋 결정으로 올린다.
- 메인 코디네이터는 catch-up 스킬로 허브들의 기록을 모은다.
- 사용자용 HTML 에는 줄을 그대로 붙이지 않고 쉬운 말 표로 옮긴다(고유명사는 참고 칸).
