# 문서 공통 문체·장치 (machamy 선례 기준)

`tech-record`·`explain-diff`·`create-pr`가 함께 쓰는 기준이다. 출처는 JobMaker machamy 문서 52편(변경 해설 26)과 PR 25건. 2026-10-08 정제·재분석(`sources.md`).

## 문체

- **평서 `~다`로 쓴다.** 선례의 다수 경향이다(문서 87%·PR 72%, 10월 문서 11편은 전부 평서). `~합니다`체 선례 7편은 특정 머리말 틀을 공유한 도구 세션 산물이라 따르지 않는다. 명사형 종결(`~함`)은 선례에도 거의 없다(1%).
  - 예외: 외부 저작자에게 넘기는 지시서는 `~합니다` 선례가 있다. 커밋 제목은 저장소 규칙(LRM 은 명사 종결), 코드 주석은 `comment-lint` 기준.
- **PR 요약·계약/계획 0절의 첫 문장은 결과를 단정한다.** PR 은 다음 문장에서 이전 상태와 대비한다("dev 는 ~했다"). 변경 해설 본문은 배경부터 시작한다.
- **굵은 주장 + 근거.** 단락·불릿의 첫 구절을 굵게 쓰고 근거를 뒤에 붙인다(선례 불릿의 34%). 훑어 읽는 독자는 굵은 줄만 따라간다.
- **용어는 처음 나올 때 굵게 + 한 줄 풀이.** 뜻이 여럿인 말은 표로 갈라 둔다(「이벤트 프레임워크」 "이 게임에서 '이벤트'란", 「AB 테스트 시스템」 "미배정").
- **사내 축약어·숫자 ID 는 첫 등장에 풀어 쓴다.** 선례: #2613 "국민체조 속보(60061)", #2629 "60001 편의점 알바 수입".
- **모르는 것은 먼저 인정한다**(#2559 "근본 원인은 파악하지 못했다"). **이유가 없으면 없다고 쓴다**(「래퍼 ID 타입 규약」 "없는 게 이유다").
- 메타 서술("본 문서에서는 ~을 다룬다")은 쓰지 않는다.

## 머리말

문서 첫머리 인용 블록에 읽기 전에 알아야 할 것만 둔다. 두 형이 있다.

**① 규모형 — 단독 변경 해설.** 해설 19/26 이 규모 줄을 쓴다.

```markdown
> <이 문서가 무엇이고 언제 읽는가 한 줄>. 말미에 퀴즈 N문항이 있고 정답은 접어 두었다.
>
> `17 커밋 · 23 파일 · +2682 / -46` (`.meta` 제외, vs dev `b04604e69d`, 2026-10-08 실측)
> **검증**: EditMode 458/458 통과. 수동 QA 미실시.
```

**② 읽는 법·범위형 — 문서망의 세부 문서.**

```markdown
> **읽는 법**: 1장 배경 → 2장 직관 → 3장 코드. 개요는 [00 개요](00%20개요.md).
> **범위**: <이 문서가 다루는 것 / 다루지 않는 것>
```

- 규모 줄은 필수, 기준 SHA·실측 날짜는 권장. 기준이 움직이면 원인 귀속이 뒤집힌다.
- 생성물 비중이 크면 밝힌다("프리팹 YAML 이 전체의 86%다").
- 문서가 크면 목차, **독자별 읽는 순서**, **커밋 순서(리뷰 순서) 표**를 붙인다. 동작을 바꾸는 커밋은 굵게.
- 상태·정정은 `> [!NOTE]`·`> [!IMPORTANT]` 콜아웃으로 쓴다(5편).
- 계약·규약·폴더형 같은 비해설 문서는 머리말을 생략해도 된다(선례 12/26 생략).

## 정정

**본문을 지우지 않고 덧쓴다**(선례 11편).

- 대전제가 바뀌면 머리말 콜아웃: "본문은 당시 판단의 기록으로 남긴다."(「도전 독서왕」), "🔴 전제 정정 — 이 문서의 절반이 무효다" + 이전/지금 표(「유저 통계 backfill 계획」).
- 부분 정정은 본문 안에 `정정(2026-09-15)` 표식.
- 틀린 수치도 지우지 않고 정정 이력으로 남겨 재사용을 막는다(「AB 테스트 시스템」).
- 실행이 끝난 계획은 설계 기록으로 개명하고 실행 단계 절을 걷어낸다 — 남겨 두면 다음 사람이 따라간다.
- 본문을 고치면 그 절을 근거로 쓰는 퀴즈·요약 표를 같이 고친다. 양성 사례 「신규 속보 21종」(퀴즈 정답까지 정정), 반례 「메타 보상 계층」(커밋 `e6f4d9e4d7` 이 §3.5 만 고치고 Q3 는 그대로).

## 근거·인용

- 숫자로 쓴다. "많다" 대신 "약 1,060개(약 6%)", "영향 uid 78".
- 코드는 `File.cs:48`, 이어지면 `:131-133`. 커밋 해시 9자리 이상, 절 참조는 `§3.5`.
- 문서 링크: 같은 폴더 안은 퍼센트 인코딩 상대경로. **PR 본문에서는 상대경로 금지** — blob 절대 URL(`explain-diff` 2-1 규칙).
- 레포 내 선례는 표로, 외부 선례(라이브러리·언어)는 이름과 링크.

## 그림

- 마크다운 문서: 코드블록 안 ASCII 흐름도·박스(선례 34/52)와 표(51/52)가 기본이다. mermaid 는 GitHub·Obsidian 둘 다 렌더될 때만(2/52).
- 흐름이나 구조가 바뀌는 PR·문서에는 표나 그림을 하나 이상 넣는다. machamy PR 은 표 21/25, 그림은 ASCII 1건(#2438)뿐이다 — 그림은 선례보다 늘린다.
- HTML 산출물은 `explain-diff/references/html-spec.md`를 따른다(ASCII 금지).

## 하지 않는 것

- 같은 글을 PR 본문과 커밋 메시지에 두 번 쓰기.
- AI 흔적 줄(`🤖 Generated with`, `Co-Authored-By`)을 PR·문서에 넣기. machamy PR 25/25 에 있으나 사용자 규칙이 우선한다.
- PR 요약 문단을 400자 넘기기. **이 스킬의 선택이다** — 선례 중앙값은 약 700자, 12KB 넘는 본문이 3건이다. 길어지면 표나 해설 문서로 위임한다.
