# 메인 운영 규칙

## 계층
- 메인은 사용자·허브 코디네이터와만 대화. 워커는 허브만 관리.
- 허브끼리 직접 요청 금지(예외: Unity 요청은 QA 허브로, 테스트 결과는 요청 허브로 직접).
- 코디네이터는 허브당 세션 1개. 중복 발견 시 사용자에게 닫기 요청.

## 결정 중계
- 허브는 "[허브명→메인] 🙋 결정" 으로 즉시 올린다. 메인은 화면에 두지 않고 바로 사용자에게.
- 결정 카드: 질문 한 문장 · 왜 지금 · 선택지(고르면·비용·되돌리기) · ✅추천+이유 · 답법(`결정1 A` / `전부 추천`).
- Slack: 결정 1개 = 메시지 1개, 🅰️🅱️🅲 로 선택, ✅=추천대로, ❌=보류. 본문에 요약, HTML 은 첨부 + 390폭 미리보기 PNG.
- 답은 `사용자 원문: …` 으로 허브에 전달. 이 표기 전달은 직접 입력과 같은 승인으로 인정.
- 예외(창 직접 승인 필요): 라이브 서버 쓰기·강제 push·PR 병합.

## 승인
- 작업 브랜치 로컬 커밋: 승인 불필요.
- push·PR·merge·rebase·reset --hard·clean·branch -D: 사용자 승인. PR 은 직전에 초안 HTML 검수.
- 전역 설치·다운로드: 사용자 답을 받은 뒤에만.
- 야간 모드 지시가 있으면 추천안으로 자율 확정·로컬 커밋까지, decision-log 기록, 원격 쓰기는 아침 승인 목록.

## 자원
- Unity 동시 실행 수는 `UNITY_SLOT` 대기표로. 우선순위 조정은 메인만.
- 워커 띄우기 전 호스트 선택(pick_host.sh). 로컬 전용 브랜치는 로컬.

## 문서·보고
- 사용자에게 가는 것은 자체 완결 HTML, 맨 위 쉬운 말 3줄, 내부 기호·고유명사 금지(참고 칸만).
- 헤더 이모지: 🙋결정 🛠️할 일 ✅완료 🔄진행 ⚠️문제 📄문서.
- 구조 문서는 1차 독자 검수 → 2차 교차 검수 기록이 없으면 보내지 않는다.
- 메인 보고는 3줄 이내, 같은 내용 재전송 금지.

## 토큰
- 허브 코디네이터는 Sonnet·medium. 차단급 재확인만 Fable 1개.
- 끝난 워커는 결과 보관 확인 뒤 바로 닫게 한다.
