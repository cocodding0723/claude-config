# catch-up

사용자는 자기 마지막 메시지까지만 기억한다고 가정한다. 그 뒤에 일어난 일을 다시 묻지 않아도 되게, 결정이 필요한 것을 이 답 하나로 처리할 수 있게 정리한다.

## 원칙

- 이 턴은 읽기 전용이다. 코드 수정·실행·게시·메시지 전송을 하지 않는다.
- 알림·서브에이전트 결과·허브 보고는 사용자 메시지가 아니다. 기준점은 사용자가 직접 쓴 마지막 메시지다.
- 쉬운 말로 쓴다. 무엇이 바뀌었는지(사용자에게 의미)를 쓰고 어떻게 했는지는 뺀다.
- 본문에 클래스·파일·티켓·커밋·실명 같은 고유명사를 쓰지 않는다. 역할로 부른다. 행동에 꼭 필요한 식별자만 맨 아래 참고 절에 둔다.
- 내부 약어(P1·fixup·ctx 등)를 쓰지 않는다.

## 1. 모으기

1. 이 대화에서 기준점 이후의 내 작업, 서브에이전트 결과, 다른 참여자 메시지를 훑는다.
2. 관련 PR·브랜치·작업의 현재 상태를 다시 확인한다(기억 대신 실측).
3. **Orca 메인 코디네이터일 때** 허브마다 아래를 반복한다.
   - `orca terminal read` 로 허브 화면 최근 출력을 읽는다.
   - 질문·승인 요청·선택지·"결정"·"승인"·"대기" 문구가 메인에 전달되지 않고 화면에만 남았는지 찾는다.
   - 허브 작업 공간의 `decisions.tsv`(decision-log 스킬)를 읽어 사람 없이 내린 결정 중 되돌릴 수 있는 것을 확인 대상으로 올린다.
   - 워커 승인 창(권한 확인)에 멈춘 것도 대기 항목으로 넣는다. 대신 답하지 않는다.
4. 같은 결정이 여러 허브에 겹치면 하나로 합치고 출처 허브를 적는다.

## 2. 분류

| 구분 | 넣는 것 |
|---|---|
| 🙋 결정 | 사용자 답이 있어야 진행되는 것. 전부 넣는다. 하나라도 빠뜨리면 안 된다 |
| 🛠️ 할 일 | 진행 중이거나 다음 순서인 것, 누가 맡았는지 |
| ✅ 완료 | 끝난 것과 사용자에게 달라진 점 |
| ⚠️ 문제 | 막힘·실패·위험 |

결정 항목마다 결정 카드 형식을 따른다: 질문 한 문장 · 왜 지금 · 선택지(결과·비용·되돌리기) · ✅추천+이유 · 답하는 법(예: `결정1 A`, `전부 추천`).
카드와 표 칸은 '지금 문제 → 그래서 조치 → 그러면 달라지는 것'으로 잇는다. 추천 이유는 비교로 끝내지 않고, 그 차이가 없으면 무엇이 막히거나 깨지는지 쓴다. 요약은 180자 이하, 카드 한 장은 450자 이하로 쓴다.

## 3. 출력

1. **자체 완결 HTML** 한 장을 스크래치패드에 만든다. 외부 리소스 없이 열린다.
   - 맨 위 3줄 요약 → 🙋 결정 표 → ⚠️ 문제 → 🛠️ 할 일 → ✅ 완료 → 참고.
   - 헤더 이모지는 🙋결정·🛠️할 일·✅완료·🔄진행·⚠️문제·📄문서만 쓴다.
   - 바뀐 흐름을 설명해야 하면 작은 도식 하나만 넣는다. 꾸밈용 그림은 넣지 않는다.
   - 문체·고유명사 규칙은 work-report·structure-change-doc 과 같다.
2. **채팅 요약**: 결정 개수와 답하는 법, 가장 급한 것 하나, HTML 경로. 다섯 줄 이내.
3. 결정이 하나도 없으면 "답할 것 없음"이라고 분명히 쓴다.

## 점검

- [ ] 허브 화면·decisions.tsv·승인 창을 모두 봤다
- [ ] 결정마다 답하는 법이 있다
- [ ] 본문에 고유명사·내부 약어가 없다
- [ ] 상태는 다시 확인한 값이다

## 한 줄 한 사실 (11-05 사용자)
- 한 줄에 사실 하나. 가운뎃점·화살표로 여러 사실을 한 줄에 몰지 않는다.
- 읽는 순서대로 위→아래: 무엇 → 왜 → 결과 → 할 일.
- 표는 선택지 비교에만, 칸에는 짧은 한 가지.
