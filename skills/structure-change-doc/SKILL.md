# structure-change-doc

구조를 바꾸자는 제안을 **처음 보는 사람도 5분 안에 판단할 수 있는** 한 장짜리 HTML로 만든다.

## 읽기 규칙 (11-05, 아래 모든 규칙보다 우선)

- **인과 규칙(11-05, 최우선):** 결정 카드·표 칸·요약은 '지금 문제 → 그래서 하는 조치 → 그러면 달라지는 것'으로 잇는다. 추천 이유는 다른 선택지와의 비교로 끝내지 않는다. 그 차이가 왜 중요한지, 즉 무엇이 막히거나 깨지는지를 쓴다.
- **길이 상한(11-05):** 3줄 요약은 합계 180자 이하다. 결정 카드 한 장 본문은 450자 이하다. 문장은 평균 45자 안팎을 목표로 한다. 가운뎃점(·) 나열 대신 문장으로 쓴다. 검수 기록과 참고는 `<details>` 로 접는다.
- 선택지 '결과' 칸은 '~하므로 ~된다', '~하면 ~된다' 꼴로 쓴다. 지적 목록에는 '그대로 두면' 열을 둔다.

## 순서 (바꾸지 않는다)

1. **쉬운 말 3줄 요약** — ① 지금 문제 ② 그래서 무엇을 바꾸나 ③ 그러면 무엇이 달라지나·사용자가 할 일. 한 줄에 한 문장, 합계 180자 이하, 괄호 금지
2. **🙋 결정 필요 — 결정 카드** (11-04 사용자: "선택지가 명확하지 않아 뭘 골라야 할지 모르겠다")
   - 맨 위 요약표: 결정 번호 · 질문 한 문장 · 추천 기호, 그리고 "한 번에 답하기: `전부 추천` 또는 `결정1 A, 결정2 B`".
   - 결정마다 카드 1장: ① 질문은 A/B 로 답할 수 있는 한 문장 ② 왜 지금 정해야 하나(안 정하면 무엇이 멈추나) ③ 선택지 표 — 짧은 이름 · 고르면 어떻게 되나 · 비용·위험 · 되돌리기 쉬움/어려움 ④ 추천 1개(✅ 표시) + 이유 한 줄 ⑤ 답하는 법 `결정1 A`.
   - (11-04 개선) 선택지 이름 옆에 용어 한 줄 풀이 필수. "안 정하면 멈추는 것"은 고정 항목. 선택지 표는 4열(선택지·고르면·비용·위험·되돌리기)·셀 2문장 이하·되돌리기는 `쉬움/보통/어려움` 라벨을 맨 앞에. 비용 단위(근무일·파일 수 등)는 카드 안에서 정의. 결정 칸에는 카드만(미룬 결정도 카드로). 추천 이유 = '지금 X 때문에 Y 가 생긴다 → 그래서 A 는 X 를 없앤다' + 인정하는 단점 한 구절. 카드 상단에 '지금 문제' 한 줄을 둔다.
   - 선택지는 서로 겹치지 않게, 2~3개. "검토", "추후 결정" 같은 선택지는 쓰지 않는다.
   - 결정할 게 없으면 "결정 없음"이라고 적는다.
3. **📄 지금 구조 / 바뀌는 구조** — PUML 두 장을 나란히(또는 위아래). SVG 를 문서에 내장한다.
4. **🔄 주제별 before/after** — 주제마다 대표 코드 1곳, 각 10~20줄, 왼쪽 before·오른쪽 after. 아래에 "무엇이 왜 달라지나" 한 줄.
5. **✅ 그대로인 것 / 없어지는 것** 표
6. **🔄 진행 순서** — 번호 목록, 단계마다 검증 기준 한 줄
7. **참고** (맨 아래, 접힘) — 파일 경로, 티켓, 커밋, 근거

## 글쓰기 규칙

- 본문은 쉬운 말. 고유명사(클래스·함수·파일 이름, 티켓·커밋 번호, 캐릭터 실명)는 **코드 조각과 참고 칸에만** 둔다. 본문에서는 역할로 부른다("효과 관리자").
- AI 내부 기호(P1·fixup·ctx_·D1·Q16 등) 금지.
- 헤더 이모지: 🙋 결정 · 🛠️ 사용자 할 일 · ✅ 완료/유지 · 🔄 진행/변경 · ⚠️ 위험 · 📄 문서/그림
- 수치·파일·동작은 origin/dev 에서 확인한 것만 쓴다. 확인 못 한 건 "(미확인)"을 붙인다.
- before/after 코드는 실제 코드에서 발췌한다. after 는 제안 코드이므로 제목에 "제안"을 붙인다.

## 만드는 법

1. `templates/doc.html` 을 복사해 자리표시(`{{…}}`)를 채운다.
2. PUML 은 `templates/before.puml`·`after.puml` 을 고쳐 `plantuml -tsvg` 로 렌더하고 SVG 를 문서에 내장한다(외부 파일 참조 금지).
3. before/after 블록은 템플릿의 `<section class="ba">` 를 주제 수만큼 복제한다.
4. 검사: `python3 ~/.claude/skills/structure-change-doc/scripts/check.py <문서.html>` — 실패 항목이 0개일 때만 완성으로 보고한다.
5. 저장 위치: `~/Documents/90_정리기록/<날짜>-<주제>/`. 완성되면 메인 코디네이터가 Slack DM 으로 보낸다.

## 검사 항목 (check.py)

- 3줄 요약 박스 존재
- 🙋 결정 섹션 존재
- 내장 SVG 2개 이상(지금/바뀌면)
- before/after 블록 1개 이상, 각 블록에 before·after 코드와 "왜" 한 줄
- 외부 스크립트·스타일 참조 없음(자체 완결)
- 본문(코드·참고 제외)에 고유명사 패턴(PascalCase 클래스명, LRM-숫자, 커밋 해시) 없음
- 내부 기호(P1·P2·P3, fixup, ctx_) 없음
- (11-05) 결정 카드마다 인과 연결어(때문·그래서·그러면·하면·~면·므로·탓에·덕분) 1개 이상
- (11-05) 3줄 요약 180자 이하
- (11-05) 결정 카드 본문 450자 초과는 경고, `--strict` 에서는 실패
- (11-05) 검수 기록(제목·요약에 '검수' 포함)이 `<details>` 안에 있음

## 바뀐 곳 강조 도구 (11-04 추가)

| 도구 | 하는 일 | 사용 |
|---|---|---|
| `scripts/puml_diff.py before.puml after.puml` | 두 PUML 의 노드(`as 별칭`)를 비교해 **추가=초록·변경=노랑·삭제=빨강 점선** 으로 칠한 `*.hl.puml` 과 범례를 만든다 | 본문 그림은 `*.hl.puml` 을 렌더해 넣는다. 별칭은 before/after 에서 같은 대상이면 같게 쓴다 |
| `scripts/image_diff.py before.png after.png out.png` | 화면 캡처 두 장을 비교해 **바뀐 영역에 빨간 상자**를 그린 나란히 비교 이미지를 만든다(상자 목록 JSON 출력) | 1080×1920 같은 크기 캡처끼리. 잡음이 많으면 `--threshold`·`--min-area` 조정 |
| `scripts/screen_flow.sh 영상.mp4 출력폴더` | 녹화에서 **장면이 바뀌는 프레임만** 골라 가로 띠(`flow-strip.png`)와 12초 움직이는 미리보기(`preview.gif`)를 만든다 | 화면 변화 흐름 섹션에 띠 + GIF. 원본 영상은 따로 첨부 |

문서에서: 그림 섹션은 강조본을 쓰고 범례를 남긴다. 화면이 바뀌는 문서는 "📄 화면 변화" 섹션(before/after 캡처 비교 이미지 + 흐름 띠 + GIF)을 진행 순서 앞에 추가한다.

## 영상 전달 (11-04)

- HTML 안에 영상을 base64 로 넣으면 파일이 1.33배 커지고 Slack 미리보기에서 안 보인다. **HTML 에는 GIF 미리보기(≤5MB)와 장면 띠 이미지만** 넣는다.
- 원본 영상(mp4, H.264, 720p 이하)은 **같은 Slack 메시지에 별도 파일로** 올린다 — Slack 이 바로 재생한다. 오래 남길 문서는 Confluence 페이지에 HTML 내용 + 영상 첨부.

## 한 줄 한 사실 (11-05 사용자)
- 한 줄에 사실 하나. 가운뎃점·화살표로 여러 사실을 한 줄에 몰지 않는다.
- 읽는 순서대로 위→아래: 무엇 → 왜 → 결과 → 할 일.
- 표는 선택지 비교에만, 칸에는 짧은 한 가지.
