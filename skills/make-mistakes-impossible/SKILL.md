# make-mistakes-impossible

에이전트는 열어 본 파일만 알고, 가장 가까운 예시를 베끼고, 컴파일되는 가장 짧은 길을 간다. 그러니 같은 지적이 반복되면 문장을 하나 더 쓰는 것은 증상만 늘린다. 실수가 아예 만들어지지 않거나 즉시 막히게 바꾼다.

## 1. 반복 찾기

- `~/.claude/skills/orca-hub-create/references/common-rules.txt` 를 읽는다.
- 메모리 폴더 `~/.claude/projects/<프로젝트 경로의 / 를 - 로 바꾼 폴더>/memory/` 의 `MEMORY.md` 와 개별 파일을 읽는다. 날짜·"지적"·"사고"·"번복"·"금지" 표시가 단서다.
- 필요하면 최근 커밋·되돌림·리뷰 코멘트도 본다.
- 같은 뜻의 규칙을 하나의 실수 유형으로 묶는다. **두 번 이상 나온 것만** 후보다(중복 항목, 여러 곳에 같은 규칙, 같은 사고가 다시 난 기록).

## 2. 막는 수준 고르기 (위에서부터)

1. **구조로 없애기**: 한 가지 방법만 남기기, 옛 방법·죽은 코드 지우기, 손으로 맞추는 목록을 한 원본으로.
2. **타입**: 잘못된 상태를 쓸 수 없게(enum·전용 타입·생성자 검증).
3. **lint·스크립트 검사**: 실패 메시지가 대신 쓸 파일·함수·명령을 알려 준다. 이미 퍼진 패턴은 새로 늘어날 때만 실패시킨다.
4. **훅**: 커밋·턴 종료·도구 호출 시점에 막는다(git 훅, Claude 훅).
5. **템플릿**: 맞는 형식이 기본값이 되게(PR·보고·spec 양식).
6. **문장**: 판단이 필요해 위가 다 안 될 때만. 눈에 띄는 위치에 실패 예시와 함께 둔다.

구조로 막았으면 같은 내용의 규칙 문장은 지우거나 "검사가 막는다"는 한 줄로 줄인다.

## 3. 증명

- 새 검사는 **실제 과거 실수 하나를 재현했을 때 실패**해야 한다. 그 실패 출력과 고친 뒤 통과 출력을 남긴다.
- 정상 사례를 막지 않는지(오탐)도 하나 확인한다.

## 4. 보고 (구현 전)

후보 표만 보고하고, 구현은 사용자 승인 뒤에 한다. 표는 자체 완결 HTML(쉬운 말·고유명사는 참고 칸)과 채팅 요약으로 낸다.

| 실수 유형 | 반복 근거(어디·몇 번) | 막는 수준 | 구체안 | 증명 방법 | 비용 | 지울 규칙 문장 |
|---|---|---|---|---|---|---|

- 추천 순서는 "반복 횟수 × 사고 비용 ÷ 구현 비용"으로 정한다.
- 판단이 필요해서 구조화가 안 되는 항목은 따로 모으고 이유를 적는다.
- 승인 후 구현은 항목 하나씩: 검사 추가 → 과거 실수로 실패 확인 → 규칙 문장 정리.
